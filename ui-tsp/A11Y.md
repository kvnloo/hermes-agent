# T19 accessibility qualification

This is a **partial qualification**, not signed-in native-window acceptance for #585.
`tern serve` exposes the real host AX/layout/control tree without requiring a signed-in
window. SDK peer tests are a separate evidence class; neither substitutes for an OS
screen-reader/window run.

## Action inventory

The audit found custom actions rendered as `row`, `text` or `kbd`: these were clickable
but were not native focusable buttons. `view/action-button.tsx` now emits the supported
SDK `el` with `tag="button"`, using `aria` (SDK spelling), text or labelled children as
its name. Existing `omp.*` roles and intent callbacks are retained. Child icon/key/label
layout remains a row. No HTML/DOM `tabIndex`, guessed SDK prop or new RPC is used.

Native `picker`, `prefs`, `list`/`item`, tabs, tool/section fold controls and links retain
host semantics rather than acquiring a second application navigation model. The context
meter remains a named meter; its companion Context button carries the intent. Agent cards
retain their pointer shortcut and gain a named Inspect button. Browser actions advertise
unavailable/busy state as disabled while preserving the underlying owner/session guards.

## Post-base composition audit

Voice and remote image preview actions added after T19's base now share the native
button adapter. The newer hold-to-talk information action and raw-wire history reload
are native buttons too. SDK tests assert actual rendered button kind/tag/name while
exercising consent/cancel, mute/barge-in, image retry and exact history reload; their
pre-fix failures are retained in integration receipts. Audio calls remain mocked.
Charts and narration add passive Markdown/SVG/display segments, not custom actions.
Vim adds host-editor state and a passive mode indicator; its settings controls retain
native prefs semantics. Submitted attachment previews keep host-native image/media
semantics; retry/remove and cross-host load actions are buttons. No new navigation or
input model replaces host controls. The models hub is audited when integrated next.

## Keyboard and focus fixes

- Browser evaluation-frame editing now declares its native input focus target, handles
  composer editing/Enter locally, and uses Escape first to cancel the frame form, then
  to close the sheet. It never types into the hidden main draft.
- Evaluation frame, plan revision/annotation/refinement, secret fields and approval choice
  list have explicit names. Secret names contain field labels, not entered values.
- Modal dismissal uses App's existing identity-owned overlay stack and restores the
  exact composer text/caret; stale callbacks beneath a secret cannot close another sheet.
- Help explains host/preset interception, paired button/slash fallbacks, Shift+Tab effort
  ownership and top-sheet Escape priority. No claim that Hermes can override host bindings.
- No action bindings/defaults were changed; configurable-binding collision tests still run.

## Repeatable evidence

```sh
scripts/dev/tern-e2e.sh /absolute/worktree smoke a11y --python /absolute/isolated/python
```

The runner keeps signed-out native-window results **BLOCKED** and runs the distinct
`tern-serve` lane. The `a11y` journey saves `proof/a11y-inventory.jsonl` plus actual AX,
tree, dump, layout and screenshots at each capture. Every observed native button must
have a name and (unless disabled) focusability plus click/focus AX actions. The adapter
correlates AX identity, owned pane subtree and exact DOM geometry before dispatch; focus
is read back, pointer clicks are separate from AX clicks, and consequential-action and
account/owner guards remain fail-closed.

Runtime coverage includes Settings via AX focus + Space and via pointer; pointer Close
and keyboard Escape; exact draft/caret restoration with a typed-and-erased caret probe;
model/jobs/browser/plan/help at 80x28, 120x36 and 180x44 measured PTY sizes; report dock
View/dismiss; real read-only context/MCP/SSH; BTW history/reader; plan section/refinement;
agent inspector event scoping and hub pagination. Fixture notifications are labelled as
such and real RPCs still use the real gateway. No model turns or live user state are used.

The connected SDK tests in `qualify-accessibility-keyboard-pointer.test.ts` cover native
button emission, browser frame keyboard ownership, disabled ownership guards, nested
secret priority, exact composer restoration, approval/list labels and host key reservations.
The native-button regression test fails when the button is sabotaged back to a `div`.

## Still required for #585

- Ordinary **signed-in isolated native windows**, at narrow/normal/wide and
  Reader/Spine/Console presets: complete keyboard-only traversal, pointer reachability,
  actual OS AX/screen-reader announcements, focus rings and host-intercepted chords.
- Reduce Motion and hidden-pane combinations in those native windows; tern-serve hidden
  completion evidence is not this acceptance matrix.
- Consequential actions are intentionally not activated in inert E2E: grants/secrets,
  plan approval/edit/external editor, cancellation/steering/stop, adoption/release/frame
  changes, rewind/retry/send, model/config writes, microphone and clipboard roundtrip.
  Existing feature tests plus SDK emission/owner tests cover their guards, not live effects.
- Visual/OpenUI candidate states, attachment failures, populated browser ownership and
  every conditional native card/control state still need the signed-in interaction audit;
  conversion of their custom actions is not a claim those states were all exercised.

No live pane, ambient daemon socket, auth, settings, contract or backend ownership policy
is changed by this qualification.
