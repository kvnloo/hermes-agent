# Source-backed process articles

- Treat history traces as indexes, not authority. Open cited primary records for published counts, dates, owner quotes and promotion claims; prefer actual commit dates over inferred chronology.
- Harvest unmerged studies from immutable remote-ref SHAs without checking out their branches. Read manifests, aggregate receipts and PR discussions separately; keep publication status distinct from a completed or frozen evidence slice. Deduplicate preregistration and follow-up branches under the study ID. Label issue-only evidence mutable with no file SHA rather than inventing an immutable source. Draft negative baselines separately from unmeasured replacement designs, and retain partial-rerun missing scenarios as unmeasured rather than incorrect.
- Keep a short visual spine of chapters with dated native HTML details/summary deep dives. Separate tried, failed, learned and changed in readable prose. Preserve stable chapter anchors and existing typography/palette.
- Distinguish reference, candidate, kept experiment, owner lock, review composite and release. A later composite using a rejected experiment does not retroactively approve the original experiment.
- Do not join scores from different critic contexts into a progress curve. Two fresh sessions of one model are not independent human experts.
- Copy selected artifacts into bounded WebP derivatives without modifying originals. Record source SHA-256, source/output dimensions and bytes in a private manifest. Inspect visible text and OCR for private paths before publication.
- Use human-readable production-record labels publicly; retain full private paths in the delivery source audit. Never publish session handles or private service identifiers.
- Verify no-JS disclosures with real browser Enter/Space interaction. Decode the hero before capturing: network idle does not guarantee paint. Avoid requestAnimationFrame promises in JavaScript-disabled contexts; they can hang even when automation evaluation works.
- Test the actual static export with a nonempty basePath mounted under that prefix, not only the URL helper. Restore the intended final build afterward.
- Make integration tests own an ephemeral server and clean it up. Check signalCode as well as exitCode before waiting for an already-emitted child exit event.
- Deliver branch/commit, exact test receipts, image bytes, quotes for owner review, omitted claims, screenshots and content-update instructions.
- Harvest unmerged studies read-only with immutable Git objects and pinned GitHub content; map multiple PRs updating one manifest into one study entry rather than treating repairs as independent experiments.
- Check README totals and performance wording against the raw aggregate artifact. Preserve category-count disagreements, excluded queue clocks and source-reported versus newly reproduced execution instead of silently choosing the cleaner headline.
- Follow public result references across adjacent PRs before drafting: a compute-conformance experiment and a model-quality comparison may have different sources. Do not reconstruct ABAB ordering from a report that is only mentioned, not publicly archived.
- Validate publication-specific anchored headings with a presentation-only citation-check projection when a citation helper recognizes only plain Sources headers. Check immutable URLs, source-read evidence, every TOC anchor and privacy exclusions against the actual delivered files.

## Read-only study harvests

- Deduplicate by manifest study ID, not branch name. Several fixture, runner and correction branches may extend one already-published study; retain their distinct source SHAs within one entry.
- Start from the newest existing post, then inspect addenda and result files separately. A newer study manifest can carry a failed follow-up or subgroup quality failure that the existing post never incorporated.
- Keep publication state separate from experimental completion. A published baseline can have draft, unscored additions; passing fixture tests and a synthetic producer interoperability repair do not establish real-source answer use.
- Preserve aggregate-only evidence boundaries when reusing prose. Replace operator device identities with roles, remove private-source coordinates and local paths, and cite repository-relative artifacts through commit-pinned blob URLs.
- Verify the harvested JSON schema, unique study count, post frontmatter, TOC anchors, privacy patterns and existence of every commit-pinned source. Read README-reported figures as source reports when the imported summary does not contain their supporting rows; never label the harvest itself a reproduced experiment.
