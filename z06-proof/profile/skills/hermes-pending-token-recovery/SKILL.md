# Queued-token recovery gates

## When to Use

Use for optional composer-token journal validation, deferred paste expansion,
or exact-base recovery-regression qualification in the Hermes TUI.

## Workflow

- Freeze an independent runtime reproducer byte-for-byte before changing production. Run the same mounted queue/dequeue/submission fixture against owner base and supplemental candidate; schema rejection assertions alone do not prove a consumer recovery regression.
- Commit test-only RED before production GREEN. Keep original unpublished-artifact recovery status separate from supplemental repair provenance.
- Treat optional persisted token metadata separately from required row text. Validate the whole discriminated paste/image list; partial filtering shifts duplicate-label identity. Preserve absent-field compatibility and literal text instead of rejecting an otherwise recoverable row solely for an unusable optional field.
- Reconstruct expansion only on branches that consume it. Exercise literal, direct visible shell, interpolation, prepared retry, and remount lifetimes through actual hooks with inert RPC. Never execute commands copied from saved journal fixtures.
- Keep visible input as the authorization boundary. Assert Unicode/CRLF/tab/nested-label paste bytes separately from shell requests. Missing historical metadata cannot recreate lost paste identity; do not claim it can.
- Mutation-remove boundary validation, lazy reconstruction, journal persistence, and visible-only authorization separately; require discriminating failures and byte-for-byte restoration.
- Resolve scratch to its physical path before renderer tests. Canonical profile-home identity is a precondition, not a reason to weaken production matching.
- Compare complete owner/candidate TUI, typecheck, lint and formatter outputs. Fix warnings only in the new test; never broadly format inherited debt. Preserve intermediate failures and exact final-head results.
- For shallow evidence bundles, ship the reachable SHALLOW boundaries, initialize a fresh repository, install boundaries before unbundle, install emitted refs, then verify bundle, connectivity, ancestry, tree and file hashes without alternates. Ordinary clone is not a qualified substitute for this restore procedure. Before independently executing a supplied restore script, inspect its output paths; copy the packet into the reviewer's owned evidence directory when it writes logs beside itself, so review does not overwrite the owner's receipts.
- Adjudicate recovery policy independently of schema assertions. Preserve incompatible throw-expecting probes as explicit failures; qualify whole-field fallback with actual row recovery, duplicate-label ordering, unknown-key tolerance, valid image/paste data, and visible-only shell calls. Use JSON-serializable malformed members for lazy reconstruction probes: a throwing property getter can fail legitimate journal serialization instead of the behavior under review.
- Use the shared native-build lock and verified effective resource cgroup. A timeout while awaiting the lock is not a failed test and must not be reported as an executed gate.
- Return READY_FOR_FRESH_REVIEW, not self-approval; separate local corrupt-journal robustness from supported-writer failure, remote exploitation, real gateway/provider execution and terminal acceptance.
