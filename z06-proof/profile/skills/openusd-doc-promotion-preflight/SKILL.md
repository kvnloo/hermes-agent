# OpenUSD documentation promotion preflight

## When to Use

Use for exact-head OpenUSD documentation candidate review, scoped native verification, policy admission checks and publication-payload preparation.

## Procedure

1. Read current `CONTRIBUTING.md`, `docs/contributing_to_usd.rst`, PR template and workflows at the pinned upstream `dev` SHA. Distinguish CLA receipt, DCO requirements and AI disclosure. A human's promise to email a CLA is not receipt; a subsequent acknowledgment on the full thread may close that gate. Do not inherit stale admission holds from an earlier snapshot.
2. Read every authored-open upstream PR's complete comments, reviews, review threads and requested reviewers. Reconcile connection totals. Preserve unrelated current-head CI and stale-body findings separately from the documentation candidate's readiness.
3. Reconcile changed-file counts for every open upstream and fork PR. `gh pr list --json files` can stop at 100 files; expand mismatches through paginated PR-files endpoints. Review the whole overlapping diff and its actual contracts, not only the shared filename.
4. Trace color-space spans through `GfColorSpace` into Nanocolor. The span wrappers pass destination first and source second; the separate single-color `Convert` method has a different receiver convention. A token-table addition is not ownership of an unrelated span-doc correction.
5. Check GfPlane prose against both `plane.cpp` and `GfVec3d::Normalize`. Zero equation normals retain the negated constant rather than divide by zero; sub-threshold normalization can leave a non-unit normal. Qualify new geometric claims instead of treating ordinary-case green tests as proof for all inputs.
6. For bounded native checks, use an isolated exact-head checkout, disable imaging/usdview/Exec and unrelated tools/examples/tutorials, enable tests and Python, select an installed supported Python explicitly, and build `_gf`, `_tf`, and `testGfColorCpp`. Clear inherited PYTHONPATH/PYTHONHOME. When a full installation is too broad, stage only built Gf/Tf extensions, their unmodified initializers, the generated root initializer and official test entry points into the configured install prefix. Label this scoped staging, not a full USD install. Run the generated CTest entries with `-C Release -R '^testGf(ColorCpp|ColorPy|Plane)$' --no-tests=error`; verify selection and preserve output.
7. Bind each test run to its exact head. A sequential Ninja rebuild after switching heads is usable only after the prior build/tests finish and receipts/product hashes are preserved; require affected header dependencies to rebuild and clean source status. Do not count the same tests rerun on two heads as distinct coverage.
8. When `gh pr checks` is empty, also query Actions runs filtered by the exact head SHA and inspect each run's jobs. An `action_required` run with zero jobs is a workflow-admission hold, not absent CI configuration, test failure, or green execution. When reconciling a stale body after rebase, compare every changed blob and file mode; identical text can hide a historical executable-bit difference. Read hosted job logs to recover the synthetic checkout SHA, then compare its Git tree with the candidate tree. Check-run head metadata alone does not prove exact-tree execution. Keep successful, skipped and untested gates separate; Doxygen syntax inspection is not Doxygen rendering.
9. Save independent prose review and behavioral corroboration separately. Existing unit tests can pass while a documentation claim is false on an untested edge case. Prepare an exact body only for a qualified candidate, otherwise supply exact source-line blockers without silently rewriting its supplied SHA.
10. Keep canonical external authorization separate from public CLA receipt and local readiness. If credential-free canonical authorization access is unavailable, retain UNVERIFIED and do not recover credentials or infer permission from fork labels. Preserve receipts outside auto-pruned scratch and never modify a parent-owned registry.
11. Pin current `dev` through the branch ref's actual target, not a PR's `baseRefOid`: the PR snapshot can retain an older base while `baseRef.target.oid` has advanced. Keep original parent/base, live head, current branch target and locally rebased head as separate identities. Preserve original author/date and compare stable patch IDs when preparing independent branches.
12. Verify incremental bundles in a separate repository containing only the prerequisite bases, with no object alternates. Assert each candidate commit is absent before importing, then fetch the bundle and verify clean checkout/head/tree. A bundle verified only in its source repository does not demonstrate restoration. Pair prerequisite-dependent bundles with complete source archives whose file bytes are checked against Git blob IDs.
13. Treat cross-format Import review as a contract audit, not merely two successful format conversions. Inspect source identifier arguments/targets, destination permissions, supported `.usd` backing encodings, TransferContent error/partial-copy behavior, and the ordering of dirty-state changes versus notices. Trace inherited helper defects newly exposed by the path; label source findings separately until differential native probes execute. Record dirty state and compare both ordinary and forced Save: a clean layer can skip ordinary Save and hide an in-memory backing-format difference. Prove a notice listener with a healthy ordinary-edit control before calling a missing event a regression.
14. Recover historical CI by exact head and individual job execution, not workflow conclusion or a stale PR body. A successful Validation-only run with skipped platform jobs does not support headless-suite counts. Trace earlier successful heads and regression-only failures separately, and compare synthetic checkout trees with each corresponding source head before attributing results.
15. Expand scoped native staging deliberately: runtime plugins need generated plugInfo plus generated schema resources, test-plugin libraries must land at their plugInfo-relative install paths, and Python packages can require sibling helper modules and additional compiled extensions. Preserve initial harness failures, fix only staging/linkage, and rerun the same differential controls; never classify import/setup failures as product RED.
16. For independent reuse of expensive native products, fingerprint the owner's source and libraries, copy source/build/install into reviewer-owned paths, and bind those copies over the cached absolute paths inside a read-only-root mount namespace. Supply a private minimal `/dev` and `/proc`; test Git and `/dev/null` access before consuming the shared build lock. Record the namespace map, actual affected-object rebuilds and before/after source identities, then recheck owner hashes. A cached build is not independent source provenance without these checks.
17. Distinguish complete commit ancestry from full historical blob availability in filtered clones. Require a nonshallow prerequisite fetch, successful full ancestry traversal and no alternates; verify every current source-archive blob against its restored tree. Supply thin-bundle prerequisite blobs to the independent object store with lazy fetching disabled for owner reads. Do not hydrate or mutate an owner store to make reviewer restoration pass, and do not claim a rebased candidate preserves original carrier ancestry merely because patch IDs and authors match.
