# Blender meta-learning evidence

## When to Use
Use for cross-trial Blender payoff learning, replay qualification, live lane ingestion and executable recipe transfer.

## Workflow
- Resolve the canonical dream-loop worktree and project artifact directory separately. Keep runtime ledgers and renders outside the skill repository; preserve the source branch and use the authorized isolated worktree.
- Publish the per-lane JSONL contract before workers start. Extend discovery-observation definitions through references rather than replacing legacy rounds. Keep incomplete historical imports visibly partial; never invent cohort hashes or timestamps.
- Isolate malformed producer records as located diagnostics so valid lanes can still plan; retain strict owner-log and coherent-snapshot gates. Append validated corrections with original receipts and unknown measurements as null; never roll an already superseded historical error back over a newer valid state. Keep historical errors visible and recipe promotion conservative.
- Coordinate lane ownership before historical repair when producers remain active. Do not claim producer trial IDs for provisional evidence-only workflow receipts with invented stable defects: a concurrent native event can then collide with immutable identity. Prefer awaiting the producer mapping or using separately identified intake receipts; preserve any existing collision through explicit corrective revisions, not rewrites.
- Deduplicate events and materialize revisions by trial ID before estimating payoff. Preserve raw pre-contract lane rows; when a valid formal event supersedes the same intake trial, keep an explicit superseded-intake receipt instead of double-counting or rewriting the worker's file.
- Allow producer classification corrections across revisions while retaining ordered classification history on the single materialized trial. Duplicate older event IDs must not revert the newest state; copy records rather than mutating input events. Keep element/run/stable-defect identity fixed and require a new trial for a substantively different intervention. Resolve provisional parent aliases through audited parent-history revisions and rerun cycle quarantine; do not rewrite original events or modify the native discovery-node contract.
- Choose a learned best only among observed eligible winners, not the entire action space: a prior-only 0.5 estimate can otherwise outrank a real but uncertain winner.
- Freeze per-trial source/dependency snapshots before shared scripts change. Keep historical hash drift visible rather than silently rebinding an old trial to the newest file.
- Separate owner acceptance, owner preference, historical retention, qualified judge wins and hard-gate outcomes. Unknowns are not failures. A report document is not another trial. Preserve original mechanism labels; any derived analytical class needs an explicit source-based rule.
- Collect HITL labels as a separately locked, append-only owner-event overlay keyed to real trial IDs; preserve event history and idempotent request IDs. Rebuild payoffs and recommendations after each save without granting the UI ownership of producer lanes. Keep component-scoped historical praise from becoming whole-scene acceptance.
- Audit every historical quote as inferred or unresolved using curated links, unique reviewed-image paths, identical hashes or unique trial directories. Preserve the exact quote/evidence and require explicit owner confirmation; chronology and coarse sentiment keywords cannot establish bindings. Reconstruct missing rendered variants from primary reports before rating them, rather than labeling report-only records.
- Test rating POSTs against a disposable data copy and compare the real owner log before/after. Use Lightpanda for keyboard/DOM behavior and headless-shell for decoded images and layout; wait for new image decoding and hide prior frames when switching candidates so stale pixels cannot masquerade as the newly titled trial.
- Backfill only native owner-authored messages: raw user-role records also contain agent task prompts, compactions and pasted assistant instructions. Preserve original UTC timestamps, verbatim payloads, source session/message IDs, mapping evidence and explicit confidence. Reuse existing evaluation IDs; split mixed feedback by aspect, leave stars null and uncertain trial IDs null. An exact quote is not proof of a trial binding.
- Reduce owner feedback by trial plus aspect, with explicit UI labels superseding chat-backfill regardless of ingest order. Retain distinct unbound receipts separately; confirm them by source event identity. Component praise/locks must not become whole-trial acceptance or qualify a recipe. Keep pairwise evidence and unset optics through quote-only confirmation.
- When porting the review runtime into a public repository, keep source data, labels, screenshots and private absolute paths external. Use synthetic fixture tests, a documented source-of-truth mirror check, and portable CLI test paths based on the imported module. Merge concurrent planner changes in an isolated worktree; preserve read-only ingestion's no-write contract for newly added owner-evidence outputs.
- Validate artifact hashes from disk before recipe promotion. Require the script and native-density gate receipt to be hash-bound artifacts. A string PASS or larger receiving texture is not source-detail evidence.
- Use Beta uncertainty descriptively; preserve cost phase coverage and unknown GPU utilization. Do not rank coupled or selectively retained trials as causal mechanism effects.
- Sort same-defect observations by known event time, not lane filename. Missing chronology cannot prove consecutive failures. Two nonwins trigger a checkpoint/switch, not a global hard stop.
- Prefix replay may recommend only from earlier observations. Compare matched-action coverage and conditional outcomes; unsupported counterfactuals remain unknown. Never call differing matched subsets an off-policy value estimate without support/propensities and dependency evidence.
- Keep retrospective leave-family-out judge audits distinct from prospective calibration. Owner-informed reconstructed briefs contaminate otherwise held-out predictions; disable automatic promotion until genuinely frozen-before-label independent anchors qualify.
- Withhold duplicate pending mechanisms, including completed renders still awaiting review. Keep full alternative proposals in a reserved portfolio rather than silently redispatching the class or losing its hypothesis. Consolidate identical directions across stable defects while preserving all evidence IDs.
- Freeze small event/calibration inputs before expensive whole-archive artifact hashing when live producers keep appending. Verify copy hashes immediately, then hash artifacts once and generate all element portfolios from that shared snapshot; retain the capture timestamp and original path/hash manifest. Do not race the owner-rating materializer or weaken fail-closed live reads to force publication.
- Treat two assessed visual nonwins as a dream trigger, not an owner rejection label. Exclude controls, delivery-only records, repeated configurations and nonvisual failures; retain unknowns. Quote partial component gains with correct variant attribution and transfer compatible components, never a donor's entire failed appearance. Keep explicit breadth slots and reserve unavailable slots for evidence repair instead of expanding scope into locked geometry, lighting or post.
- Transfer a recipe in a disposable Blender scene. Prove inert import, idempotence, source hash and geometry preservation; inspect actual renders. Technical transfer does not imply aesthetic or final-density acceptance.
- Use a fully clean `env -i` for system Blender when the agent's Python runtime leaks into its standard library; unsetting only PYTHONPATH/PYTHONHOME may be insufficient. Preserve HOME, a system PATH and the authorized scratch TMPDIR.
- Make CPU fallback explicit for both Cycles and `scene.render.compositor_device`. A saved scene may still request GPU compositing after `cycles.device='CPU'`; preflight both real settings before launching a full render, record both in receipts, and never describe the whole pipeline as CPU-only from the Cycles flag alone.
- Run standalone polling in the foreground with a finite budget. For an explicitly persistent owner-rating server, put the finite 15-minute/four-hour schedule in the server's own service loop, serialized with label writes under the same RLock/flock; do not spawn a detached wait loop. Expose last-check/error/expiry state and retain the prior catalog on incomplete producer JSONL tails. Keep one materializer/report writer and separate lane writers.
- Pair LOOK/CLEAR only from hash-bound rendered artifacts and geometry receipts. Keep provisional optics visibly distinct from current LOOK.json, recognize post-only LOOK even when camera DOF is false, and reject mismatched crop dimensions rather than inventing registration. Open stone trials on the measured plinth front face. Use content-addressed image URLs and reject changed bytes under an old asset identity so producer revisions cannot silently replace reviewed evidence.

## Whole-frame breadth-first scans

- Pair registered full-frame grid measurements with explicitly labelled reviewer semantic ROIs. Report overlapping flagged-region counts, not fabricated distinct defect counts; colour masks and Laplacian energy nominate inspection but do not recognize artifacts or prove optical focus.
- Attribute sharpness changes against luminance/material changes: darkening a fern lowers Laplacian energy without defocusing it. Inspect native edge spread and actual optics ownership before crediting a blur gain.
- Read the upstream integration receipt before treating a later copy as a new intervention. If the upstream scene already includes the exact recipe hash, mark the reapply as an idempotence control and compare improvements against the actual pre-intervention image, not the immediately preceding filename.
- Erode UI validity by the widest feature-filter radius before measuring local contrast/sharpness. Masking only final pixels still leaks lettering into neighbouring windows; keep a UI-only regression fixture and clamp tiny negative integral-sum energy before square roots.
- Publish target-derived density masks and camera-projection conventions before geometry integration. Log actual ray-hit receiver counts, not just total scatter points: a top-normal filter can silently omit moss on a block's visible front. Preserve the failed placement receipt, test the actual receiver coverage, and keep point-mask data separate from albedo textures.
- Coordinate local background ownership with the optics lane through an additive collection, then rebuild its Cryptomatte union after geometry. Split combined foreground/background plant meshes without losing inherited light-link receiver collections; do not change global DOF/bloom in an independent greenery recipe.
- Test suspected Geometry Nodes Cryptomatte omissions with a tiny real-render coupon before realizing instances or adding prototype names. Select the intended union by its matte IDs, not the first Crypto node; threshold PNG dither when counting selected pixels. Correct membership alone does not prove useful bokeh: inspect whether the final original-mask mix clips spread over a protected foreground surface.

## Verification
Run ledger, schema, revision, cycle, unknown-cost, recipe-drift, prefix-leakage, held-out-split, pending-work and CLI fail-closed tests. Exercise a real bpy transfer separately from offline Python tests. Preserve exact execution receipts and report remaining unqualified outcomes explicitly.
