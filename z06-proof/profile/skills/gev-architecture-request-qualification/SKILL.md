# GEV request/resource qualification

## When to Use
Use for independent GEV architecture/performance qualification of existing candidate branches and current-main adoption.

## Procedure

- Read the complete CURRENT-STATE contract before proposing an architecture change; inspect every truncated long-line remainder. Existing source seams, lifecycle extractions and bounds are not aesthetic problems to replace.
- Freeze API head/base/main identities and exact lock hashes. Use exact-head focused tests with exact dependencies, then separately test current-main adoption. Label an integration patch/tree distinctly from checkout HEAD in receipts.
- On a resumed qualification, re-read the live head before replaying an accepted test overlay. Preserve newer owner-only test names or formatting and prove the final overlay-to-commit tree identity. If the accepted candidate is not a live ancestor and merges are forbidden, make the local reconciliation a single-parent descendant of live, retain the accepted candidate as a separate bundle ref, and record the ancestry constraint rather than fabricating dual lineage.
- Treat explicit lock-contention exit 75 as NOT_RUN, independently of outer-shell exit status or zsh monitor/gitstatus warnings. Run gates with absolute runtime executables and direct argv without changing global shell configuration. Keep Node 24 calibrated allocation probes mandatory; Node 26's documented allocation skip is not an executed allocation verdict.
- Exercise thumbnail intent through createRecentImageryLayer's public setVisibleRange/focus actions, not retain alone. Count native HTTP requests and aborted server sockets with delayed loopback fixtures; preserve pins/preview work. Native Blob URL counts are measurable resources, while size-squared RGBA diagnostics are estimates, not decoded/GPU memory.
- Exercise terrain coalescing through createTerrainHeights.resolveEllipsoidalGround over request services. Test a cold concurrent burst, warm hit, one cancelling waiter, all cancelling waiters, and lifetime cache clearing. Request-count reduction is not automatically latency improvement.
- Respect current provider ownership when adapting old heads: preserve injected thumbnail acquisition. Current-main tools-services ownership can be newer than a candidate's boundary manifest, so rerun check:boundaries even when git auto-merges that manifest.
- Retain the terrain candidate's late-floor wait/count test changes when adopting its runtime; a previously duplicate fast response can mask the slower shared request that the new code correctly waits for.
- For browser evidence, use an owned headless application with explicit source overrides and local HTTP fixtures. Record any CSP bypass as harness-only. Count DOM nodes/listeners, native object URLs, actual Cesium collection ownership and viewer destruction; verify delayed work cannot recreate disposed state. Distinguish layer mounting from actual drape tile requests.
- Import a real scene fixture through importProjectFile and invoke seekScene forward/backward, start/stop and a superseded seek. Measure pending work and camera state after delayed settlement rather than asserting lifecycle from source alone.
- Re-run ENOSPC watcher failures with CHOKIDAR_USEPOLLING, preserving initial failure receipts. Read child exit codes inside wrapper receipts; wrapper exit zero is not child success. Mark timed-out browser gates incomplete, and SwiftShader as software only. Normalize ANSI escape sequences before counting `[PASS]`/`[FAIL]` markers: the tracking gate colors text inside the brackets, so a raw regex can report zero cases despite an explicit nonzero RESULT summary. Retain raw logs and reconcile parsed counts with that summary.
- Leave a reproducible integration patch, raw logs and verifier; restore only owned experiment paths. Route rebases and metadata adoption to the existing carrier rather than spawning a competing implementation.
