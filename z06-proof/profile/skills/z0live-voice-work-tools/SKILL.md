# z0live voice work tools

## When to Use

Use when changing broker work recall, native task execution, inbox delivery, or their mobile protocol.

## Procedure

- The Hermes link role ("z0bridge" in the owner's words) is filled by existing pieces, not a separate repo. The broker reaches Hermes through `desktop/hermes_host.py`, which runs Hermes's native API server only: `/v1/runs`, `/api/sessions/*`. Garden uses the same pattern on its own loopback port. Dash's bridge has an ACP client, and Hermes speaks ACP via `hermes acp`. The owner approved extracting the Hermes link into one shared bridge repo, `kvnloo/z0bridge`. Hermes comes first, via ACP (`hermes -p <profile> acp`: list/load/resume/new/prompt/cancel) plus read-only SessionDB listing. More harnesses get added later as adapters, T3 Code-style. Check whether z0bridge exists and use it before building any other Hermes transport in z0live or Dash. z0bridge is also the owner's one pairing and identity layer (`docs/PAIRING.md`, `docs/ARCHITECTURE.md` on kvnloo/z0bridge#2). New pairing, scopes or send-to-session work belongs there: `hermes:session.send` with `next_turn` / `steer` (z0bridge#4; migrations z0live#38/#39). Do not add another device-token store to the broker.
- Reconcile retained qualification by exact source revision and full-suite terminal result before rollout. Passing narrow relay repeats do not override a failed desktop discovery suite. Probe the real loopback introspection listener separately from public JWKS: public 200 plus unauthorized 401 proves availability/negative auth only, never authenticated voice interoperability. Preserve pending grant/enrollment authority; do not mint or expand credentials to make a diagnostic green.
- Resolve the live checkout first; the canonical broker is `/mnt/zer0models/workspace/zer0/products/z0live`, separate from the portable runtime RFC and PRs #6/#7. Preserve those tracks.
- Load hermes-agent before changing native integration. The API-only native session is `z0live` on port 8644; the broker is port 8791. Never start a second gateway or host scheduler to obtain tools.
- Read `docs/VOICE-TOOLS.md` and `docs/API.md` as the current executable contract. Mint registers all builtin schemas and returns `builtin_tools`; mobile clients with hardcoded names must include every new builtin and preserve local execution for phone tools.
- Pull with rebase before desktop edits and inspect peer changes. Persona authors may concurrently edit core.py; register tools without rewriting their persona.
- Query resident z0intelligence at `/v1/file-search` and its canonical `~/.z0int` memory/State Packets directly. The original pre-turn plugin is not a memory-search tool and its automatic policy may be disabled. Do not bypass that policy by inventing an automatic adapter.
- Exclude empty `context.resolve` receipts from summaries of work; retrieval attempts are not completed work. Filter blank assistant tool-call records before ranking FTS results. Keep every excerpt's project/date/session/citation and explicit completion uncertainty.
- Search ctx using the installed CLI with `nice -n 19`, `--refresh off --backend lexical --format json`, transcript/message filters, and an outer timeout. The CLI can be much faster than MCP and must not block voice; return partials then inbox completion.
- Preserve durable queue and inbox atomicity. Test caller-timeout/completion races, restart recovery of already-completed pending answers, and provider call_id idempotency for task creation.
- Native task request completion is not implementation completion. Read the actual kanban/issue tracker; use real blocked `[test]` tasks for qualification and archive only their exact IDs afterwards. The selected shared board may be `zer0-company`, not the root kanban.db; resolve the current board before direct readback.
- Use `desktop/tests/live_work_tools.mjs` for real headless Chromium WebRTC/GPT tool turns. It uses text on the real data channel (no microphone), forces a harmless 26-second native terminal probe to test the 24-second overflow, checks exact inbox lookups, archives test tasks with canonical readback and revokes its disposable bearer. Do not claim acoustic/Android TTS qualification from that test.
- Keep Telegram delivery on the supported `hermes send` path with offline-only batching. List targets first. An empty clean-profile Telegram target list is a real deployment blocker, not permission to copy another profile's credentials. Subagents must not send owner test messages when the coordination context reserves messaging for the parent.
- Pin the complete z0intelligence-exported VoicePlan per minted session. The desktop stack consumes `smol`/`meta_role`/`task` bindings; never turn it into another model selector or an implicit provider fallback. Use the native adapter's explicit runtime-lock path for bound runs, and record actual served identities.
- Keep the L1 native inference helper tools-free and provider-explicit. Immediate acknowledgement/cache admission must not wait for full liaison generation; report actual inference latency separately from acknowledgement and acoustic latency.
- Qualify stack changes with `desktop/tests/live_voice_stack.mjs` against an isolated loopback broker/data directory. Pass its exact `Z0LIVE_DATA` in every L2 fanout/progress/trace command. Persist broker-namespaced native idempotency keys before submission; reused job numbers from a disposable store otherwise collide with the persistent host's old keys. Preserve legacy keys on already-persisted lost-acceptance requests.
- `what_changed` must answer "what work is happening". Its first source is titled Hermes sessions across all profile DBs, read-only, with `last_activity_at` in the window: list live ones with `last_activity_description`, and count oneshot/cron/finished-subagent runs as one aggregate item. Its second source is local git commits. Do not make per-project GitHub calls, because one lookup would spend about 20 requests of the shared rate-limit budget and fail under it. Do not report voice-event telemetry, which is noise for this question. "today" must cover at least the last 12 hours, because local midnight leaves an empty window for late-night questions. Skip profile DBs that have no sessions table instead of reporting a gap.
- Inbox `say` text is data the phone's model summarizes. Write plain facts ("Agents working right now: …; Commits: project N (latest subject)") with no template preamble such as "More work context." and no status jargon. The phone side must interpret it and never read it aloud (lawnchair-z0live-delivery).
- To ship a broker change: prove the new tests fail with the old source stashed (`git stash push -- <files>`), then pass. Restart `systemctl --user restart z0live.service` only when `broker.db` has no `sessions` row with `active=1 AND ended=0`, then confirm port 8791 and a fresh `GET /v1/inbox` in the journal. If the owner explicitly asks for the install during a call, restart anyway and tell him the call dropped.
- Several finished draft branches deploy together. Merge them into a `deploy/z0live-<date>` branch in a separate worktree off the served HEAD. Tool registrations (core.py `TOOLS`, `Store.tool` dispatch) and `Delegator.handle` pre-routes usually conflict: keep both blocks, and give each pre-route its own `finish(...); return`. Test on the MBP with `fleet-build -- bash -c 'cd desktop && PYTHONPATH=.:tests python3 -m unittest <modules>'`; tests import sibling helpers such as `test_relay`, and the MBP has no pytest. Then `git -C <canonical> checkout --detach deploy/...`, push the branch and restart. Verify by importing `LIVE_TOOLS` and checking the new names are present.
- Never speak summaries, setup/context notes, broadcasts or previous-session backlog. Allow requested-work speech only for the latest non-ended human-started session with fresh activity; preserve cursor/history while silencing stale inbox items. Queue while the client reports user/assistant floor, and drop local TTS for interrupted turn IDs. Provider-side response.cancel alone does not reach desktop workers.
- Prove child cancellation by reading each exact native run's terminal state, not by observing a stop request. Lost acceptance remains unknown and known-ID stop failures remain pending; neither is false cancellation success or permission to start a replacement.
- Keep async acceptance data-only (`say:"", speech:"silent"`) and append its function output without forcing `response.create`; L0 may acknowledge once before dispatch. Memory/meta/worker lifecycle telemetry is trace-only. Reject no-news partials, dedupe normalized findings durably, and let a final answer replace unheard floor-held progress. Prove quiet waiting with the real data channel, not only persona string tests.
- A tools-free liaison's lack of execution authority is not a missing human input: require a concrete `missing_input` plus an actual clarification question, otherwise hand the original request to the native agent. Include both original request and native terminal status in condensation so a correct path/value is not turned into a spurious context question.
- Guard real WebRTC continuation creation with both active and creating state. A response containing a function call must not resolve the user turn merely because it also contained acknowledgement text; otherwise the next utterance races an in-flight continuation and raises conversation_already_has_active_response.
- Record supplied L0/L1/L2/L3 usage/cache counters, but leave dollar cost unknown when subscription billing/prices are absent. Missing interrupted-run usage is null, not zero. Text-channel first-token time does not certify physical first-spoken latency.
- The Hermes backend behind the voice defaults to Opus (`Delegator.binding`). Set `Z0LIVE_DELEGATE_MODEL`/`Z0LIVE_DELEGATE_PROVIDER` in `$Z0LIVE_DATA/service.env` to match the owner's live budget. Use `claude-sonnet-4-6` / `anthropic` while Codex is exhausted, and a Codex model such as `gpt-6-luna` / `openai-codex` only while that pool has tokens. Never leave a lane on a pool he said is out, because it bills credits. The VoicePlan smol lane is pinned separately (claude-haiku-4-5 measured ~1.8 s wall; probe free fast models if sub-second matters). Back up the file first, then restart `z0live.service`; new sessions pick up the binding. Smoke-test the model with a one-turn `hermes chat --provider ... -m ... -q`.
- For a GUI target, distinguish discovery from write ownership. `source=gui` must be included in both HUMAN_SOURCES and DRIVEN_FROM for unpinned/title discovery. A `Z0LIVE_RELAY_DEFAULT` pin can resolve a row even when the native gateway cannot own it. Read the exact profile's `runtime/active_sessions.json`: an in-process standalone dashboard GUI lease without `metadata.shared_runtime_url` is not the native gateway. `session.resume` may return `not_found` for its login-stamped row; never rewrite source/user_id, remove its lease, impersonate a bare login subject, or start a second writer. The missing seam is an authenticated send into that original runtime. Separately inspect the existing Dash credential's scopes read-only: `dash:chat` does not grant `z0live:voice`; a successful scoped introspection of an invalid token proves listener/credential availability only, not authorized voice. Do not mint or widen a grant just to qualify it. Once the owner approves a scope change, use z0bridge's own `z0bridge grant` flow for exactly the missing scope, then verify it from the audit entry and a readback. The Dash in-app voice chain is ContinuousVoice → bridge `POST /voice/bootstrap` (target check + z0bridge audience `z0live`, scope `z0live:voice`) → broker `/v1/realtime/session` with `context.hermes_target` → `ask_z0` → smol lane or exact-session relay. Debug it hop by hop, starting with the bridge journal status, because a bridge-side 400 never reaches the broker.
- Status 2026-11-03: the dash-bridge `gui` source fix is deployed (release 1e577218), so `/voice/bootstrap` accepts Desktop chats. Relaying into a Desktop/dashboard-owned session is still blocked: no shipped Hermes runtime advertises `shared_runtime_url` or serves `/api/session-attach`. Upstream carriers are NousResearch/hermes-agent#113486 (owner side) and #120605 (lease proof, issue #120604). The factory item HERMES-COOP-ATTACH builds them as a kvnloo/hermes-agent experiment. z0live's adapter (`_try_shared_runtime_endpoint`, 10b748a) activates once the runtime serves it; running that branch as the owner's runtime needs his yes.
- The relay's default target is `relay.main_session()`: the `Z0LIVE_RELAY_DEFAULT` pin, else the most recently active interactive CLI/TUI/GUI session (GUI support requires the deployed discovery repair). Before telling the owner the voice reaches you, verify that it resolves to the session he expects: `cd desktop && python3 -c 'from z0live_desktop import relay; print(relay.main_session())'`. Also read the target's `source` in `state.db`: candidates are filtered by `relay.HUMAN_SOURCES`/`DRIVEN_FROM`, and a Hermes desktop-app session has source `gui`. If that source is not listed, the auto-pick silently lands on an older CLI/TUI session, so a `Z0LIVE_RELAY_DEFAULT` pin alone isn't proof it will deliver. Confirm that the delivery path supports the session's owner, then prove delivery with one prefixed test relay and its `messages` row.
- To pass a message to Kevin's Hermes, use `bin/z0live relay "MSG" [--to title|id]` (`relay.py` + `desktop/hermes_relay.py`, docs/RELAY.md). It goes through the owning gateway's viewer protocol: `session.resume`, then `session.steer` if the turn is running, otherwise `prompt.submit`. Never send it through `/v1/runs`. That route refuses CLI/TUI-owned sessions, `/p/clean` has no key, and the unprefixed route runs in the *default* profile under the same id, which wedged the real session (`admission_conflict`). Do not probe it with a live session id. Delegations must carry the recent spoken turns (`Delegator.request`), because a bare "Yeah" sent alone made Hermes replay a stale phone tap.
- Offer ONE work tool to gpt-realtime (`LIVE_TOOLS`: tell_hermes feedback-only, get_context, summarize, ask_z0, cancel_work). With the five legacy work tools offered, the model always picked `work_search` and answered from an empty partial (0/5 repo answers). Legacy tools stay executable and reserved (`reserved_tool_names()`), never offered. Never put "Say 'Checking …'" in tool descriptions: the model narrates plumbing verbatim.
- `ask_z0` on gpt-realtime defaults to `Delegator.ask` (`Z0LIVE_REALTIME_WORK=delegate`): same persistent Hermes backend as bidi via `InboxCall`, silent acceptance, call_id-idempotent, final as one `run:rt-…` inbox item; `liaison` restores the L1/L2 stack.
- A bidi `session.context_window.*` event before the first assistant `turn.done` means a wedged call: `LiveCall.degenerate` ends it.
- Frameless Bidi (`gpt-live-1-codex`, the OMP `/live` route) is the default voice transport for clients that send `transports:["bidi",...]`; see `docs/LIVE-BIDI.md`. It rejects function `tools` (call dies with `unknown_parameter`), so phone actions are delegation results: liaison picks one declared tool, broker queues an inbox action, the phone's `tool_result` becomes the final. Never re-add client tools to the Bidi session payload.
- The Bidi sideband carries ~100 base64 audio frames/s. Skip them by prefix before JSON parsing, use a deep receive queue and no client keepalive pings, and keep SQLite/HTTP side effects off the reader thread; a 16-frame queue plus pings dropped a live call after one slow write.
- `delegation.created` can arrive before the user's `turn.done`; key delegations by `item.user_bidi_turn_id`. The model sometimes says only "On it." without delegating: the broker recovers by running the transcript and answering through `session.context.append`.
- Measure voice quality acoustically with `desktop/tests/live_audio_turns.mjs` (Piper speech as the WebRTC mic, real model audio levels, same script for `bidi` and `realtime`) against `desktop/tests/live_isolated_broker.py`, which copies only the Hermes key, disables Hermes notes and uses qualification Hermes sessions. Use a free port: another agent may hold 18791.
- System phone lane (`phone_system.py`, opt-in `Z0LIVE_PHONE_SYSTEM=1` + `Z0LIVE_PHONE_SERIALNO` in service.env): volume/DND/Bluetooth/brightness/media run from groot over adb and answer from the phone's readback (`landed`), checked before phone_route and Hermes. Grammar first; unparsed setting words go to a closed catalog on the semantic router with an EXPLICIT model (`cerebras-qwen-3.8-27b`, ~0.2 s), then groot qwen3-4b. `vllm-sr/auto` fans out and 403s on some prompts. Cerebras/Groq behind the router return a non-JSON 403 for the default `Python-urllib` User-Agent, so always send a custom UA. The watcher (cerebras-gpt-oss-120b, reasoning medium) only logs verdicts to `$Z0LIVE_DATA/phone_system_watch.jsonl`; give it the action's catalog meaning and the readback summary or it rubber-stamps (qwen3-4b approved every wrong action). Multi-step Android requests go to Hermes session `z0live-phone` with PHONE_LANE rules (display 0 only, never unlock/uninstall/Wi-Fi off).
- When the MBP Kueue queue is held (`stopPolicy: Hold`, fleet-health) and fleet-avrea-budget refuses, run the public exact SHA on Avrea via `gh workflow run verify.yml -R kvnloo/fleet-runner -f repository=kvnloo/z0live -f sha=<40> -f command='cd desktop && PYTHONPATH=.:tests python3 -m unittest discover -s tests -p "test_*.py"' -f request_id=<unique>`.
- Gate with scoped ruff and desktop unittest discovery, then real WebRTC. Publish explicit owned paths only, never an unrelated pairing helper. Verify the pushed branch SHA and actual GitHub Actions run before reporting green.
