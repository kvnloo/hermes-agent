# Parallel fork merge lanes

## Scope and prerequisites
- Read the tracking issue first and confirm the owner authorized merging to the fork, not upstream. Use explicit `-R owner/fork` on every GitHub command.
- Use a dedicated clone and explicit author/committer identity. Respect host memory constraints; hosted CI is the gate when local suites/builds/installs are prohibited.
- Link each worked PR in the session. Preserve lane order and retarget each successor to main only after its predecessor merges.

## Branch targets (owner rule, 2026-11-05, supersedes the 2026-08-21 nightly gate)
- Feature PRs target the default branch. `dev`, `nightly`, `preview`, `channels/*` and `integration/*` are throwaway union refs for integration testing: rebuild them freely and never merge them. Measured across 2,244 PRs, PRs into integration bases landed 0–0.3% of the time, against 26–77% for PRs into default. Receipt: `operations/repo-consolidation-20261105/BRANCHING.md`, `DECISIONS-20261105.md`.
- Standards with no A/B: one fast required check per repo; heavy tiers run via fleet-build or fleet-runner; anything stale for more than 14 days is archived as `incomplete/*`. Back up local-only tips to `wip/*` before any delete.

## Plan the wave (before any merge)
- Freeze the open-PR inventory with exact head/base SHAs, bodies, comments, reviews, changed files and check conclusions before planning. Verify the collected count and paginate inline review comments; canceled checks are not passes, and draft status is not a review verdict.
- Build the dependency graph from `git merge-base --is-ancestor <head-a> <head-b>` plus explicit source/API prerequisites. Label shared-file overlaps and resolution-order edges separately from hard dependencies; independent PR heads can still conflict, and sharing a file does not establish a dependency. Publish the graph with the requested merge work, distinguishing merged, qualifying and blocked nodes.
- Map conflicts with sequential trial merges, not with GitHub's per-PR `mergeable`. Every PR can be MERGEABLE against main on its own and still collide once others land. Run this in an owned integration worktree: `git fetch origin '+refs/pull/*/head:refs/remotes/pr/*'`, then `git merge --no-ff --no-edit pr/N` in a candidate order, recording `git diff --name-only --diff-filter=U` and `git merge --abort` on conflict. Keep machine-readable receipts outside the source checkout so later resolutions and tests remain attributable.
- Group PRs into lanes by the hot files they collide on. Lanes with disjoint files can run in parallel workers; inside a lane, merge serially. Land the conflict-free, green PRs first as lane 0.
- Before blaming PRs, read the failing CI logs across all red PRs together. Several red PRs often share one root cause, such as a CI job missing the host app's dependencies. Fix it once with a CI-only PR that installs from the pinned lockfile the other jobs already use. Never touch tests or the plugin's own dependencies for this.
- File the wave as issues whose bodies hold all state:
  - one pinned START HERE roadmap, with a lane table (PR, stacked-on, known conflict files, status cell);
  - one self-contained issue per real code fix.
  
  Generate the bodies from a script kept in the operations dir, so status edits are reproducible. Merging into the fork's main still waits for the owner's explicit go.
- Draft PRs must be marked ready (`gh pr ready N`) before `gh pr merge`.
- A main-only publish workflow (for example a bundle that pushes `dist/` back to main) can fail on a fork that lacks upstream's deploy-key secret. This makes the fork's built artifact stale without any PR going red. Check main's workflow runs after the first merge, and ask the owner before adding a deploy key.

## Bootstrap a fork program when the fork has none (RFCs + waves + CI)
Use when the owner asks to "organize everything like the other repos". Mirror the shape of the owner's existing fork trackers (read one RFC and one START HERE issue from a sibling fork first).
1. **Inventory beyond the repo.** List branches (`git rev-list --count main..b`, ancestry between heads), PRs, issues, worktrees, unpushed `exp/*` branches, and the host pieces that run the code: systemd units (`systemctl --user cat`, `list-unit-files`, `list-timers`), installed binaries (sha256, which vendor strings they contain), provider/config entries pointing at worktrees. Branches running live with no PR get a PR. An unpushed experiment branch that is only a merge of existing PR heads is superseded by the integration branch: say so instead of opening a PR.
2. **Verify every host claim before it goes in an issue.** Scripts that "run every N minutes" may have no timer; a service may be a transient `systemd-run` unit that dies on reboot. Write what is true now, and make the gap a card.
3. **Issue taxonomy.** Labels first (`rfc`, `wave-0..N`, `merge-wave`, `lane:<area>`, `fork-only`, `upstream-candidate`, `exp`). Then create stub issues in one pass to fix their numbers (RFC-0 index, one RFC per direction, the START HERE merge wave, later-wave trackers, one card per concrete follow-up), and fill the bodies afterwards so cross-references are exact. Pin RFC-0 and the START HERE issue (GraphQL `pinIssue`). Retitle and label pre-existing issues into the scheme instead of duplicating them, and leave a pointer comment on every affected PR.
4. **RFC-0 holds the policy whole:** branch kinds, no force-push to shared branches (fix a PR by adding a commit; fix a stack by merging the lower branch up), checks on the SHA that lands, merge to main is the owner's "go", upstream off by default, installed bytes only from a checked SHA with a receipt, and separate status words (proposed/tested/draft/merged/installed/live).
5. **CI is lane 0.** Add a `checks` workflow on `pull_request`, pushes to `main` and `integration/**`, and `workflow_dispatch`, with a read-only token, per-ref concurrency, and the toolchain pinned to the host's version. Include: the test suite, typechecks where the tree defines them, a **generated-artifact drift job** (rebuild every committed bundle, then `git diff --exit-code`), and a compile + start + protocol smoke of the shipped binary, uploaded with its sha256. Add a PR template (Problem / Fix / Verification / Wave / Model-harness).
6. **Get union CI before main has the workflow.** `pull_request` runs use the workflow file in the merge ref, so other PRs get no checks until the CI PR is in main. Push `integration/wave-N` branches (main + the CI branch + each lane's heads, merged `--no-ff` in landing order) so the union is checked on push right away. Cite those run URLs in the wave issue as the proof.
7. **Fix what the first runs find, at the owning PR.** Typical first-run defects: stale committed bundles, and a lockfile written by a newer toolchain that the pinned one can't parse (`Unknown lockfile version`, so `--frozen-lockfile` fails). Regenerate with the pinned version as an added commit on the PR, then re-merge the fixed heads into the integration branches.
8. **Two PRs that add the same code** (an identical cache or declaration) conflict, or merge into a duplicate declaration. Resolve with `-X theirs` for the hunks, delete the now-duplicate declaration, run the affected tests, and record the resolution in the later wave's issue so the real landing repeats it.
9. **Spot checks must fail loudly.** Never discard the exit code of local build or drift checks (`>/dev/null 2>&1`): a script whose inner tool isn't on `PATH` exits 127, rebuilds nothing and looks "clean". Print the exit code, and trust the CI run over a local spot check.
10. In fork issue and PR text, a bare `#N` resolves inside the fork only while N is within the fork's own numbering. Write upstream refs as `owner/repo` in code spans, with no number.

## Integrate and qualify
- Fetch and merge the latest origin/main without rebasing or force-pushing. Resolve independent bindings, commands, imports, callbacks, registration methods and tests as a union. Preserve every added package script and discovery glob; resolving a package-file conflict must not silently remove another lane's tests.
- Qualify the combined tree in a draft integration PR before landing overlapping feature heads; per-head green checks do not test the union. Run an independent code audit in parallel with the union gates, reproduce its blockers, and repair them before promotion. Obtain a fresh independent repair review after blocker fixes, and rerun the affected tests on the resulting head; an earlier audit is not clearance of a later diff. A merge-all request authorizes integration work, not knowingly unsafe changes.
- Compare every newly added test file against the actual CI commands. Run omitted Python, delivery and nested-package suites explicitly, install nested packages from their own lockfiles, and add durable CI discovery when the new regressions would otherwise never run. Distinguish setup failures from test failures rather than declaring the whole candidate broken or green.
- Qualify optional inference-library upgrades against the final worker combination in an isolated environment. Resolver/import/CUDA tensor checks and short real supported-mode runs answer different questions; fake-provider/web CI cannot certify model loading or generated output. Check host RAM and GPU admission separately before loading weights, including encoder weights and runtime overhead; spare VRAM alone is insufficient. Record blocked runtime gates as unqualified, not as demonstrated incompatibilities or passing tests, and do not kill unrelated work to manufacture admission.
- Preserve main's fixed chords. Restrict broad modifier matchers so Alt+P cannot steal Alt+Shift+P; reserve fixed app/editor chords in configurable override validation and add negative collision tests.
- Preserve separate profile refreshes and their ordering in adoption code, recording fakes, lifecycle assertions and golden RPC traces. Full config reads with and without profile scoping are separate real requests, not interchangeable snapshots.
- Never hand-edit generated bundles: take main's bundle. Never raise lint ceilings, suppress new lint, skip tests or weaken assertions. Extract unchanged cohesive adapters/components if a union exceeds a file-size ratchet, preserving public exports.
- When capability gating changes a test fixture, explicitly register the capability owned by that test. Do not grant implicit authority to all fakes. Keep separate absence/refusal tests proving no mutation or legacy fallback RPC is sent.
- For backend boundaries without runtime hooks, verify that capability status is unavailable, mutations refuse, drafts survive, old contexts register nothing unauthorized, and real tests demonstrate it. A test-only checkout of a reviewed public registration seam must remain separate from the runtime dependency pin.

## Exclude unqualified heads without false merge receipts
- When an all-head trial union contains a blocked PR, build a fresh qualified branch from current main and merge only admitted heads. Do not revert a blocked merge and land its ancestry: GitHub can still mark the blocked PR merged even though its feature was undone. Preserve the all-head trial branch, verify held heads are not ancestors of the qualified branch, and compare trees to prove only deliberate exclusions differ.
- Make nested browser verification honor the parent’s codec-capable browser selection. For `preload=none`, assert metadata after Play; waiting for speculative metadata while paused can fail correctly non-preloading browsers even when tap-to-play works.

## Safe shell and landing
- Chain branch switch, merge, commit and push dependencies with `&&`, and assert the current branch before pushing to an explicit head ref. Do not use semicolon chains that continue after a failed merge and accidentally commit on another lane.
- Read failed hosted logs and fix their real causes. Prefer the host app's PR watch notifications when available; otherwise use bounded checks at 60–120 seconds without duplicating active watchers. Require all named checks to pass on the exact current head; a skipped unrelated workflow is not a substitute for required jobs.
- Reconcile each check notification with the live PR state and exact head before acting. A delayed green event for a superseded or closed candidate cannot qualify its replacement; stop the obsolete watcher and retain monitoring only for the active candidate.
- Fetch main immediately before landing. If it moved, integrate it and qualify the new head. Merge with `--merge --match-head-commit <verified-sha>`, then read back PR state and merge commit.
- After landing a multi-head union, verify every included head with `git merge-base --is-ancestor <head-sha> origin/main`, and verify every held head is absent. Reconcile GitHub's original PR states separately: automatic merged-state updates can lag the union merge. If an immediate open-PR list still contains integrated heads, make a bounded follow-up read before closing or re-merging them. Persist the exact PR-state inventory and derive final merged/held totals programmatically.
- Before updating a shared tracking issue, reread its body, change only the owned row, detect concurrent edits, and verify exact readback. Preserve other workers' rows.
- Update the published dependency/conflict graph to the final merged, superseded and held states. Finish with a concise outcome, verified totals, merge SHA, remaining blockers and a pointer to per-PR receipts; include product-specific changes only when relevant. Distinguish code merged to main from deployment of the running service, and keep media/reference-fidelity acceptance separate from successful app integration.
