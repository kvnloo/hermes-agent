# Privacy-first activity telemetry

## Standing gates

Keep collection local-first, lightweight and explicitly authorized. Do not enable screenshots, OCR, credential/content capture, cloud sharing, health ingestion or learning interventions as part of activity setup. Preserve source stores and service dependencies; analytics is a redacted projection, not their replacement. Make minimal reviewable changes; never push without approval. Complete independent work before stopping for access, permission approval or potentially destructive changes.

Keep observed activity separate from inferred concentration or productivity. Report PASS, PARTIAL or BLOCKED with timestamps and reproducible evidence. Installation, process liveness and an HTTP info response alone do not establish collection health. Never describe untested integrations as verified recipes.

## Procedure

1. Inventory before installing: inspect user units with `systemctl --user cat` and `status`, enabled targets, process ownership, listeners, watcher configuration, compositor hooks, existing ActivityWatch buckets and read-only SQLite schema/count/time ranges. Inspect canonical dotfiles and existing event infrastructure before creating another spine. Resolve symlinks before edits and preserve unrelated changes.
2. Determine server ownership from the installed watcher's `--help`, not its name. Some awatcher distributions embed the backend; another server can create a port conflict or parallel store. Preserve workspace-copilot's awatcher dependency and avoid duplicate window/AFK watchers.
3. Exercise `/api/0/info`, `/api/0/buckets` and recent bucket events on the configured loopback endpoint. Compare timestamps to current UTC and assert expected types and title redaction. Inspect workspace-copilot independently through read-only SQLite grouped counts/latest timestamps; compositor events do not prove ActivityWatch ingestion.
4. For datastore failures, follow references/activitywatch-recovery.md. Distinguish restored collection from upgrade/sync compatibility and recurrence prevention.
5. Inspect Android with `adb devices -l` and explicitly scoped package queries for the intended Android user. Verify installed release and current official sync requirements before installation. Prefer local Maestro hierarchy-driven setup plus ADB when the user requests automation; load maestro-local-android. Stop for permission approval when the task requires it, but reassess that gate when the user explicitly authorizes automated grants: automate only necessary app-scoped permissions and read back both Android and app-recognized state. ADB connection authorization alone is not permission approval or collection evidence. Do not scrape the private source database as a substitute for supported sync; inspecting an official sync export is a separate staging check.
6. Validate real foreground, AFK and workspace transitions without injecting fake source events. Follow focus-safe-desktop-automation for desktop interaction; coordinate physical-seat idle tests rather than manipulating protected workspaces. Read source records after each action.
7. Reuse an existing event spine only after checking compatibility. Keep private projections under XDG state outside Git with directory mode 0700/file mode 0600. Define versioned IDs, provenance, UTC intervals, device identity and allowlisted metadata before ingestion; redact before model access. Handle mutable heartbeat durations and mirrored buckets. Verify duplicate-free replay and do not silently sum cross-device overlap as human active time.
8. Verify installation, collection, official export, transport and destination ingestion separately. Permission-granted Android collectors can backfill activity from before installation: require an export containing a specifically observed post-setup app-switch event, not merely a nonzero event count. An ADB-copied official export recognized by `aw-sync status` verifies export/layout only, not Syncthing transfer or PC ingestion. Require a newly generated phone event on the PC with correct identity/time before declaring sync working. Verify restart separately from login persistence. Report measurements, coverage, gaps, rollback and retention/export/delete procedures. Leave only authorized lightweight collectors running; future learning/health namespaces do not authorize ingestion.

## Shared behavioral and learning foundation

When the user expands an existing behavioral pipeline into learning telemetry, inspect its current receipts, code and authoritative projection before building integrations; do not create a second analytics database. Assign one worker ownership of projection code, writes and importer units. Other workers own separate producer outboxes and submit versioned events through the validated single-writer path. Specify stable concept/card/locus IDs, timestamps, session and treatment fields, method versions and bounded result metadata before producers implement adapters; keep raw answers and held-out evaluation content outside the redacted projection.

Keep Anki as the sole card-scheduling authority. Test review writes against a disposable real collection before seeking approval for a personal collection; read-only discovery or successful import does not authorize changing existing intervals, policy or content. Label synthetic review events as tests and keep them out of human outcome summaries.

Establish explicit start/pause/resume/end work-block markers before reporting session fragmentation or resumption latency. App switches alone do not identify interruptions or work boundaries. Require baseline-quality evidence and approval before randomizing notification shielding; leave important alerts and control sessions untouched.

Persist experimental assignments immutably, isolate held-out answers from practice interfaces, and anchor delayed evaluations to actual study events. Distinguish implemented instrumentation, tested integrations, actual human dogfood and experimentally supported outcomes; never convert allocation previews or synthetic results into completed experiments or future retention claims.

## Phone sleep proxy (owner's S25)
- The official AW Android exporter keeps writing `/sdcard/Download/ActivityWatchSync/kevin_s_s25_ultra/<device-id>/test.db` (buckets `aw-watcher-android-unlock` and `aw-watcher-android`, timestamps in ms). `adb pull` it into `sft-svlm/.../staging/android-official-export/<date>/` (mode 600) and analyse it locally only.
- Sleep proxy = the longest gap between unlock events from 19:00 to 15:00 the next day. Use unlocks, not foreground events: agents on hidden displays create foreground events (ChatGPT/DeepSeek) but never unlock the phone, and a recurring 07:20 no-unlock foreground event is an alarm/automation. Report it as a proxy, never as measured sleep, and drop nights cut off by the end of the export.

## Projection pitfalls

- Treat ActivityWatch time-filtered event responses as potentially clipped intervals. Re-fetch boundary events through their canonical per-event endpoint before hashing or appending revisions; otherwise pagination can replace an event with its last slice and undercount coverage. Prove this with a multi-day clipping fixture and canonical-source read-back. Fail the import if canonical recovery fails.
- Compare a mutable event against its latest payload, excluding ingestion time, rather than globally deduplicating every historical hash. An A→B→A source change needs a third revision. Verify exact-batch replay separately from repeated live imports, where ongoing heartbeat extensions legitimately append revisions without new logical events.
- Sweep half-open interval boundaries per device/source and report contradictory active/idle overlap separately. Never convert compositor point observations into continuous active time or count app/workspace changes as interruptions without an explicit supporting source.
- Use an existing timestamp-leading SQLite index with a verified bounded query plan, mode=ro, query_only and bounded fetchmany. Select only allowlisted columns; never read details/labels just to redact them later. Document the source read-transaction lifetime and keep ingestion manual unless scheduling is separately authorized.
- Benchmark DuckDB batch parameter conversion before accepting slow bulk imports. A bounded JSON string decoded with an explicit from_json schema can avoid costly Python list-of-dict/STRUCT conversion without introducing raw staging files or extra dependencies.
- When disabling DuckDB external access, explicitly allow its owned private directory for checkpoints and spill files. Some versions reject allowed_directories in connect configuration; set it after connecting, then disable external access before querying. Disable extension autoload/install at connection creation and exercise file-backed checkpoint/reopen, not only in-memory tests.
- Preserve superseded development receipts rather than presenting them as final evidence. Name corrected receipts, verify the latest view against real canonical source events, and retain append-only correction history without destructive rewrites.
- Preserve requested future namespace identifiers literally in code, tests and documentation. Reserve them without enabling ingestion until the user explicitly requests that extension; then add a compatible versioned contract and strict validation while preserving existing records and replay semantics. Namespace authorization does not authorize health ingestion, card edits or learning interventions. Compare delegated contracts against the original acceptance criteria, because passing tests can validate a substituted contract.
- Regenerate the real two-import exercise and verification receipt after report-contract changes; keep historical receipt comparisons strict rather than weakening assertions to accommodate changed code.
- Qualify UI automation's failure artifacts before using it under a no-screenshot constraint; omitting explicit screenshot commands does not disable automatic diagnostic captures. Use filtered hierarchy inspection plus authorized ADB actions until capture-free execution is verified, and restrict diagnostic/logcat artifacts as private data.
- Distinguish configured login persistence from exercised restart and reboot/login survival; enabled units establish intent, not observed boot behavior. Do not imply scheduling when analytics ingestion remains manual.
- When explicitly enabling periodic projection imports, retain the original writer lock; commit bounded batches before atomically advancing each successful source cursor, then test process death between batch commit and cursor persistence. Serve cached redacted aggregates so the dashboard does not hold DuckDB open. Check the storage mount before every write, including HTTP ingress after server startup.
- Supplement time-window scans with a constant-size canonical ActivityWatch tail refresh and durably tracked prior head IDs; mutable intervals can start before the overlap or publish their final duration late. Persist watch IDs only with a successful checkpoint, retain them on failure, bound API requests, and never claim exhaustive recovery for old unwatched events. Test both timestamp-list omission and clipped-overlap responses through the real periodic tick; qualify the observed live backend rather than attributing a synthetic filter behavior to it.
- Separate collector health from historical event-type age: an obsolete active row while a recent AFK tail says idle is not a stale collector. Cache identity-checked API status and canonical tail timestamps independently, age both at HTTP read time without source queries, and withdraw current-state claims when evidence expires. Old foreground records during fresh idle are inconclusive, not proof of a dead collector or of healthy collection.
- Stress same-file schema migrations at production row scale using synthetic data and disable core dumps before native tests. DuckDB 1.5.0 can abort in deprecated ART serialization on a large primary-key rebuild; an explicit same-file ATTACH with STORAGE_VERSION 'v1.5.0' qualified this path, whereas the connection default alone did not upgrade an existing file. Back up DB/key/code first, compare copied rows bidirectionally, disclose the newer minimum storage version, and rerun canonical-source readback.
- Validate exact producer wire identifiers before adding closed metadata enums. Preserve practice versus held-out conditions and exclude explicitly synthetic producer events from production counts. Do not solve integration differences by admitting arbitrary strings, raw answers or content.
