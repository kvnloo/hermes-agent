# Canvas atlas timeline qualification

## When to Use

Use for atlas-backed canvas timeline migrations that must retain archive accessibility and pass complete-main-thread-work trace gates.

## Procedure

1. Preserve the existing archive, exact tied-timestamp selection, filtering, keyboard access and image deep links. Freeze before/after source and export identities before timing. Do not merge merely because canvas rendering works.
2. Build content-addressed atlas pages from the approved public thumbnails, with gutters, a content-bound UV/date/theme/status manifest, and exhaustive tests for every sprite's identity, UV bounds, nonempty crop and page hash. Keep image source paths out of public outputs. Ordinary builds should consume committed atlas pages rather than require private originals.
3. Use one WebGL2 surface with immutable per-page instance buffers and time/window uniforms; provide an actual Canvas2D fallback. Keep only the small hero-image set in DOM. Test both backends, DPR sizing, context loss/restoration, touch/keyboard, filters, autoplay and timestamp ties. Inspect real screenshots; a GL class name is not a renderer receipt.
4. Trace the scrubber as well as the artifacts. A native range value can trigger layout every input even after the thumbnail rewrite. When measured, a role=slider overlay with keyboard semantics and throttled aria-valuenow can use the same canvas to draw rail/thumb, avoiding per-frame input layout and CSS-transform layerization. Retain the input tape's public value/min/max interface if the existing harness uses it; document the adapter rather than weakening the harness.
5. Bound DOM publication separately from immediate canvas feedback. Clear an image-settle timer on EVERY input frame, including repeated positions; an early return for an unchanged artifact can accidentally publish/decode medium images mid-drag. Test a sustained repeated-position input tape before and after the fix.
6. Attribute Paint clips and Layerize work. A small caption text update may repaint the document despite local containment. Measure a single instrument compositor boundary, not hundreds of card layers. Do not infer complete-frame work from JS submission time.
7. Test content-visibility rather than assuming it is free. Thirty-card reveals can produce large max-work spikes; smaller chunks may still add style/layout/prepaint bursts. A fixed-size whole-archive visibility boundary plus native paint-clipped sections can avoid these reveals while retaining accessible DOM cards. Keep rejected experiments and their trace receipts; remove regressions rather than advertise a lower p95 alone.
8. Defer initial canvas drawing until observer dimensions are usable. A pre-ResizeObserver width of one pixel can make scissor widths negative. Treat GL console errors as test failures and assert context restoration resumes a real draw.
9. Treat an owner-approved visual design as an independent gate. Compare identical timestamps and viewport/DPR on both public and local editions; retain unaligned PNGs, exact geometry, unmasked pixel deltas and a separate unchanged-UI count. Inspect the images: matching geometry alone misses text wrapping, count alignment and minification aliasing. Preserve native settled text; use canvas labels only during manipulation when text layout itself is the measured bottleneck. Restore immediate live scene/count feedback rather than hiding DOM cost by freezing state until release.
10. Share one frame scheduler between input and entry animation. Independent renderer and controller rAF queues can draw the same frame twice even when each queue is individually coalesced. Build browser-font label textures outside the scrub path; keep slider aria values current while deferring hidden DOM card text. Record font-atlas memory and cold-load tradeoffs separately from interaction timing. Avoid eagerly baking every full-width caption at full DPR without measuring startup: a fast uniform-only scrub can coexist with multi-second blocking and a much larger image transfer. Compare same-setting baseline/candidate Lighthouse, and keep a cold-start regression explicitly blocked rather than describing a gesture-only gain as an overall performance win.
11. Defer GPU context/shader creation as well as image and font work until an offscreen instrument approaches view; an idle upload queue alone can leave shader initialization on the cold main thread. Decode image pages in an owned Worker, prioritize the current window and upload small strips only outside input. State explicitly whether labels are demand glyphs or all-label pages prepared on approach. Record full transfer bytes, not just the first requested page.
12. Rebuild worker-produced GPU-backed ImageBitmaps after context loss instead of reusing them: real Chrome/ANGLE may reject their old shared-image mailboxes even when the JavaScript bitmap still has valid dimensions. Exercise loss/restoration after full readiness and assert no GL errors both before and after it.
13. Cover native labels with the opaque live canvas rather than changing their opacity if traces attribute first-input cost to text layer transitions. Keep native settled text and compare identical timestamps; removing a first-frame Layout/Layerize burst is not permission to drop the maximum-work gate. For deferred assets, document an explicit post-scroll readiness wait before the unchanged trace window, and independently test cold/unprepared behavior.
14. Port the full dependency closure to file-based review pages. Inline shared modules in dependency order and embed atlas images as data URLs; test both actual WebGL and forced Canvas2D with zero HTTP requests. Keep private local provenance out of public atlas manifests.
15. Preserve every admission condition: repeated interleaved before/after and bad control, exact browser binary and renderer, pinned owned descendants, p95 AND max, zero forced layout/LoAF, callback/frame counts and repeatability. A passing pilot is not admission; baseline instability and host load must remain visible. Headless emulation is not physical refresh-rate proof.
16. Treat recycled native text publication as a separate rendering cost. A small card ring can still produce layout/paint/layerization spikes on every recycled row. Compare it against an opaque live canvas with Worker-prepared nearby labels and native settled controls, preserving a complete semantic archive, actual row hit testing, keyboard materialization and no-JS fallback. Bound and close label bitmaps; rasterize only the text region rather than the blank image area. Test the real hot path with a MutationObserver and main-thread OffscreenCanvas instrumentation instead of inferring zero publication from source.
17. Import only URL-backed CSS font faces into a label Worker. Browser-generated local() fallback faces can reject FontFace.load and poison a shared Promise.all, silently moving all label rasterization back to the main thread. Assert actual successful Worker messages and zero main-thread label rasterization during prepared native scrolling; retain a readable cold/error fallback without retry storms.
18. Assert screenshot state before accepting pixel masks. Explicitly decode visible lazy baseline images, verify actual rather than requested scrollTop, and inspect high image-region deltas: an unloaded baseline can falsely appear design-equivalent under a broad image mask. Check the sticky canvas's actual padding-box offset at both zero and nonzero scroll; correct an image shift rather than masking it. Capture live and settled labels separately, with raw unaligned PNGs and unchanged-UI counts.
19. Do not equate an elapsed debounce timer with idle animation input. Host stalls can run a native-detail publisher between delayed frames, triggering layout even though input resumes on the next frame. Require an unchanged generation across quiet animation frames before publishing native details/URLs; preserve immediate canvas and ARIA feedback. Prove the bug with a delayed-rAF-delivery browser regression (ordinary CPU busy-waiting can fail to reproduce the ordering), and retain the original trace's publisher duration, thread CPU and ensuing layout. Scope MutationObserver hot-path assertions to the actual gesture interval so a delayed CDP reply does not count legitimate post-gesture settlement.
20. Publish a recycled archive's settled native window inside its existing animation-frame paint scheduler, not directly in the debounce timer task. Timer mutations can leave pending layout for a resumed scrollTop read before the browser's next rendering opportunity. Prove timer-task writes with MutationObserver.takeRecords around the actual timer callback, then rerun interleaved traces; preserve synchronous materialization for explicit keyboard focus. Zero timer writes and zero observed forced layouts do not close LoAF, frame-count or repeatability gates.
21. Align LoAF timestamps to trace timestamps with a performance mark's recorded startTime, then retain overlapping spans and bracketing main-thread CPU deltas. Empty LoAF scripts and tiny traced work do not prove idle or host-only delay: enabled categories can omit substantial browser/runtime/throttler CPU. Label unresolved attribution explicitly, retain failed infrastructure cohorts, and require matched asset mirrors before accepting repeated gates. A fresh ten-run scroll pass does not automatically qualify the separate scrub workload.
22. If LoAF script attribution points to the measurement observer, preserve raw entries during delivery and defer toJSON until after the unchanged window. Prove delivered and takeRecords entries retain the original overlap semantics and full script data, including a real long-frame browser control. Label the collector revision in evidence; sequential old/new observer cohorts cannot prove a causal cure, and all historical failures remain visible.
