# Cua Driver local evidence lane

For certifying upstream PR heads and researching structural work deletion in Cua Driver / jev-use (Driver+MCP+Chromium, isolated displays, interleaved A/B). Work downstream first; promote only the narrow mechanism established by independently audited evidence.

Standing rules (user preferences)
- Evidence-only default: never post, push, open PRs, or move an active PR branch without explicit user authorization. For local-only certification, a fix is a NEW local branch cut from the exact PR head (`refs/review/<n>` fetched from `https://github.com/trycua/cua.git +refs/pull/<n>/head`), upstream tracking unset, minimal commit, SHA reported. When the user explicitly requests fixes and a push to an existing PR branch, reuse its worktree and preserve the published history with normal commits/merges; do not invent a competing carrier or force-push. An explicit rebase/re-cut of an owned PR branch is the exception: force-with-lease that branch only after the remote SHA still equals the parent you rebased from.
- Fetch first and verify every pin; record old/new if heads moved. Reuse existing worktrees/harnesses; cut a NEW evidence branch instead of amending the old one.
- Tag every claim SRC / UNIT / FIX / REAL / BENCH / LIVE. Separate structural deletion from quantitative performance: mock-provider and injected-delay measurements establish only their stated cost regime, not live-provider performance. Report paired direction counts, uncertainty, sample size and platform scope.
- Qualify every optimization through forced path -> actual executed path -> admission/proof facts -> independent oracle -> explicit decline/fallback. Reject successful tasks whose intended optimization was not proven to execute. Mutation-test the evidence checker before trusting its verdict.
- Prefer deleting model decisions, then whole steps, observation producers, waits and redundant verification before micro-latency. Completed evidence is a reusable primitive; do not keep polishing it without a new review, regression or falsifying experiment.
- Give scientific conditions a stable `cell_key` and individual executions a separate `trial_key`; count repetitions as replication, not new coverage. Preserve completed packets and record supersession instead of rewriting them.
- Fail closed on safety: a cross-session mutation, replayed mutation, or stale-authority reuse means stop and report.
- Never touch the user's Hyprland desktop. Desktop GUI/input uses a parent-verified headless Sway harness; do not invent an unverified Xvfb fallback for that work. jev-use Chromium E2E reuses the existing scrubbed X11 session harness that CI uses, and that harness must still strip host compositor variables. Hermetic lanes must not invoke browser/computer-use tools or cached global Driver daemons. Secrets are forwarded by NAME only and never land in artifacts.

Procedure
1. Fetch pins and inspect current maintainer decisions, owner threads, downstream evidence and Driver/runner contract changes before selecting experiments. Reconcile moved contracts explicitly. Reuse existing work before creating an isolated worktree per lane (`git worktree add --detach` for read-only certification; a separate research branch for evidence commits). Install dependencies with `uv sync --frozen` and `npm ci --ignore-scripts`, or reuse verified dependencies read-only without mutating another lane.
2. Unit tier: mirror the CI workflow steps (read the workflow file, do not guess commands): unittest discover, npm test, tsc, verify_*_cli scripts, focused guarded tests, plus `cargo fmt --check` for Rust PRs.
3. Real tier: one Driver binary serves all arms when a PR touches only examples/ (diff `libs/cua-driver/rust` first). Bind each receipt to the exact clean runner HEAD, the Driver binary SHA-256, and its built Rust source-tree object. A main merge can change Rust despite an example-only authored patch; rebuild then. Reuse a binary for a later example-only commit only after verifying identical Rust source trees. When worktrees share a cargo target dir, `touch` every source file before building/testing, otherwise mtime freshness reuses another worktree's binary and you test the wrong code. After that head is validated, if upstream main moves again and the new tip does not touch the measured trees and merge-tree is clean, leave the measured SHA and name the newer tip. A parent-only re-cut unbinds the receipt.
4. A/B: interleave paired arms per seeded block; separate clean timing trials from traced route/fresh-ref/coverage passes. Serialize quantitative desktop trials; fan out cheap replay, scouts and checker attacks only when they do not contaminate measurements. The independent fixture `/state` and genuine submission journal own success. Measure the first independently verified outcome separately from cold startup, runner lifetime and cleanup. Pass ABSOLUTE output paths because cells run in a different cwd. Use a foreground call with a sufficient timeout for bounded runs; use notified background execution for genuinely longer batches. Preserve failures and partial packets rather than dropping cells.
5. Fail-closed fallback proof: invalidate the owned fixture DOM after the provider-selected first mutation (for example duplicate Submit), not Driver APIs. Require exact declined telemetry and provider routing, plus independent `/state` success. An evidence-only journal may wrap the genuine fixture submission handler, but must never initiate a submission. Inspect runner JSONL for token absence; elapsed provider time alone is not proof of a skipped call because tiny mock decisions can round to zero.
6. Live provider: reuse the configured key by name, respect the request cap (baseline costs 2 calls per trial, treatment 1), stop on rate limit.
7. Have a runner and independent auditor use separate contexts where practical. The auditor checks exact artifact hashes, source/tooling pins, path/proof/counter/oracle correlations and corrupted-evidence rejection; a worker's successful summary is not certification. Retain claim/falsifier, environment/factors, forced and executed paths, authorization/refusal facts, independent outcome, fallback, negative controls, named spans, work counters, invariant violations, hashes and exact reproduction commands. Keep protected field contents out of commands, traces, stdout/stderr and receipts, not merely the final report. Before publishing a sealed packet, compare every manifest entry against the committed Git tree: ignore rules can silently drop raw logs even though local verification passes. Copy missing sealed artifacts byte-exact into the authorized publication scope and explicitly stage them after privacy checks; never normalize or reseal immutable logs to satisfy formatting. Record narrowly scoped whitespace exceptions for preserved raw outputs.
8. In continuous research mode, maintain a CLAIM -> EVIDENCE -> NEXT DECISION graph and regenerate candidates from current upstream claims, measured traces and adversarial assumptions after every audit. Rank approximate decision relevance x information gain x claims affected x falsification power x reproducibility / implementation cost / runtime cost / confounding; explicit maintainer requests and qualification dependencies override the score. Prefer replay and fixture/configuration/delay injection before product changes. Classify KEEP / NARROW / REVISE / KILL / NEEDS_REPLICATION / BLOCKED and immediately select the next experiment; queue exhaustion is not a stop condition.
9. Periodically ask fresh agents which experiment would falsify the strategy and which remaining verified-outcome work could disappear without creating new authority. Keep successful policy recipe-local and opt-in; do not convert it into a new service or competing API. Stop/escalate continuous work only at the user's resource, architecture, reconciliation or information-value boundary. Name the exact blocker, affected decision, smallest next experiment/resource and next-best local alternative; execute that alternative when feasible. Package coherent evidence and analysis with reproduction commands, using normal downstream commits/pushes only within the authorized scope.

No-install promotion safeguards:
- Reconcile stale claimed issue envelopes against exact published evidence refs before declaring work absent or assigning another writer. Read recovered README/review/provenance artifacts at the remote SHA; a published packet proves historical work, not a currently running executor. Keep executor reconciliation separate and preserve owner refs.
- For exact native rebuilds blocked on offline rquickjs, use an explicitly authorized public locked build against the Driver manifest in an owned CARGO_HOME with the pinned installed Rust toolchain; retain crate checksums against Cargo.lock. Include the exact-source libs/images/sandbox-images.json sibling: cua-telemetry includes it at compile time even when only the Driver binary is selected. Preserve the missing-file build as setup failure, not a product regression.
- For actual semantic-v2 opacity proof, use an exact built Driver over direct stdio MCP, a fresh Driver-owned browser profile, production list_windows and exact native/CDP binding, then browser_navigate and get_browser_state with semantic_v2 plus screenshot. Wait for the owned Chrome window to map: endpoint readiness precedes native window readiness. Independently retain the same page's real AX backend IDs, DOM attributes, computed ancestor opacity and positive bounds, with lowercase-hidden and visible controls. Native Wayland Chrome on headless Sway is not Chrome --headless or physical-desktop acceptance. Chrome may expose a single joined /proc cmdline; locate the sole DevToolsActivePort only inside the attested private runtime rather than guessing split arguments or scanning host profiles.
- Independently audit semantic visibility receipts by joining real AX backend IDs to DOM children and DOMSnapshot parent/layout indices, then cross-check computed ancestor opacity, positive bounds and actual screenshot pixels. Require both zero-opacity exclusions and visible controls; reject receipt copies with fabricated positive AX IDs, wrong layout parents, missing positive/violation refs, blank screenshots or mismatched native PIDs. Public Driver refs may omit backend IDs: label unique-name correlation honestly rather than claiming a directly exposed ref-to-backend mapping. Keep immutable raw-transport correlation separate from decoded-receipt mutation tests, and check both owned TCP ports and Unix sockets after teardown.
- Separate real browser rendering facts plus compiled exact-source predicate probes from full Driver/semantic-v2/platform acceptance. CSS priority normalization can differ between Chromium computed style and a source-string parser; preserve mixed-case priority and visible controls, but require the actual Driver route before promoting a parser reproduction as end-to-end evidence.
- Locate displaced object stores and registered worktrees on mounted project volumes before assuming a checkout is absent. A shallow home/workspace scan can miss the actual Cua lanes; inventory local branch tips against live downstream refs and inspect the relevant local-only runner deltas before extracting a candidate.
- Reuse an existing example runtime only after comparing its dependency manifests and locks with the exact candidate. Invoke its Python directly with inherited PYTHONPATH/PYTHONHOME removed, and keep reused node_modules read-only. Re-run aggregate gates in a complete checkout: historical missing-SDK or missing-repository-input failures need not persist once the existing full runtime is located.
- Discover jev-use manifests, `.venv`, and `node_modules` at the shared `examples/jev-use` root before searching its language subdirectories; a missing runtime under `python/` or `typescript/` does not establish a setup blocker. Select already-installed runtimes matching the committed CI language versions, verify installed package versions against the locks, and hash reused dependency trees before/after to substantiate read-only reuse.
- Execute original published RED/GREEN tests under the safety envelope rather than substituting AST/string assertions. Count unittest methods separately from failing subTests, and Node TAP leaf assertions separately from failed parent containers; focused reruns overlap the full suite. Account for unittest docstrings that put the final status on a second line when reconciling parsed method counts.
- Inspect formatter configuration before receipt-only gates: a repository can default Ruff to `fix = true`, so pass `--no-fix --no-cache` explicitly. Keep inherited formatter failures separate from behavioral RED and retain them without changing the published source.
- For Sandbox adapter replay, use the component's supported Python range and exact uv.lock registry hashes; a root workspace's newer Python floor does not override the component. Install real locked cua-fleet rather than inventing fleet_sdk stubs, and distinguish its wheel from the generated read-only Fleet mirror. Keep build/Twine tools in a separate venv because newer packaging/pluggy dependencies can silently move test pins. Verify installed import origins before replaying unchanged tests against a built wheel, and retain missing native cua as a full-package blocker even when selected adapter tests pass.
- Inspect CI checkout refs before attributing a docs failure to an original PR: a salvage carrier can share its head, run a synthetic merge, then independently add generated-file repairs. Refresh that successor and its exact-head reference jobs before editing; obsolete original-head drift is not an unclaimed current repair. A shared-lock timeout means the generator never launched, not that generation failed.
- Distinguish terminal unknown-outcome handlers from a pending-mutation barrier. An exception path that already exits gains explicit redacted reporting, not a new exactly-once guarantee; an available oracle that reports no visible effect is a different case.

Reply-cancellation refresh:
- For current-main formatting qualification, preserve the original author and source SHA, compare the formatted TypeScript AST to the original, and keep unadopted `.mjs` tests byte-exact. The root Prettier script's glob excludes `.mjs`; report that limit rather than claiming all changed files are formatter-owned. Scope its supported `--ignore-path` filter from a temporary file at the checkout root, not the external receipt directory: ignore patterns resolve relative to that file and can otherwise yield a misleading zero-file PASS. Require the formatter write log to name every intended adopted file, remove the temporary filter before committing, and rerun build/type/tests/check on the final commit using CI's Node major when installed.
- Preserve repository-relative fixture layout in isolated SDK replay trees: presence-netcode tests load the sibling Rust crate's presence-conformance.json. A missing fixture is setup failure, not behavioral RED; retain that failed attempt and rerun with the unchanged fixture before comparing complete TAP totals.
- When a pure-Python guard forbids native/network access, report deselected native-dependent tests and websocket retry timeouts separately. A passing focused real-dispatch selection does not refresh an older full-owner count; fixture setup errors are not baseline behavioral failures.
- Keep SDK HTTP reply-wait cancellation separate from native admitted-action cancellation and upload resumability. Replay the original real-loopback partial-body tests on the immutable candidate and on baseline/current-main production with an explicitly labelled test overlay. A current-main source patch plus tests is composition evidence, not a newly tested commit. Inventory `gh pr checks` alongside exact-head workflow runs/jobs: passing administrative checks can coexist with approval-held product workflows that executed zero jobs.

Hermetic replay safeguards:
- Set `CUA_DRIVER_BIN` to an asserted-nonexistent owned path and scrub desktop/session environment before importing any runner. Patch the same ESM SDK export the runner imports, not its CommonJS twin: otherwise prototype mocks can fall through to a real stdio transport. Fail closed before any experiment, including bootstrap probes.
- Scrub inherited `PYTHONPATH` and `PYTHONHOME` when reusing an installed example venv; invoking its executable alone does not prevent a different interpreter's packages from leaking into imports.
- In interrupted exact-source exports, inspect archive member prefixes before mapping them back to scratch paths; a doubled item directory can make every unchanged file appear missing. Verify the corrected mapping against both tar bytes and the exact commit's `git ls-tree` blobs. Keep missing sibling fixtures and `.github/workflows/authorized-live-jev-use.yml` as setup failures until restored from the same head, not behavioral RED.
- When composing a copied Driver class, preserve consumer-facing accessors as well as transport behavior. Exercise the guarded consumer route and typecheck: direct normalization tests can pass while a missing session accessor silently routes guarded completion back to the provider. Inject canonical nested `error.code` through the real native runner; classifier-only tests with top-level codes do not prove producer normalization. Report nested TAP containers separately from leaf failures.
- Label historical outcome-only corpus rows as structural adaptations when pre/post snapshots, task/candidate objects or session-bound plans are missing. Do not call generalized rule-shape experiments execution of a recipe-local final resolver. Record producer reachability separately from synthetic resolver acceptance, and compare unknown-oracle retry behavior against the unoptimized runner.
