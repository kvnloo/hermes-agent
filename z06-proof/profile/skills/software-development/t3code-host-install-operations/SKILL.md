# t3code-host-install-operations

Use when diagnosing or operating installed T3 Code hosts, provider accounts, runtime state, thread organization or fork Android/nightly channels.

## Rules

1. Read the relevant docs/user page and identify actual runtime before answering: `t3 --version`, `t3 service status`, ~/.t3/runtime/service-state.json, process argv, desktop launchers and per-instance caches. Match source to serverVersion; inspect origin/main docs and history when the local checkout is stale. Separate installed version, available release and observed fault evidence.
2. Diagnose desktop startup through a bounded terminal launch and ~/.t3/userdata/logs/server-child.log. For ServerAlreadyRunningError exit 78, offer service-hosted clients, desktop-hosted service or client-only desktop as choices. Reserve stopping, channel switching and restarting for explicit owner timing; these drop active chats, terminals and remote clients.
3. For authorized client-only desktop setup, close the app, set localEnvironmentEnabled:false in desktop-settings.json and pair from home with `t3 pair --base-dir ~/.t3`. Keep pairing output private, including its short Token field, use loopback and the supported t3code://pair route, and let the owner confirm the backend. Keep updater and onboarding detail in the existing live-install-update reference.
4. Add provider instances instead of replacing binaries. Prepare each Claude directory at mode 0700 with a dedicated wrapper that explicitly sets CLAUDE_CONFIG_DIR and unsets inherited API/auth/base-url/OAuth overrides. Preserve existing instances. Back up settings, merge only intended changes, atomically replace and read back; configuration is only staged until authentication and real bounded inference succeed.
5. Generate real account-labelled OAuth URLs from one retained interactive login process. Keep callback codes inside private secret entry and keep independent active Claude/Hermes grants rather than sharing refresh-token ownership. Distinguish account directories, T3 instances, Hermes pool rows and conversation profiles. Check actual authenticated account, usage and reset windows; inference-only setup tokens cannot establish plan limits.
6. Rank picker instances by real 7/30-day provider-turn counts from a snapshot, preserving ACP grouping and host-specific availability. Set defaultModelSelection using the instance cache's actual model slug; use hermes-clean-acp on the owner's main host and respect hosts without clean. Apply settings atomically on every named host without an unnecessary service restart.
7. Diagnose send failures from boot-service.log, provider events, gateway status, dependency failures and native session admissions before driving the phone. Confirm OOM/pressure evidence and list recent unknown sessions read-only. Recover only sessions behind the reported failures with `hermes -p <profile> sessions discard <session_id> --yes` or `/discard <admission>`; list older ones, recheck unknown rows and ask the owner to resend lost input. Reserve gateway restarts for separate clearance.
8. Use T3 storageCleanup with worktreeKeepWhen:any-local-files for T3-managed trees instead of a custom sweeper. Apply only requested settings across named hosts, then distinguish settings readback from an observed cleanup event. Route home-level agent-run directories to root-pressure-safe-cleanup rather than pretending T3 owns them.
9. For thread cleanup, page all unsettled projects and classify finished top-level threads from the last owner ask and assistant tail. Keep decisions, approval/login/device steps, unfinished background reports, failures and unverified work visible. Settle idle empty placeholders and completed children reversibly, check every result and re-list; preserve running work and queued owner input. Follow references/thread-triage.md for bounded scripted calls and durable categorized indexes.
10. For scheduled-work migration or pause requests, inventory all projects on both servers and save original rows. Rebind through the destination's supported bindToCurrentThread flow; verify an idempotent cross-project replacement before pausing the original. Preserve one-time completed tasks and existing correct bindings. Use authenticated owner MCP sessions rather than another thread's bridge identity; organization alone authorizes no underlying workflow execution.
11. For priority-title ticks, read the t3-thread-titles README, save and review every digest record, and return exactly `titles: no changes` on empty output. Change only titles, preserve fitting manual wording, check each rename response and record every reviewed thread with confirmed titles using argument-list JSON serialization. Keep stable emoji prefixes until that server supports tags; nightly tag support alone does not migrate stable.
12. Use ~/.t3/userdata/statev2.sqlite rather than stale state.sqlite. Snapshot with read-only VACUUM INTO for heavy/multipass analytics; use explicit short read-only queries only where the references permit. Count field availability per provider, join native session IDs and prefer native usage ledgers without double counting. Reuse the weekly tool-failure report, filter no-match noise and follow references/state-db-data-model.md for exports.
13. Manage side-by-side Android channels with t3-channel and channels.json: preserve stable com.t3tools.t3code, add features to nightly and ship sequentially. Build exact pushed SHAs on fleet-runner, locally re-sign with the BWS-backed stable channel key and install -r --user 0 only with clearance. Dedupe devices by ro.serialno, verify artifact hashes and Success/package readback, and preserve pairings rather than uninstalling.
14. Dogfood composed nightly with its isolated t3-nightly.service on port 3793 and an empty DB. Keep copied settings separate from live native session state; copying live statev2.sqlite can replay real turns and scheduled side effects. Disable nightly GitHub polling, use scratch projects for demos and pair clients to the matching server. Offer a full main-service switch with timing instead of performing it unasked. Follow references/fork-android-channels.md and report each feature's actual demo status.
15. Treat owner UX critiques as mobile-first, preserve existing execution owners and trace exact appearance journeys through toggle, navigation, resume and cold launch. Verify inactive-screen bleed, contrast, wallpaper and actual blur capability separately; offer restart-to-apply only for a demonstrated limitation. Continue authorized source work when device access is missing and report source tests, APK build, installation and phone behavior separately. Follow references/mobile-appearance-qualification.md.
