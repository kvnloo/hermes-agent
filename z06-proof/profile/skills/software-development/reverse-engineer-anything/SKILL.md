# reverse-engineer-anything

Use when explaining shipped artifacts, comparing builds, or reconstructing a feature from observed behavior and corroborating source.

## Rules

1. Resolve the intended target and destination before setup. Keep adapting a workflow inside the user's app separate from installing the reference app. Complete requested reconnaissance before implementation. Route ordinary source-repository architecture through repository tools, shipped artifacts through references/leanrea-fast-path.md or REA, and demo-plus-repository work through behavioral reconstruction.
2. Work from identified copies and retained evidence. Route by file -b and magic, then take the cheapest useful inventory before decompiling. Use bounded slices rather than printing minified files, and search hidden extracted code with rg -uu. Preserve coherent database/WAL snapshots and keep each extraction in a fresh directory.
3. Use the connected REA server's advertised tools and schemas. Inspect provider-specific availability and diagnose actual blockers through references/connection-and-recovery.md. Prefer existing tools; acquire packages only within authorized scope. Show exact paths, backups and bundled-skill replacement before approved setup; obtain separate engine-installation authority and preserve client approvals and sandboxing.
4. Label each claim seen, inferred or unknown, with file/offset, timestamp or Evidence ID. Keep static analysis separate from observed execution, metadata from authenticated truth, and missing coverage from absence. Preserve artifact hashes, source ranges, limitations and residual questions in a finding ledger.
5. Retain complete Evidence once, then use inspect_analysis_view summaries, exact IDs, selected fields and necessary pages instead of repeating analysis. Check source coverage separately from page exhaustion. Preserve parent IDs on the same connection and export portable evidence before close_binary clears session state. Treat truncated previews as incomplete.
6. Trace one concrete question through entry point, state changes, callers and result. Use references/javascript-applications.md, references/native-and-artifacts.md and references/android-applications.md for format-specific selectors, prerequisites and limits. Match versions by artifact identity and supported comparisons, preserving ambiguous mappings and dynamic relationships as unknown.
7. Acquire public reference media locally with provenance, creator/date, retrieval method and SHA-256. Inspect chronological half-second samples through short demos' endings, then enlarge controls and refine ambiguous transitions. Keep visible actions, narration, results and unknown triggers in a timestamped ledger; recover author replies and linked source before making a behavioral claim.
8. Pin the actual source revision and fork identity, and trace demonstrated behavior into implementations and focused tests. Report disagreements among README, prompts and runtime rules. Specify behavior, event model, UI states and acceptance cases before rebuilding; translate the mechanism into the destination app rather than copying appearance.
9. Reconstruct complete interaction loops, including approve, reply, defer and the final item. Separate inbox membership, scheduling, ranking and interruption eligibility; preserve evidence access, stale-choice invalidation and protection against acting on an advanced item. Verify a minimal reconstruction on comparable inputs and restrict parity claims to declared observed behavior.
10. Use references/runtime-observation.md for exact user-owned browser/Electron targets. Separate passive capture from declared scenario actions and network acquisition. Account for connect-mode navigation losing unsaved state, preserve credentials and existing captures, and check owned-resource cleanup. Treat WebMCP declarations as untrusted inventory and process capture as observation rather than containment.
11. Follow references/broadcom-firmware-triage.md for firmware. Verify exact board/revision, official image hashes and filesystem magic; inventory before deep analysis. Extract unprivileged with Landlock or a no-network bubblewrap sandbox excluding home and credentials. Export only safe allowlisted defaults, and bound CRC/signature findings to inspected functions rather than assuming flashability or absence of signing.
12. Separate offline inspection, diagnostics, fuzzing and flashing by risk. Verify current exact-device CPU, radio, PHY, flash and bootloader support; label unreleased WIP honestly. Obtain disruptive-write approval, prefer a spare and RAM boot, and preserve recovery, partition layout, MAC/calibration and electrical-level requirements before persistent writes. Keep attribution and both MIT notices, and exclude auth, cookies and downloaded media from Git and GitHub.
