# dash-turbo-live-preview

Use when changing Dash during phone dogfooding, integrating preview workers, or porting its annotation, voice, and turbo loop.

## Rules

1. Discover actual client/package, Metro and bridge units, resolved release links, served SHA, port, and manifest before editing or promising live delivery. Use the correct native dev-client versus Expo Go URL.
2. Branch isolated candidates from the served revision. Preserve the served tree, shared dependencies, signing identity, app data, and active preview; use a private dependency overlay for native changes.
3. Prioritize the complete exact-session voice, navigation, S Pen, reply, and verified-refresh loop. Ship functional checkpoints before unrelated polish; keep launch shortcuts and offline error tests separate from native voice acceptance.
4. Name one integration/install owner. Compose disjoint worker commits and required native modules, then qualify the exact union through admitted off-host compute before promotion.
5. Apply turbo_decide.py before changing the preview. In worktree-serving mode, qualified JS HMR fast-forwards need no idle proof; follower pushes/release flips that restart Metro do.
6. Require logical turn, recording, foreground, and IME evidence before restarts or installs. Escalate idle holds after 60 minutes; empty TCP queues or a black dozing screen cannot establish idle.
7. Keep the S25 owner's active screen untouched. Use S22 candidate journeys under the shared lock, bounded ADB calls, fresh screenshots, and authorized virtual displays; ask the owner for physical acceptance only.
8. Check dash-phone-watch and read incidents first. Capture full native crash traces promptly and verify seen_rev against the actual served release before reporting a fix on the phone.
9. Fetch every served lazy chunk and exercise each touched surface on device. Verify native module and bridge-route compatibility; separate read-only metadata rollouts from session-mutating compaction.
10. Preserve drafts, queue, attachments, session identity, and voice ownership. Keep annotation Exit visible; accept ink only when a real stroke follows the tip and remains after lift.
11. Follow the native interaction contract: full-width multiline composer, one primary Send/Steer/Queue/Stop button, focus-gated ambient motion, pen-button mode toggle, anchored row actions, and in-app dictation/voice controls.
12. Report code, exact-revision gates, served, and phone-verified stages separately with inspected screenshots. Diagnose harness failures via references/harness-turn-failures.md and lag via references/on-device-performance.md; preserve failed reporter receipts.
