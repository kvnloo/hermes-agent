# ACE campus twin + public site

Recover first, stills-first website, lane-based Blender build-out.

ACE = all-sports peak-performance / human-flourishing campus. Thesis: the facility is the environment, the feedback loop is the product. Racquet halls are one subprogram; missing sports/healthspan program is an implementation gap, never dropped scope, never presented as built.

Owner-decided shape (always on):
- The campus is MULTIPLE specialist buildings around a public loop (spatial r1.1 `ace-facility-specs/v0.1/spatial/r1/program.json` + `ASCII-ATLAS.md`: R tennis, Q fine racquets, T team+strength, M movement, A APEX science/care, C commons+learning, W aquatics, I ice, L grass/food lab, S operations, outdoor track/field/action). The old 4-level stacked racquet building from the 2023 chats is superseded; do not keep polishing it.
- Architecture must be expressive, not code-minimal boxes: premium, minimal, warm solarpunk modernism. Style source is the owner's Parr-house portfolio (`kvnloo/architecture_demo`, `universe/incredibles/`): thin swooping/hypar cantilevered roof plates with deep overhangs and timber soffits, floor-to-ceiling glazing with raked mullions, offset stacked floors and cantilevered decks, stone bases under floating light volumes, water features, warm dusk glow. Take the form language, never its orange palette; keep the mineral/navy family but warmer (timber, travertine, bronze, living walls, ~3000-3500K light) with a sparing bold accent. Scale/program inspiration: UIUC ARC (huge multi-court rec centre, elevated track, stacked facilities), Amazon Spheres (glass biosphere with indoor forest at the campus heart), research-lab tower, terraced greenhouses.
- Stack floors for variety even where single-storey is more efficient (e.g. courts at grade with a gym/track level above on long-span structure; spectator mezzanines; 2-3 storey C/A/M; rooftop terraces). Connect buildings with airport-style glazed skybridges (moving walkways) and an underground daylit concourse. Plain single-storey white boxes fail review regardless of correctness.
- Program covers ALL popular sports: tennis, racquet sports, basketball, volleyball, futsal, soccer, American football, rugby, lacrosse, baseball/softball diamonds, track and field, aquatics, ice, gymnastics, climbing, combat, adaptive sport. An empty shell building or a flat outdoor parcel counts as missing; report coverage per sport.
- People must look real: rigged/generated or licensed character assets (Hunyuan3D/Tripo generation, asset libraries, MPFB-style humans) posed or animated from engine/OS state, actually using the facilities. Procedural low-poly mannequins/capsules fail review; use them only as hidden placement proxies.
- It sits on a realistic parcel in south/southwest Naperville IL with real surroundings (roads, neighbours, farmland, trees), lawns and lived-in amenities. A building on a flat green plane reads as barren and fails review.
- L also grows fruits, vegetables and mushrooms for the C nutrition kitchen/commons (garden-to-table), with safe evidence-based nutrient optimisation (light recipes, UV-B mushrooms, agronomic biofortification within limits, ferments such as L. reuteri yogurt). No unsafe methods, no medical claims.
- Flagship feature: AI form + intention analysis for ALL sports. A member states how they want to shape their game (e.g. emulate a pro); the system teaches the form, prescribes exercises, routes to experts. Protected court-side displays or projectors show playback with overlays and cues; the signature loop is a ball machine repeating one shot under AI feedback until mastered, then varied. Show displays + ball machines in the racquet halls (VISION/MOCK until a pilot), build prototypes per sport-form-prototype-gates, and judge success as retained skill vs a strong coach, never as reference resemblance.
- Backlog the owner expects next: people actually using the facilities and visible smart features, not empty rooms.

## Campus build-out (Blender lanes)
For a stacked-to-campus relocation, follow [rigid relocation gates](references/campus-relocation.md): preserve identity, camera-relative transforms, OS exports and floor elevations.
Follow multi-scene-reference-match-orchestration for lane mechanics. Setup order:
1. Checkpoint first: back up the old Blender worktree's diff/status and `.dream-loop/` into the run dir, then cut a fresh integration branch + worktree from the last pushed Blender head with only ACE-owned uncommitted work (scripts, picked PNGs). The old worktree mixes Rally House and web changes; never build lanes on it.
2. Smoke-render one camera from the base with `scripts/ace-render.sh` (clean env + host-wide flock; copy it to the run's `bin/`).

6. When the owner adds or changes scope mid-wave (a new core feature, a site, a food program), append it to the run's DECISIONS.md and `delegate_task action=steer` every running lane it affects in the same turn; lanes finishing on the old brief waste a wave.
7. Cross-check audit-lane claims against the cited file before relaying them; static auditors misread sources (e.g. claimed a palette the design doc does not contain).

Moving to / extending the multi-building campus:
- Reuse existing room modules; never remodel rooms from scratch. Relocate each module's objects as rigid blocks (parent to an Empty at the building origin, subtract old origin and floor height) and move cameras with their rooms.
- One integration lane owns `build_ace_campus.py` + `ace_campus_layout.py` (building registry, parcel, `place()`). Parallel lanes (site, farm, new buildings) write LOCAL-frame modules: `build(parent_collection, mats) -> collection`, origin at own footprint centre, z=0 ground, no world coordinates of other buildings, own preview script under the same flock. Write this contract plus a DECISIONS.md into the run dir before dispatching.
- Integrating a site module authored in a parcel-centroid frame: set an explicit shift on the module (applied to the registry it reads for clearances) and translate its root objects back by the same shift, then re-test every building/outdoor rectangle + 3 m inside the parcel polygon. Never edit dozens of absolute coordinates (loops, cameras, arrival) to chase the shift.
- When a dropped-in local module's footprint overlaps reused content in the same building, widen the building in the registry and offset the module (record the deviation for owner review); never let them interpenetrate.

## Engine + Bend
- For WorldKernel, projectile packs and solver comparisons, follow [world physics bakeoff qualification](references/world-physics-bakeoff.md): preserve exact legacy behavior, separate calibration from assumptions, keep replay state explicit and qualify timing failures against an untouched baseline.
- Recover engine state from branch heads + issue comments (see Locations), then run lanes in separate worktrees off the newest stacked branch: rules (new sport profiles on the sport-blind kernel + Bend laws/parity/sabotage) and world physics (WorldKernel) never edit each other's directories.
- Camera/CV observations must not be forced into WorldObservation fields they cannot measure (metric state, forces from 2D video); reject the conversion and add a sensor-observation shape with provenance + uncertainty instead of inventing values.
- Bend GPU: Bend 2 looks for CUDA at /usr/local/cuda; on this host it is /opt/cuda, so set `CUDA_HOME=/opt/cuda` or builds silently go CPU-only (the earlier 'nvrtc.h missing' failures). GPU work = `!` bang calls in a native `bend f.bend -o f` binary that emits `f.gpu`; run `--gpu 1GB` after nvidia-smi shows >=2 GB free; prove with `--gpu on` and identical stdout vs `--gpu off`. Reference runs: /mnt/zer0models/z0-wt/wiring/bend-evals (gpu-setup.md, results/gpu.jsonl). Lean 4.34.0 for `--verdict` is at /mnt/zer0models/bend-stack/lean-4.34.0-linux (keep host clang first on PATH).
- A capped CUDA run of a tiny workload (score checksums) is slower than CPU because launch/heap setup dominates; report it as GPU-live proof, not a speedup, and benchmark GPU only on heavy per-lane work (full rally/flight simulations).
- Integrate rules + world lanes on a fresh integration branch, then run `npx tsc --noEmit` and the engine + world suites with the wall-clock statistical test run separately; when that timing test fails, record the load average and reproduce it on the untouched base before calling it a regression.
- HomeBase features (robots, scheduling, revops/ROI, gamification tech tree) live on ace-digital-twin origin/main + origin/nightly src/; port them only after a seeded business simulation and owner review (simulate before commit).

## Architecture layers over reused rooms (v2 lesson)
- Iterate a new architecture layer on a cached base: build the campus once with the layer's module absent, save `base_h<hour>.blend`, then each pass loads it and runs only the layer's `build()` (~1 min) before a 24-spp/50% preview under the flock. Finals still go through `bin/ace-render.sh` from a worktree snapshot.
- Skins over reused envelopes: glass at wall+0.75 m with a dark backpan + 3000 K glow strips; plinths/glass/backpans must skip every 6 m door void, and new outdoor elements (water walls, pavilion back walls) get re-probed with `probe_exterior.py` — they silently closed A-east and R-north doors.
- Blender 5.2.2 sky API is verified by `test_blender_render_policy.py`: `ShaderNodeTexSky.inputs` contains only `Vector`; set `sun_elevation`/`sun_rotation` RNA properties in radians. `sky_type='MULTIPLE_SCATTERING'` is the new multiple-scattering model (enum also has `SINGLE_SCATTERING`, not `NISHITA`). Update the view layer before reading `LGT_Sun.matrix_world`; with `pos = -(sun.matrix_world.to_3x3() @ Vector((0,0,-1))).normalized()`, use `asin(pos.z)` and `atan2(-pos.x,pos.y)` (Cycles horizontal sun direction `(-sin r, cos r)`). Facility-OS checks read back h10=53.693575deg, h12=62deg, h17.6=6.480765deg, not the old stuck 15deg. Own the sync and exposure/WB in shared `setup_render()`/its render-pre policy, never a geometry-layer duplicate. Treat any protected interior's legacy ambient-dome exception as an explicit artistic lock, not a physical solar value; require same-settings pixel and vision A/B before acceptance.
- Objects created in the same session have identity `matrix_world` until `view_layer.update()`; call it before distance filters (entourage >= 8 m from cameras).
- Owner review uses object-ID masks: name every emitted mesh semantically (`ARCH_Roof_<bid>_<Gesture>`, `ARCH_Skybridge_<A>_<B>`), one object per element, and list final camera + hour pairs in REPORT.md.
- The shared render lock is contended by other lanes (12+ min jobs); queue finals as one background chain early and inspect previews meanwhile.
- A lane can return before its background finals chain finishes, and the chain dies with it. On lane completion, check the finals dir for camera logs with no matching PNG (or empty logs) and re-run the lane's snapshot-based finals script for just those cameras before reviewing or merging; never present preview-quality stand-ins as finals.

## Source-backed exterior site studies
- Test the actual campus registry plus 3m margins against exact candidate polygons before promoting a site; acreage or a buffered/rectangular envelope alone does not prove fit. Preserve pond notches and protected-area exclusions; expose any land-budget increase for owner review.
- Treat OSM landuse fields as design-study geometry, never cadastral parcels or proof of zoning/availability. Cache bounded Overpass/Nominatim responses with source IDs, attribution, stated width/height/elevation defaults and rate-policy compliance.
- Use owned headless GEV keyless aerials when photogrammetry is unavailable. Dismiss first-launch overlays semantically, require consecutive tile readiness and retain full-page provider credits. Inspect imagery for missing context classes such as railway corridors before finalizing the extract.
- Keep authored planting/amenity placement in site JSON, with the canonical registry authoritative when importable. Never silently translate an imported layout; document any proposed common shift and validate all building/outdoor buffers exactly.
- Test import inertia, unrelated-scene preservation and one-collection ownership with a no-render sentinel probe. Flat ground underlays may span footprints; raised objects must not. Check tiled concave parking by actual faces, not its enclosing AABB.
- Bind final PNG receipts to source hashes, render completion, image hash and camera/clearance probes. Use unique iteration filenames and fail-fast command chains: a failed render followed by a copy can promote stale pixels. Acquire the shared flock for every render; a bounded multi-camera batch may hold one flock across its clean-env Blender invocations.
