# terminal-agent-orchestration

Use when assigning, launching, inspecting, coordinating, recovering, or supervising local and remote terminal agents.

## Rules

1. Identify exact host, window, pane, native session, profile, and live owner first. Reuse the requested running agent and confirm submitted input plus real tool progress, not composer text or a title match.
2. Recover the owner's verbatim mandate before relaying it. Mark agent-added defaults as defaults and reconcile peers' current assignments before adding a worker or transferring ownership.
3. Preflight the installed CLI, exact model/account, and a real tool on the target host. Keep Claude/Nous workers in Hermes, GPT in fx/pi, and Google in Antigravity; preserve existing entitlement without paid fallback.
4. Assign bounded disjoint checkouts/files, protected state, output schemas, verifier, publication gates, and hard outer deadlines. Keep Opus on core fixes/integration and Sol on bounded support; review actual artifacts yourself.
5. Keep worker tabs within an existing session and default to at most two remote workers. Increase only after representative one/two/four-worker measurements and current quota, memory, and responsiveness admission.
6. Name the compute route in every brief. Send heavy CPU checks through fleet-build without groot fallback; keep GPU placement separately admitted. Use command-local environment and explicit remote Bash/runtime paths.
7. Reconcile wrapper exit, native admission/result, and artifact coverage separately. Recover unknown outcomes and live remote jobs before retrying; preserve partial artifacts and ignore already-consumed stale notifications.
8. Resume interrupted workers from their exact transcript and Git state after checking live leases and successors. Respect denied edits, explicit STOP, ownership, and resource gates; never recreate a refused write through another tool.
9. Serialize shared device UI and installs under named locks with one integrated install source. Preserve the owner's active screen and drafts; use authorized isolated displays and keep physical acceptance distinct.
10. Keep one integration owner responsible for exact-union gates and visible delivery. Verify served revision ancestry and actual client interaction; report each requested deliverable as ready, active, held, or not started.
11. Use native goals/loops or supported scheduling for standing mandates. Verify completion wakes, a slower stall backstop, STOP path, non-overlap, and delivery lifetime; continue independent eligible work when one lane is held.
12. Diagnose pressure through PSI, swap, process ownership, and real cgroup limits before relaunching. Clean only owned completed panes/processes and verify the original user agent survives; see references/host-pressure-triage.md and references/tern-agent-panes.md.
