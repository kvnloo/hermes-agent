# Dash Hermes session qualification

## When to Use

Use for Dash session roster, transcript, stale-thread or continuation changes.

## Procedure

- Read Dash's AGENTS.md, pairing boundary and worktree ownership before edits. Keep data/behaviour work separate from UI restyling and never restart the owner's bridge or Metro during qualification.
- When the owner reports "stale chats" or "missing chats", find out which side produced each row before changing code. The bridge lists OMP chats only from `~/.omp/run/daemons/*/broker.{sock,pid}` with a live PID. Threads that appear while no daemon has those files come from the phone's persisted store, so the fix is reconciliation (`stale`), not bridge discovery.
- To put a qualified branch on the owner's phone, use the owner-phone-dogfood reference in the dash-living-night-proof skill (combined tree, bridge and Metro swap, roster check).
- Inspect installed Hermes API source and real SessionDB metadata before filtering sources. Native session-authority CLI conversations can have source `local`, not `cli`; excluding it hides the owner's current chat.
- Reuse z0live's read-only multi-profile SessionDB discovery and garden's loopback native API/key-file boundary. Never copy a full host-tool API key to the phone or start a new full Hermes gateway merely to read history.
- Keep roster profile refresh free of `hermes gateway list`: full CLI startup can load Bitwarden and outlive a short timeout, orphaning secret-loader children. Reuse `HermesSessions.profiles(false)` and native gateway-state projection instead; cache the last successful snapshot, coalesce refreshes, and never await refresh on connect. Prove the native path spawns no children; process-group termination is required only if a subprocess fallback is retained.
- Initialize Git metadata in fleet source stages before running Dash's full bridge suite: the file-inventory test invokes real `git ls-files`, and source-only stages omit `.git`. Fetch artifacts with their stage-relative `src/` prefix. Use a larger per-test timeout for CPU-throttled fleet fixtures without reducing assertions.
- Prefer a profile's reachable API, but prove a named endpoint knows that profile's native session ID before trusting a copied `.env` port/key. Default API credentials must not silently replace another profile's roster.
- Carry host/profile/session identity in roster, sends and history responses. Identical native session IDs across profile databases must remain distinct.
- Treat persisted native chats as available conversations, not running processes. Successful roster snapshots mark missing phone threads stale without deleting history; failed refreshes are not empty snapshots. Provide phone-local Clear ended.
- A live CLI holding a session shows up in `<profile home>/runtime/active_sessions.json` (pid + process_start_time; read it, never lock or write it). Current Hermes runs every classic CLI/TUI turn inside the profile gateway (`hermes_cli/gateway_agent.py`): the CLI lease pid is a thin viewer with a loopback TCP link to the gateway, the TUI writes no lease, the gateway writes a `gateway:local` lease under its own pid during turns. Classify before waiting (`bridge/src/hermes-gateway-host.ts`: serving gateway from `gateway_state.json` + `/proc` TCP link, or a `source='local'` session). Gateway-hosted sessions get replies NOW via Hermes's own thin client `hermes chat --resume <id> --query-file - --format stream-json` (FIFO: next turn, or queued behind a running one; follows only its own admission). Only a standalone owner keeps `handoff: queued`. `bridge/src/hermes-continue.ts` is the seam.
- Recover a session pinned to an exhausted provider through native gateway model mutation, not `hermes chat --resume --provider/--model`: resume rejects creation-route changes. Use `connect_gateway`, `PreparedMutations.apply(..., 'model', {'model': ..., 'provider': ...})` (the `/model` path), and read `session.resume` back. A `status: deferred` result is NOT a switch; stop only the owned recovery admission with generation-fenced `session.interrupt`, wait for idle, then apply again. Honor context-switch confirmation through the native callback when the user's requested subscription switch authorizes it; never disable the guard. Send the recovery check through native resume without creation flags and verify the exact assistant message in the canonical session. Historical billing metadata may retain the old provider; verify the live snapshot route instead.
- Do not use the API server's `/v1/runs` to write into a session a CLI/TUI viewer holds: it refuses those sessions, and the unprefixed route runs under the DEFAULT profile with the target's id, which wedges the target in `admission_conflict`. For a mid-turn steer, as opposed to a next turn, use the gateway submission helper the z0live relay uses (`bin/z0live relay`), returning `steer|next_turn`. Keep one send-to-session mechanism per host rather than one per app.
- Do not use the gateway ACP projection (`hermes acp`) for a session another viewer is using: it forwards every viewer's deltas into the prompt stream, so the terminal's own turn text leaks into Dash's reply. Prove with `scripts/verify-hermes-gateway-live.ts` (busy targets, foreign-text check). The classic prompt_toolkit CLI does not paint other viewers' turns (TUI does); judge a TUI pane by its newest `│ reply` line, not by counting words (the alt-screen capture caps history). Prove with `scripts/verify-hermes-handoff.ts` on a throwaway session; drive the proof CLI in a private `tmux -L` socket and type `/exit` with `send-keys -l`, then Enter separately (a same-burst Enter is swallowed by the completion menu).
- Bots must not list persisted Hermes sessions (`hermes:session:*`, ~150 on the owner's host): collapse them into a chat count on the profile row; they also must not mint Orchestra projects.
- Never resume through a second CLI that runs its own agent beside a live writer. The gateway thin client is a viewer, not a writer, and only runs when a serving gateway is proven. Sends must check the exact target, serialize Dash turns and stop after an ambiguous result. Standalone in-process ownership still requires an orderly owner handoff.
- Use the repo's pinned WebSocket types in proof clients. If the global constructor lacks Bun's header-options overload, use the bridge's supported execution-token query lane only with disposable proof credentials; never print or persist that URL. Keep HTTP auth in headers.
- Verify cross-surface delivery in three stages: read the exact reply from canonical Hermes history, retrieve that reply through the history path used by the running Dash bridge, then verify the phone renders it in the same host/profile/session. Discover the running bridge's checkout from its PID cwd before testing its reader; another worktree may implement different history logic. Compare native title and latest visible message ID, not raw counts, because API projections and compaction differ. A reply in SQLite or a gateway snapshot proves persistence, not phone visibility; report the verified stage and remaining gap instead of saying it appeared in Dash. If phone verification is unavailable, request a screenshot including the chat header to distinguish stale rendering from a different thread; do not repeatedly resend the same recovery prompt.
- For background-work updates, reuse the installed `dash-report "title" "body" [--url dash://notices]` path rather than creating another dashboard or sending a new agent turn. Read the CLI from the running bridge release before relying on default ports or credentials. Verify the returned notice ID in private persisted history and authenticated WebSocket replay at `/ws`; keep execution tokens in headers, never printed. These prove backend delivery, not phone visibility.
- Distinguish a stopped phone app from a broken backend: inspect `pidof app.dash.mobile`, the resumed activity and, when debuggable, the exact notice ID in the read-only `dash.notices.v1` storage projection. If the owner is active in another app, do not launch or force-stop Dash; retain the update for reconnect and use a non-focus-stealing notification pointing to Settings → Notices. Report rendering as unverified until actually observed.
- Inspect the listen address before declaring Metro down. Expo localhost can bind only `[::1]`; use `curl -g 'http://[::1]:<port>/status'` for that listener instead of treating an IPv4 connection failure as service failure.
- Qualify code changes with an owned loopback bridge, isolated credentials under TMPDIR, authenticated HTTP roster and WS history.
- Print only titles, IDs, counts and short nonsecret status in receipts. Do not print message bodies or keys. Tear down only the owned bridge and verify its port is unbound.
- Make fixture scratch portable without falling back to system temp: prefer TMPDIR and use a private home-cache directory when CI leaves it unset. Give protocol fixture objects explicit named types so literal discriminants do not widen under Bun's typed assertions.
- Run full unit and mutation commands under the host's heavy lock. Keep the operator's exact bridge swap command, credential directory and approval gate flags in delivery notes. A bridge restart alone does not update the phone app's reconciliation code.
