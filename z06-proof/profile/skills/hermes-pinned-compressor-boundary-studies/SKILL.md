# Pinned compressor boundary studies

## When to Use

Use for exact-SHA compressor characterization, deterministic paired availability
studies, or separating tool-pruning mechanisms from unshipped API capabilities.

## Procedure

- Pin a freshly fetched upstream SHA separately from the downstream study branch. Assert the imported compressor's checkout HEAD before execution; external pytest paths can otherwise select the wrong source tree.
- Test both lean tail demotion and proactive pruning. They emit different stubs; a tool's dedicated summary template can precede the generic fallback. Inspect the emitted content, not just the fallback source.
- Separate an injected historical transcript result from a live tool invocation. If the pinned tool lacks read/doc dispatch, assert that rejection and explicitly skip the unsupported doc case; scope the verdict instead of claiming an end-to-end reproduction.
- Write real UTF-8 bytes for on-disk fixtures. A string containing backslash-x escapes is not the corresponding byte sequence.
- Replace only the summary LLM call for deterministic boundary studies. Preserve native planning, pruning, iterative summary handling, assembly, and anti-growth checks; count completed compactions separately from messages or agent turns.
- Treat K0 as zero optional recency, not zero physical tail, when native active-turn guards retain anchors. Record actual protected tokens and achieved ratios for both arms.
- Account for native summary prefixes and merged carriers before sizing output. Measure scaffold overhead without looking at target outcomes. Keep transient ratio mismatches in the full trace; do not silently filter them.
- Freeze probe IDs/source digests across arms, ratios and checkpoints; hash actual raw trajectories before native token memoization or tail metadata can mutate rows. Counterbalance arm order with fresh compressor state.
- Label literal-presence scoring as deterministic availability, never model recall. A proposed non-inferiority gate must reject deterministic rows and remain unapproved by default.
- Audit the living protocol body and full comment chronology before freezing a gate. Record adopted requirements separately from later suggestions, contradictory remarks, edited corrections, and unposted drafts; a tolerance proposed downstream does not amend an upstream worst-point gate.
- Freeze treatment boundaries explicitly: a read repair, write gate, larger hot-store cap, hygiene skill, background promotion plugin, and governed compaction are separate mechanisms. A green unit battery or manual field pilot cannot substitute for a missing architecture arm.
- Isolate probes on disposable copies of each arm's own checkpoint without resetting accumulated treatment state. Shared initial seeds/exogenous workloads support pairing; forcing identical later summaries or histories changes cumulative retention into a local replay estimand. Do not count checkpoint branches as independent trajectories.
- Keep native-package comparators separate from component-isolation and equal-resource ablations. Do not weaken native retrieval to manufacture architecture gains, translate character budgets into token matches without measurement, or treat failure to show superiority as equivalence or adoption permission.
- Specify no-memory-write, no-persistence, and later deletion/revocation contracts separately for every declared sink. Recovery must consult current authorization and preserve authorized-recovery controls; finite lexical or semantic probes do not prove universal absence.
- Keep discussion authority and execution evidence separate. Distinguish reporter endorsement, maintainer product decisions, automated triage, claimed runs, and independently reproduced exact-tree receipts; record unread gists or missing raw data as limits.
- Bind consent/provenance controls to harness evidence rather than fixture prefixes or foreground-session status. Challenge identifiers independently and distinguish delayed promotion/retention-until-bank from no-retention.
- Freeze effective compaction policy and collect actual cache/input/output/reasoning usage. Treat price matrices quoted in discussions as claims until independently verified for the pinned model/provider route.
- Run Hermes imports in the authorized hosted CI-parity environment. Verify JUnit testcase nodes, artifact study/source SHAs, unique paired keys and full trace counts; workflow success alone is not a result.
- If a fleet preflight is rate-limited, an explicitly authorized direct workflow dispatch may still succeed. Read back the exact returned run and fetch its artifacts; do not infer that every REST endpoint shares the same failure or repeatedly poll a blocked endpoint.
