# root-pressure-safe-cleanup

Use when groot lags or swaps, agent workloads cause memory or I/O pressure, or root, tmpfs, bulk storage or MBP disks fill and need ownership-safe recovery.

## Rules

1. Measure before changing policy: uptime, free, swapon, memory/IO/CPU PSI, vmstat, per-process RSS/VmSwap and same-window IO deltas. Include tmpfs files and zram's compressed footprint. Attribute processes by cgroup, cwd, ancestry and lane, including your own gateway and timers; compare process IO with diskstats and swap before naming a culprit. Require at least 30 percent of system-wide IO in the same window before attributing pressure and adding caps.
2. Coordinate with omp for exact ownership and keep/delete lists before stopping or deleting its work. Preserve the phone Metro, compositor, terminals, browser and active paths. Stop your own side job first when pressure spikes; run experiments one at a time in capped units and keep CPU preparation separate from GPU training.
3. Admit groot-local work through groot-admit with the actual need: require the documented 6 GB desktop reserve, full-memory PSI below 5 percent and swap below 85 percent. Honor exit 75 and fleet health, thermal and queue holds. Place new harnesses under agent.slice at launch; account for memory that stays charged to the original cgroup after migration.
4. Keep agent-oom-guard.service the sole oom_score_adj writer. Use its batch 900, tools/subagents 800, other-user 200, protected-root 100 and system 0 ranking. Preserve root harnesses, renderers and service mains and keep protected scores at least zero. Use hard MemoryMax and child-first selection rather than whole-harness oomd pressure kills; verify `agent-oom-guard --check` and kernel-effective placement before claiming protection.
5. Obtain owner approval for new killability, swap removal or gateway/omp restarts. Keep the gateway in the owner's shared slice without silently adding a separate cap. Keep gateway/core CPU and I/O unthrottled because they serve every session. Run privileged changes through the Hyprland-session polkit dialog and a backup-making repo script; keep passwords outside agent tools and avoid restarting the gateway that hosts the current turn.
6. Resolve live config links before editing .files. Use an owned worktree off origin/deploy/live while that remains the live release source; preserve unrelated changes. For authorized deployment, hold `/tmp/files-live-deploy.lock`, compare every LINKS source against its live target and read back systemd/kernel state. Treat committed, root-applied and running policy as separate milestones.
7. Diagnose SIGKILL and pressure-relief SIGTERM separately using kills.jsonl and the agent-oom-guard journal. Preserve terminated benchmark evidence and stop retry loops during relief. Log scheduled jobs' duration and peak memory and recheck early runs. Stream database scans or use exiting subprocesses instead of retaining huge tables in the gateway; time out whole owned process groups and check for orphaned descendants.
8. Pair every service cap/throttle with a real functional probe and same-window pressure comparison, reverting ineffective changes. Record persistent user.control overrides and restore effective cpu.max/io.max explicitly when removing them. Write a z0.manual_mitigation.v1 lease.json with owner, approval, expiry, before/applied observations, exact probe and hashed nonempty evidence, including failed probes.
9. Audit independent targets independently and inspect LoadState before interpreting unit defaults. Distinguish configured journald ceilings from actual current-start evidence and counterfactual replay inputs from retained incident measurements. Preserve external groot-admit callers and bounded-wait behavior when changing CLI limits. Verify real recovery and generated-artifact ownership instead of blindly running doctor --fix.
10. Keep agent scratch on bulk-backed `${XDG_CACHE_HOME:-$HOME/.cache}/agent-tmp`, private and inherited while preserving explicit TMPDIR. Check the standing fframes tmpfiles policy/timer and scan allocated /tmp files and directories. Relocate only inactive, owner-qualified artifacts by verified copy plus compatibility symlink; report tmpfs allocation released separately from physical RAM. Set T3CODE_NO_BROWSER=1 for agent-run standalone servers.
11. Enforce the existing UI-tier no-swap intent through session.slice plus explicit Noctalia coverage and groot-memory-intent.toml, using exact unit ownership rather than comm qs. Read both limits and current swapped usage; lowering memory.swap.max does not fault pages back in. Preserve the live shell, require approval for swapoff/restarts and verify effective values and drift checks before declaring deployment.
12. Measure df bytes/inodes and findmnt per target mount. Scan with bounded `ionice -c3 nice -n19 du -x` batches without following offload symlinks. Use metadata only when secrets must remain unread. Qualify owner, age, Git state and current cwd/exe/fd/maps immediately before deletion, and retain receipts and unknown ignored content.
13. Apply references/disk-reclaim.md category boundaries: keep active npm caches and model/benchmark assets; use Hermes-owned GC only when directed and `uv cache prune --offline --no-config --cache-dir <explicit>` without force. Preserve receipts before reclaiming inactive fleet snapshots older than 24 hours. For checkouts, verify fresh remote reachability and an --all --reflog recovery bundle; remove qualified worktrees through Git while preserving branches and shared stores.
14. Plan archive-then-delete with `scripts/stale-tree-cleanup.sh plan|apply <receipt-dir> <root>...` only for agent-run roots such as ~/workspace, never home itself. Inspect plan.tsv by top-level directory and preserve active paths. Check existing MBP cleanup/T3 retention first, send scripts through bash rather than fish syntax, inspect recursive copies and inactive duplicate environments, and report Btrfs savings from df rather than du.
15. Treat recurring fills as a lifecycle repair spanning T3 worktrees, fleet spools and home-level E2E roots. Recover MBP capacity well beyond kubelet's approximately 12 percent clear threshold, aiming around 20 percent free; verify DiskPressure and ClusterQueue stopPolicy None without manual uncordon/hold bypass. Record per-item freed bytes, kept paths and before/after pressure in `/workspace/zer0/data/operations/storage-maintenance/runs/<session-id>/SUMMARY.md`; report functional recovery and sustained-load limits separately.
16. For a steady disk-fill rate, look for write amplification first: per-process `write_bytes` in /proc/<pid>/io, plus a two-sample `du -sm` of candidate roots (run it detached with nohup; MBP's fish shell and IO pressure kill long ssh one-liners). Known offenders:
    - ctx in auto mode republishes a full Tantivy generation and re-copies every source SQLite whenever a live Hermes state.db changes. Fix: manual mode plus `ctx-import.timer`, on both hosts.
    - Playwright `trace:'on'`/`video:'on'` keeps ~1.6 GB per army run, and the HTML reporter copies it again.
    - Hermes `state_meta` `gateway.admission.result.v1.*` rows keep each turn's messages forever.
    Receipt with numbers: `storage-maintenance/runs/mbp-growth-20261105/REPORT.md`.

## Fix the growth source, don't park it
When a disk report names a growth source and Kevin has asked for a fix, apply it at the source (the job's runner or config). Don't list it as a pending "decision" while repeatedly deleting copies; that is the miss he calls out. Procedure:
1. **Ask what data is actually needed.** For every artifact class a job writes, measure size per run, then how often anything reads it. Most hosts mount with relatime/noatime, so atime can't tell you. Instead, grep agent session history (profile `state.db`, opened `mode=ro`) for opens of that artifact type (e.g. `show-trace`, `.webm`, `-html/index.html`) and grep code for consumers. Discount boilerplate that only echoes a path, such as Playwright's failure hint. Report it as "X opens in N days".
2. **Add a flag; default to the needed set.** Use an env var like `ARMY_ARTIFACTS=failures|all|off`, defaulting to failures only. Keep the verdict json and log always, and the bulky artifacts only for the newest N failing runs. Pass the flag explicitly through ssh to remote runners, and read it back once.
3. **Prefer library settings over hand-rolled deletion.** Examples: Playwright `trace/video: 'retain-on-failure'`; the HTML reporter linking to artifacts rather than copying them. Where a whole subsystem is hand-rolled, name the maintained OSS that replaces it (see the reference below).
4. **Swap a running bash script in by atomic `mv` of a `.new` file**, after `bash -n` and keeping a `.bak-<tag>`. Editing it in place corrupts the loop already running.
5. **Purge the existing backlog** of finished runs (a `.exit` marker is present, never in-flight runs). Use `nice -n19 ionice -c3` and write a per-path size receipt TSV. Then report before/after `df`.
