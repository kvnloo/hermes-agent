# OMP read-only promotion assessment

## When to Use

Use for an OMP candidate wave that permits remote reads and local evidence but not external writes.

- Load upstream-contribution and repository policy first. An unresolved control-plane permission or failed claim release remains a hold; never retry through another route or turn review preparation into an upstream write.
- Inventory all fork refs and open origin/fork PRs with pagination; verify cardinalities against GraphQL totalCount. A complete ref inventory is not a complete code audit. Record the lexical candidate-screen scope and uninspected local roots explicitly.
- For every active carrier collect issue comments, formal reviews, inline comments, timeline and paginated GraphQL review threads. Record exact head/base, conflicts, pending reviewers and current-head checks separately. Green historical checks or zero unresolved threads are not human approval or current-base qualification.
- When commit-to-PR lookup is empty, search closed PRs by source behavior/title and inspect author follow-ups. A closed superseded carrier may have the exact orphan fork head even when the commit association endpoint returns nothing.
- Keep code heads, evidence-only descendants, sibling repairs and existing carrier ownership separate. Two PII repair branches from the same parent do not contain one another. Do not count an evidence branch as an additional promotion.
- Fetch bounded immutable source snapshots and verify Git blob SHA plus SHA-256. Run actual modules in an isolated no-network sandbox with fake HOME/TMPDIR; preserve all per-subprocess exits and logs. Driver exit zero is not test success.
- A minimal alias shim may re-export verified real utility modules to complete a focused Bun source graph. Label this module-scope execution, not full package or native-addon certification. Resolve genuine pure-wrapper dependencies before declaring native execution blocked; never replace behavior with a passing mock.
- For current-main runner-cache qualification, use a complete isolated checkout and frozen dependency install before package types; utility alias shims do not qualify the production caller graph. If a published native addon is needed, fetch its exact-version platform leaf, verify npm integrity, and label it as a prebuilt dependency rather than a source rebuild. Exercise unmodified `PythonKernel.start` after deliberately priming the actual cache key with another source, plus an unprimed cold control; current Python/IDA/MLX callers use fixed distinct tuples, so that injection is not evidence of a spontaneous cold-start or upgrade defect. Keep the original helper/tests byte-identical and supplemental probes outside the minimal upstream patch.
- For baseline replay against an owned dirty candidate, export the immutable base helper to scratch and bind it read-only over the helper path in a private no-network bubblewrap namespace. Keep the repository read-only, make only owned fixture scratch writable, and compare the unchanged worktree status/diff before and after; this avoids temporary source edits and restoration races. Bind each arm to the helper blob and the candidate tree, not merely the shared HEAD.
- When paginated GitHub PR files stop at 3,000 below changedFiles, retain that coverage gap instead of treating pagination as exhaustive. Fetch the exact lane paths at the affected immutable heads and compare them with the unfixed baseline; this can resolve whether those broad stale-base carriers contain the mechanism without claiming complete unrelated-file coverage.
- When requalifying Python-only component fixes, compare the entire SDK tree to the newly pinned upstream before carrying source equivalence forward. Replay the unchanged frozen union tests with arm-local production imports against upstream and each leave-one-fix-out variant; keep full-SDK inherited teardown failures historical unless actually rerun, and never count the union as another repair.
- When REST quota prevents detailed CI jobs, use bounded GraphQL check-run annotations to distinguish integration job timeouts from unsupported dependency-review features. Bind annotations to current-head job IDs, retain inaccessible step/log gaps, and do not infer a product regression from cancellation.
- For Python startup-registration cleanup, supplement fake-child tests with an actual no-network Bun RPC host rejecting duplicate custom-tool names. Capture the child/readers at ready, assert the original registration error and immediate child/thread cleanup, and always stop only the owned process in finally on RED. Pin the host independently from the SDK arm; reused native addons, generated tool views and explicit provider/model selection are environment prerequisites, not current-main host qualification. If full-SDK historical teardown failures do not reproduce on either arm, report that result without inventing a repair.
- Distinguish natural probe completion from child teardown policy and launcher identity. If RpcClient launches bwrap, its Popen returncode -15 identifies bwrap, not necessarily Bun. Capture `/proc/PID/exe` and replay direct Bun inside an outer no-network namespace before assigning an exit code to Bun: OMP's SIGTERM cleanup can return 143, while stdin EOF can race it and return zero even when the real SIGTERM syscall was sent. Preserve failed strict exit-code claims and qualify resource cleanup separately; do not relabel observed zero as proof no termination signal occurred. Require the probe itself to finish without a success-exit shortcut, capture descendant PIDs/readers/pipe handles before failure, and verify reaping and resource release afterward. Use a separate TERM-tolerant EOF fixture for deterministic natural-zero and socket-port-reuse controls.
- When the independent gate runner becomes a Linux subreaper, concurrently reap only its adopted orphan children while leaving each active direct Popen child to its owner. A subreaper that waits until the whole test ends can keep killed grandchildren as zombies, causing otherwise-correct SDK killpg/survivor tests to fail on both base and candidate. Preserve the contaminated attempts, test the runner's TERM-resistant-descendant cleanup independently, and rerun unchanged source/tests after correcting reviewer containment.
- Under fake HOME, an installed user-site pytest can disappear. Reuse the verified package location explicitly through `PYTHONUSERBASE` or the exact existing interpreter, preserve the no-module attempt as setup failure, and keep production PYTHONPATH arm-local; do not install or mix candidate/base source to make collection succeed.
- For no-source-edit mutation reviews, bind a checksummed mutated copy read-only over the production path inside a private namespace. Record caught/survived/inconclusive outcomes, ensure named behavioral tests execute, verify tracked hashes never change, and replay restored frozen/full suites after the overlay vanishes.
- For PII-example qualification, run the committed Bun test through the real ExtensionRunner graph, not a stripped helper substitute. Use a frozen install with lifecycle scripts disabled, explicitly run `gen:tool-views`, and obtain the exact native platform package version with verified registry integrity when source-native rebuild is outside scope. Pin origin and downstream donor independently; overlay pre-repair production source read-only under identical tests to prove literal-placeholder, binary identity, shared-reference and tool-details sensitivity. Keep actual persisted JSONL, PAW NER and provider transport as separate gates.
- Run package scripts from the actual package cwd (or use the documented equals form for Bun's cwd flag). A misplaced `--cwd` argument can print help and exit zero; require output showing the expected lint, formatter and typecheck commands before accepting the gate. Preserve that invalid attempt separately.
- For restored Bun bundles in a read-only namespace, create ignored dependency/generated-file mountpoints in the owned restore checkout before binding; a missing mountpoint on the read-only root is setup failure, not a test result. Do not overwrite tracked native loader sources to hide a restore discrepancy; verify matching loader blobs when mounting a prebuilt dependency directory.
- Treat a published evidence runner's exact RED-count guard as a distinct acceptance condition. Extra timeouts can stop baseline replay before candidate execution; preserve the failure and run the unchanged candidate and independent probes separately, without weakening the owner's guard or calling the packet replay green.
- Record import-resolution failures separately from behavioral regressions. If a broad three-file run has import failures but an isolated file passes, report only that isolated file as freshly passing. Preserve failed attempts.
- Rerun the baseline with identical tests. A performance optimization can correctly have green functional tests on both arms; its red gate is the frozen performance criterion, not an invented correctness failure.
- Read the newest exact-source receipt before carrying forward typecheck holds. Keep historical package-types success separate from unverified root/workspace types, hosted CI and native suites.
- Rank wrong-result correctness repairs and existing review obligations above speculative micro-optimizations. Renderer regressions remain adoption holds despite Unicode correctness. Never relabel helper timing as end-to-end savings.
- Finish with a concise ranked report, machine-readable candidate/review/test ledgers, immutable source archive and a hash index. Reverify archived source identities and log digests; keep every external mutation disabled unless separately authorized.
