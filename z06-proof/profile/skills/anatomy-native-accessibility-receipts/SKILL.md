# Anatomy native accessibility receipts

## When to Use

Use for downstream Anatomy dial/example input fixes and native evidence qualification. Repository-relative paths below refer to the Anatomy checkout.

- Recover the exact fork PR head and complete reviews, comments, inline threads, requested reviewers and CI before changing it. Preserve author ancestry with a merge, not a rebase, when force-push is forbidden. Use a new pinned downstream base ref if changing a shared validation base would affect sibling PRs.
- Read current CONTRIBUTING.md and the repository's motion reference. Anatomy forbids code comments; framework-free builds commit both themes. Reproduce input defects in the actual generated page before editing build.mjs.
- Keep driver changes with their owner. Existing drive.mjs supports native keys and mouse actions but not native touch taps; a dispatched PointerEvent is only a synthetic browser regression. Supplement it with an owned headless Chromium touchscreen/CDP receipt that verifies pointerType=touch and isTrusted=true.
- Test reduced-motion first-frame state by preloading a wrapper around native requestAnimationFrame, calling the production callback first, then recording carriage/plunger/needle/readout DOM state. Arm recording from the actual key event and wait for a captured frame; a delayed final screenshot can miss a spring tail. When counting frames with Playwright, use interval polling rather than its default requestAnimationFrame polling so the test's own callbacks do not inflate production-frame counts. Compare geometry against the kit's projection/model values, require quiescence afterward, and retain a normal-motion animation control. Separately emulate a live preference change during an active tour and observe readout mutations across more than one tour interval; initial reduced-media coverage does not lock live changes.
- Test selection ARIA writes separately from animated visual readouts. Count actual MutationObserver records, cover unchanged endpoint keys, hold focus beyond the idle timer, and check blur restarts the normal tour but not reduced-motion touring.
- For blur-tour checks, observe readout mutations across the interval instead of comparing only the final text: a correctly running cyclic tour can return to the same block at the final sample.
- Verify vertical touch scrolling with a real touch swipe in a viewport shorter than the page; assert positive scrollY, a trusted touch pointercancel, and retained pan-y. A CSS string alone does not prove native gesture behavior.
- When a frozen non-sandbox candidate inherits unconditional Linux `--no-sandbox`, preserve the committed source and use an external headless-only launcher that strips sandbox-disable flags and requires an owned scratch profile. Disclose this containment shim: those suite results do not qualify that candidate's default launch policy. Separately run the sandbox candidate through the unwrapped browser boundary.
- For headless `--dump-dom chrome://sandbox`, require the actual sandbox-status table and evaluation text. New Chromium may return New Tab unless `--allow-chrome-scheme-url` is supplied; exit zero alone does not establish sandbox status. Record namespace/Seccomp rows, not only absence of a launch error.
- Run both themes at desktop and mobile widths, normal and reduced motion, save AX slider nodes and inspect every screenshot including enlarged dial/joint crops. For Playwright 4× receipts, create the context with device_scale_factor=4 and capture scale=device, then verify PNG pixel dimensions against CSS crop dimensions; changing CDP metrics after context creation can still produce a 1× screenshot. A visible native auto outline is not proof of the exact documented token/offset styling; report the distinction.
- Pin normal-motion controls explicitly: omitting the driver's --reduced flag inherits the host preference, so a real reduced-motion fix can expose old animation assertions that only passed because the old reduced path still animated. If driver changes belong to another owner, use a narrowly scoped test-only media-query fixture and disclose it; retain separate real CDP media-emulation receipts. Await the observed blur callback before measuring no-tour quiescence rather than assuming a 3.6-second browser timer fires before a 4.2-second driver deadline.
- Read the current workflow's external regression dependencies and set `NODE_PATH` to their verified scratch installation before the full suite. Node's built-in-only build scripts do not imply that the React regression tests are dependency-free; missing TypeScript/esbuild imports are setup failures, not behavioral RED or partial full-suite qualification. Keep failed setup logs and rerun the unchanged complete suite with the workflow versions.
- Match CI's Node major for byte-identity builds, but do not assume that resolves host differences. Linux Node 22 and Node 26 can both differ from committed macOS-generated Raptor payloads and turning-stress data. Preserve each drift receipt, rebuild the untouched pinned base with the same runtime, and compare baseline-generated versus candidate-generated bytes separately from committed-page identity. Never commit unrelated drift or claim byte identity from visual equivalence; let actual hosted macOS CI establish its own committed-page gate.
- Hash every generated HTML before and after all 14 official example commands; compare unrelated pages to pinned upstream bytes too. The React examples have no standalone build script. Bind suite, build and native receipts to the exact committed head.
- For gallery submission preservation, test the target `figure/<id>` ref independently of the current checkout: commit customized figure bytes there, switch to `main`, invoke the real CLI without force, and assert unchanged target SHA, current branch/HEAD, sentinel bytes and empty disposable fork refs. Pair with explicit-force replacement and an existing target ref identical to gallery main. A working-tree-only diff misses this destructive `switch -C` path; retain real local Git transitions while intercepting only GitHub calls and network destinations. Test empty `build: []` and `pages: {}` independently through the CLI: type/truthiness checks alone accept incomplete manifests and can commit/push them despite a metadata-refusal claim. Keep nonempty validation narrow rather than importing the gallery's full schema into the publisher.
- Publish only to the authorized fork using explicit SHA refspecs, --atomic and --no-follow-tags without force. Read back branch SHAs, PR base/head/diff/body, actual check runs and jobs. An upstream publication hold stays held; a proposed factory registry is not deployed registration.
