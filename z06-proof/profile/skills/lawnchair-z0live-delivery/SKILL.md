# Lawnchair z0live delivery

## When to Use

Use for resuming, validating or publishing the native Lawnchair z0live/Ripple integration.

## Workflow

- Confirm checkout/branch and preserve dirty work. Known checkout `/mnt/zer0models/lawnchair-z0live`, branch `feat/z0live-realtime`, base `experiment/hyprspaces-phone-harness`, fork `kvnloo/lawnchair`.
- Coordinate with the separately owned backend only through its `docs/API.md` and service `127.0.0.1:8791`; do not rewrite/restart it to fit Android fixtures.
- `/v1/inbox` is `{messages,after,has_more}`, not an array. Preserve pagination, validate monotonic cursor/IDs, persist handled identities. `action:null` means speech only; reject/report undeclared phone actions.
- Builtins use `/v1/tools/{tell_hermes,get_context,summarize}`, parsed argument objects and broker-generated session IDs. No generic `/v1/tools` endpoint. Events are bare batches with closed event vocabulary, Unix seconds and stable UUID dedupe identities; explicitly end `/v1/sessions/ID/end` after bounded flushing.
- Wait for response.done/user silence/pending tools before continuation. Never use Android TextToSpeech for z0live inbox replies. Deliver current-human-session results through the existing Realtime voice as a `role: system` conversation item framed by kind (lookup, run, progress, message, from the inbox `source` prefix), asking the model to answer the user's question in its own words in 1–3 spoken sentences, never verbatim, then `response.create` with only `tool_choice: none`. Never put `instructions` on that response: a response-level override replaces the session persona and conversation context, and an instruction like "faithfully relay … beginning 'Hermes says'" makes the model read the raw broker text aloud, which the owner hears as TTS reading the inbox. Assert the interpret-not-read contract in `Z0LiveInboxDeliveryTest`. Keep the mic available for barge-in unless it is manually muted or focus is lost. Never let voice activity alone interrupt or reply. Plain server VAD fires on footsteps, doors and room noise, which cuts the model off mid-sentence and then answers empty turns ("I'm here whenever you're ready" on repeat). So configure `semantic_vad` with far-field `noise_reduction`, and set `interrupt_response:false, create_response:false`.

  `Z0LiveSpeechGate` then interrupts (response.cancel plus WebRTC `output_audio_buffer.clear`, which truncates unheard server audio) only when the live transcription delta contains real words: at least 2 Latin letters, and not a known noise hallucination such as "Thank you" or a lone grunt in another script. It sends `response.create` only for a real final transcript, through `Z0LiveTurnState.takeUserReply()`, which also absorbs any pending tool continuation so one turn gives one response. It deletes noise-only items with `conversation.item.delete`. Assert this in `Z0LiveSpeechGateTest`, which is wired into `test-z0live-protocol.sh`. Never mint an opening summary on session start. End the broker session even when an in-flight mint finishes after local hangup.
- Scope encrypted monotonic inbox watermarks to backend + paired device, snapshot latest id at each explicit connection to skip history, and claim live reply identity before speech. Session End must record interrupted playback before invalidating callbacks; QUEUE_FLUSH is not an inbox acknowledgement. Inactive/old-session replies are silent notifications only, with best-effort OS scheduling explicitly disclosed. Never create empty diagnostic sessions that repeatedly enqueue spoken summaries.
- Reserve the real phone before an automated batch and stop immediately if the owner/parent revokes access. A stop forbids every further ADB call, install, debug turn and cleanup until explicitly re-enabled; do not keep retrying voice startup or ask the owner to wait through a replay backlog. Mark current-repair device acceptance NOT RUN rather than promoting earlier diagnostic turns.
- Implement optional in-app control in an isolated accessibility service instead of widening Lawnchair's existing navigation service. Keep schemas declared while disabled and return `permission_required` with one-time Settings guidance. Require owner-only Android enablement plus in-memory per-session consent; bind exact selectors to fresh package/window/snapshot identity, reject ambiguity/password/sensitive targets, and report Android acceptance as `dispatched, verified:false`, never UI-effect proof.
- For silent async acceptance, append the function output but do not schedule `response.create` when `speech:"silent"`; retain pending synchronous/parallel continuations. Preserve inbox `source` from the real server so layered result/partial messages keep requested-work framing.
- Diagnose owner voice complaints from the recorded sessions before touching code. Read `/mnt/zer0models/workspace/zer0/data/z0live/sessions/<id>.jsonl` (types `user_transcript`, `assistant_transcript`, `tool_call`, `tool_result`, `app_state`), plus `broker.db` tables `inbox` (`say`, `source`) and `work_lookups`. Empty `user_transcript` events between assistant lines mean noise turns. A model that denies having a capability usually means the installed APK lacks that tool, not a prompt problem.
- A feature is not on the owner's phone until its APK is installed. A locally built APK that was never installed (for example because ADB failed) leaves the phone on the old build, and the model will honestly say it can't do the thing. Merge the feature into `feat/z0live-realtime` so CI publishes it, then hand the owner the release APK. KDE Connect works when ADB is unavailable. Say which build the phone runs before claiming a fix.
- gpt-realtime only transcribes committed audio, so a word gate alone makes barge-in wait for the whole sentence (4.7 s measured). `Z0LiveSpeechGate` therefore commits the first `PROBE_MS`=250 ms of speech heard over the assistant (`input_audio_buffer.commit`) so words interrupt in ~0.6 s; starts the reply at the first two-word delta after speech_stopped (`earlyReply`); and allows one reply per utterance even when the probe split it into two items. Semantic VAD eagerness high (auto ends turns ~0.2-0.3 s later). The gate still costs ~450 ms on direct turns vs server auto-reply.
- Bidi duck (`Z0LiveBidiBarge`): duck on real words while the assistant turn is open or ended < `TAIL_MS` ago (buffered tail), un-duck on the next turn OR on new output after the interrupted turn ended, and duck at most once per owner turn. Full duplex answers quick follow-ups before `turn.created` and transcripts arrive late; without the last two rules rapid follow-up answers were muted (3/5 in eval).
- Transport setting `Z0LiveTransport` (Settings > z0live > Voice connection): Auto (default; bidi when offered, realtime fallback on Live setup failure), Realtime, Live (no silent fallback).
- Frameless Bidi calls (branch `feat/z0live-bidi`): the phone sends no gpt-realtime control messages (no VAD `session.update`, `response.*`, `output_audio_buffer.clear`), never injects inbox `say`, executes broker-queued inbox actions (poll 600 ms) and falls back to a realtime mint with the same SDP offer if `/v1/live/calls` fails. `Z0LiveBidiBarge` mutes playback on real transcript words; Bidi only emits interrupting transcripts when it yields (~1.5 s), so do not expect client barge to beat the model without energy ducking, which the owner rejects. `requiredText` rejects control chars, so validate SDP (CRLF) separately.

Run formatting, variant unit task, full Android lint and assemble; explicitly disclose a NO-SOURCE unit task and use actual-client JVM scripts for behavioral evidence. Verify CI with gh, read prerelease assets, download APK/metadata/checksum, compare bytes/hash, inspect versionName/package with SDK aapt and signature with apksigner. A planned URL or Actions artifact alone is not release proof.
- QR pairing: desktop `z0live pair NAME --qr` uses qrencode ANSIUTF8; `--qr-png PATH` creates a new 0600 PNG, refuses overwrites/symlinks, passes links through stdin (not argv), suppresses plaintext output and revokes the new verifier if rendering fails. Test real QR roundtrips with qrencode + zbarimg; isolated Store fixtures must never touch deployment credentials.
- Android uses `play-services-code-scanner:16.1.0`, QR-only `GmsBarcodeScanning`, and manifest `com.google.mlkit.vision.DEPENDENCIES=barcode_ui`; no CAMERA permission. Do not scope scan Task listeners to the Activity's onStop lifecycle: scanner UI backgrounds it and can remove listeners before results. Use main-thread callbacks with destruction guards. QR/VIEW/paste share PendingPairing -> parse -> resumed confirmation -> existing encrypted save; keep pending credentials process-local and single-use, not on a 30-second background timer. Process death requires re-scan/reopen.
- Adding the Google scanner triggers Licensee's unknown-terms gate. Allow only the exact scanner/transitive coordinates reported by the gate (Google ML Kit/Android terms), not a global unknown-license bypass; rerun assemble and lint. FLAG_SECURE may prevent handset screenshot proof; do not weaken credential protection just to obtain a screenshot.
- Ripple is a React/React Native ephemeral intent component (`@kvnloo/ripple`, closed/unmerged PR #1 branch cursor/intent-surface-e30f), formerly IntentSurface/aodl-ui, not a verified deployed URL. Distinguish configurable HTTPS host from native Ripple; widgets launch rather than embed WebViews.
- Consume the validated `builtin_tools` name array returned at session mint and scope dispatch to that broker session; do not freeze work-tool names in the APK. For old brokers retain original helpers plus work_search/ask_hermes/start_task/task_status/what_changed as fallback. Reject invalid/duplicate/path-like catalog names before requests; allow ask_hermes's bounded 25-second wait with a longer bounded HTTP deadline.
- Script real-phone batches with shell-quoted device commands: adb concatenates argv after `shell`, so subprocess argv alone does not preserve a multi-word `--es` value. Require the exact full injected transcript plus provider/tool/effect receipts. Distinguish accepted debug requests from actually injected idle turns, and stop if the owner ends/replaces the tracked session. Never terminate a replacement owner session.
- Treat microphone mute as a turn-state transition: disabling a track sends no silence, so clear pending input and reset/ignore muted VAD speech events. Otherwise inbox/tool readiness can deadlock forever after muting mid-utterance. Closing pooled TLS sockets may write close-notify packets: evict OkHttp pools off Android's main thread.
- No-history pairing trampolines must `finish()` after starting their target: `finishAndRemoveTask()` on a root trampoline can delete the newly launched controls in the same task affinity. Preserve secure window/input scrubbing rather than loosening export rules.
- Compare certificate digest VALUES, not whole apksigner lines (V2 and V3 prefixes differ). Gradle's cached signer may be stale even when ~/.android/debug.keystore matches the phone; explicitly sign an owned output with the existing stable debug key, assert its digest against a pulled installed APK, then install -r. Never uninstall to bypass a mismatch.
- Track in-flight broker tool calls as interruptible work even after Realtime response.done has released the audible floor. A quiet user barge can precede HTTP admission: advance the cancellation generation, suppress the late turn, and cancel only its exact turn ID; remove failed/no-turn calls so they cannot leave phantom work. Test this separately from audible response races.
- For the multi-agent broker, map actual user/response/output-buffer floor transitions, preserve held floor in 20-second active-session heartbeats, drop interrupted turn speech before drain, and associate supplied response.done usage only with broker-returned session-owned turns. Keep telemetry/control requests off the serialized long-wait tool executor.
- For gesture Standby, promote the microphone FGS while visible before networking; retain foreground admission across idle/session/idle, construct no WebRTC/AudioRecord while idle, and expose OFF. Gate the documented assistant exception on active VoiceInteractionService plus role, microphone permission and prior explicit opt-in; role alone is insufficient. Preserve API26 launchers by guarding RoleManager calls at SDK29 before accessing that class or methods. Treat delayed first capture on One UI as unverified until handset evidence. A resumed-only worker may report ready=false after prior opt-in but must never claim commands or start audio. Lawnchair Standby dozes and stops heartbeating presence, so with the owner's adb opt-in (`Z0LIVE_GESTURE_ADB=1` in `data/z0live/service.env`) the broker falls back to `adb_launch` when no surface is fresh, rather than dropping the gesture. It still requires exactly one tailnet adb device, and never guesses among several. The fallback relaunches `Z0LiveActivity` with `autostart`, which toggles a live call, so it may only START a call. Debounce it to one dispatch per ~3 s. During a call, Lawnchair must heartbeat presence/ready so gestures route as queued commands. If every `gesture_events` row says `fallback: no_presence` while a call is live, presence is broken.
- The owner's gesture map is fixed; keep it exactly:
  - double tap with no call = start call;
  - double tap during a call = toggle mute;
  - triple tap = end call.
  Don't propose "triple to wake" (it collides with end). Fight false triggers with detector thresholds/burst shape and debounce. Quad/quint/rapid taps are recorded only for rejection or future gestures and must never read as double/triple.
- Detector work is driven by labelled recordings that the owner drives at his own pace. Scripted cue sequences can't match his pace, and he rejects them. The primary flow runs through a z0live call:
  - Broker tools: `ring_recording_start(kind)`, `ring_label(double|triple|none|undo)` and `ring_recording_stop`. He says "double" and then performs the gesture.
  - Each label covers everything until the next label. Baseline ("none") segments are the negatives: walking, typing, talking, rest.
  - Gesture actions are suppressed while recording, but the detector still logs its decisions for live scoring. A stop command or timeout restores normal actions.
  - Labels and raw samples share one clock via an offset stored at start.

  Record while walking, not only still. A stillness gate on taps kills walking recall, which is where he misses double taps most. Report per-class precision/recall (walking vs still), false triggers per 10 min of baseline and double↔triple confusion, old vs new. Validate on the owner's real false positives from the strap log, not only synthetic windows.
- "Pass this along / tell Hermes" in voice means relay a message into the owner's main Hermes session (via its gateway), never phone screen control. The voice agent needs a relay tool that reads back the exact text and target, plus grounding that "Hermes" is his agent, not mythology. Check the `z0live-voice` session's tool_results for what was actually sent before claiming a relay happened.
- "Did my message go through / what did Hermes say" must be answered from a backend tool, never from phone screen control. Give the voice agent a deterministic `relay_status` tool that returns, from `live_delegations`/`jobs` plus a read-only check of the target Hermes state.db:
  - the exact text sent;
  - the target session id and its current title;
  - the delivery state;
  - any reply since.

  Without it, the model guesses and contradicts itself across calls. It infers "crashed" from a stale session title. It falls back to `phone_do`, which hits `blocked_app` on Lawnchair and can land an unrequested real tap elsewhere. The broker must refuse `phone_do`/`phone_act` unless the current utterance asks to operate the phone. When the owner asks whether a relay arrived, verify it in this Hermes session's history and say which messages landed.
- Rebasing Standby onto newer realtime/bidi: keep per-session objects non-final and rebuild them in `beginSession()` (broker session via a lambda that reads the current `telemetry` field, not `telemetry::offer` bound at construction; speechGate, bargeProbe, bidi flag/caption/barge). Shut `network` and `control` executors only in the non-Standby branch of `settled()`. This repo sets `rebase.updateRefs`, so a rebase on a new branch also moves the old PR branch locally. Reset it with `git branch -f` before pushing anything.

- "Double tap doesn't do anything": trace the hop where gestures die before touching the detector. Check each in order:
  1. NOOP strap log `tap burst ... - DOUBLE_TAP` lines.
  2. The `z0live.service` journal shows `POST /v1/gesture`.
  3. Read-only `broker.db` under `Z0LIVE_DATA` (read it from `/proc/<pid>/environ`): `gesture_events.result`. `no_active_target` means no surface heartbeated within 15 s (`gesture_presence.seen`), so the fix is routing, not detection.
  4. `gesture capture ended` shows the arm window expired. Setup-screen arming lasts at most 300 s and disarms on link loss.
