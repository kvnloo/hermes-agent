# hermes-contribution-workflows

Use when reviewing, testing or contributing to Hermes or its Tern plugin, including upstream salvage, fork drafts, promotion queues and plugin command delivery.

## Rules

1. Gate every upstream action and fork draft with the existing F3 implementation in `/mnt/zer0models/worktrees/oss-factory-f3-contrib/factory/upstream_contrib.py`, locating its accepted replacement after integration. Run `classify --evidence ev.json` then `decide --facts facts.json`. Proceed only on exit 0 ALLOW, follow JSON next on exit 3, and notify the owner without acting on exit 4 ASK_OWNER. Honor owner stop and keep research waves write-free.
2. Re-read the exact current target head and real labels before acting. Classify confidence from reproduced red/green or source file:line, complexity from changed scope including security/auth/data, and priority as the most severe reported or labelled value. Reserve autonomous actions for C12's P2 high-confidence low/medium-complexity, P2 medium-confidence low-complexity or P1 high-confidence low-complexity cases; discuss the rest with the owner.
3. Count authored open upstream PRs fresh against the cap of three. Route new work to fork drafts and the canonical promotion queue when capped. Search subsystem identifiers for existing carriers, hand them a credited test/counterexample or one cherry-pickable salvage commit, and preserve original author ownership. Keep speculative frameworks out of contributions; pin one invariant at the real boundary.
4. Respect one comment per thread per wave, no mentions and no re-reporting fixed findings. Apply the continuous planner's stronger limits: no previously commented thread, one action per author/24h and three/week, maintainer threads two/day, subsystem three/day, no three same-kind sends, upstream at most 60% of ten sends and no targets briefed by other phone runs in three days. Keep 01-08 CT downstream-only and retain salvage links as drafts until daytime.
5. Choose live maintainer work dynamically through `hermes-upstream-01/planner.py` and inspect planner.jsonl before tuning. Inspect existing send/harvest services, STOP files, run state and tagged replies before adding work. Treat DeepSeek GAP outputs as unverified leads to recheck at current head; preserve clipboard exceptions and owner foreground safeguards. Use direct ghcache reads only under the recorded core-budget gate.
6. Prove code with base red, head green and reverted-source red where possible. For test-only pins, run one exact mutant per claimed behavior. Run neighbours and reproduce failures on unchanged base before attributing them. Keep source and negative-control commands inside the target checkout with `PYTHONPATH=<worktree>`. Label unrun and borrowed reported numbers explicitly.
7. Follow `references/fork-draft-recipe.md` for fork-only cards. Assign disjoint cards/paths and record the base SHA plus applicable AGENTS.md rules. Build the test environment once per base under flock/nice/timeout. Use `HERMES_TEST_FILE_RETRIES=0 timeout 400 nice -n 10 scripts/run_tests.sh <files>` with the selected HERMES_PYTHON, and inspect Summary/FAILED/error output rather than a pipeline status alone.
8. Protect the real Hermes home during integration tests. Run `tests/acp_adapter` (and any home-guard path) in an owned `git clone --no-hardlinks` outside that home with its own .git, never a linked worktree of the live install. A worktree's .git resolves into the real home, so `home_io_guard` fails tests as "file I/O against the REAL hermes home" and runs die early. A clone copies refs at clone time, so after committing re-fetch the branch from the work worktree (`git fetch <wt> <branch> && git reset --hard FETCH_HEAD`) and check the HEAD SHA before trusting a run. PM's bundled store Python refuses to start without a committed environment ("no dependency environment is committed"), so run pytest from a throwaway venv built from it (`<store-python> -m venv --without-pip ~/.cache/hermes-test-venv`), inherit PYTHONPATH plus a pytest/pytest-asyncio `--target` dir, and set HOME to a temp dir. Run the base and the candidate one after the other with `--junitxml`, each writing its own output files; never start a second batch over files a running batch still writes. `test_gateway_native_sessions.py` dominates suite time, so give it its own timeout. If whole-suite runs die from SIGTERM (rc=143) on a memory-tight host, run each test file as its own process with its own junit file. Then compare per test: a regression is base-pass but candidate-fail or error. Report identical failures on both sides as inherited. Before publishing, check that the base is on GitHub (`gh api repos/<fork>/commits/<sha>`). If the local install sits on unpushed commits, cherry-pick the fix onto `origin/main`, rerun its tests, and publish with the tree-verifying API publisher when `git push` fails on index-pack.
8a. For bootstrap/home-guard paths, keep using the owned clone described in 8. Set isolated HERMES_HOME, HOME and bundled-plugin inputs for real discovery. Reproduce neighbour failures in an unchanged control of the same checkout kind; correct dishonest fixtures while retaining their assertions.
9. Before a fork draft, inspect compare/main...branch ahead count and paths. Reconcile a strict-ancestor fork main only through an authorized plain fast-forward, preserving concurrent work. Use `scripts/gh_push_commit.py <worktree> kvnloo/hermes-agent <branch>` for partial-clone publication and retain its returned exact SHA; keep unavailable-blob porting and patch-only qualification explicit rather than claiming tests on an untested new base.
10. For accepted fork work, use the owner's author identity, a conventional why-focused message and `Refs kvnloo/hermes-agent#N`. Open a clearly fork-only draft with exact tested/base SHAs, red/green commands/counts, negative control, authors and local/CI limits. Close the loop with a card proof, promotion-queue row and link_pull_request. Keep upstream promotion subject to a fresh slot and C12 decision.
11. Audit phone results' `GATE {json}` with the real decision implementation and actual target labels. Notify ASK with the concrete owner decision, stop on unauthorized posted actions and keep pre-gate results marked legacy_no_gate. Treat Bend PASS as evidence of the emitted table, not proof that input facts are correct. Regenerate proofs and law counts after law changes.
12. Follow `references/plugin-slash-commands.md` for command changes. Check built-in collisions, declare only needed handler kwargs and return text on ACP/local/messaging surfaces. Advertise plugin commands through commands.catalog and available_commands_update before routing slash.exec. Verify unit discovery, real isolated ACP, profile-only install diff and actual invoke_plugin_command paths independently. Provide status/stop and verify recorded PIDs before stopping spawned tools.
13. Keep external plugin backends in dedicated data roots with their native server and lexical path contract. Sanitize inherited omp/XDG/profile routing variables, verify ~/.omp preservation and use the same lexical sessions root in trace URLs. Keep secrets outside PR bodies/commands and use fresh `--body-file` files when command-text guards would interpret quoted examples as execution.
14. Triage older fork CI read-only from actual logs and compare metadata as STALE, REAL or INFRA. Preserve missing-runner versus product-failure distinctions and ask before closing PRs. Report exact heads, test paths/commands/results, overlap, credits and remaining gates. Make salvage easy to cherry-pick and keep gateway/profile/session/tab ownership with its creator until explicit user action.
