# ephemeral-ui-kit

Use when building ephemeral-ui cards, sections, playlists, inline boards, or native host integrations.

## Rules

1. Recover the actual private kit checkout, source revision, brief and existing integration owners before editing. Keep plain ES modules, KINDS registration and card.v0.json aligned; isolate new kinds/styles and preserve sibling hunks.
2. Inventory the source app's complete routes, controls, serializers and action consumers. Cover real jobs with primitives and route composites; correct source-proven misassignments in both generators and generated catalogs.
3. Accept unchanged source API JSON plus opts; preserve units, nulls, totals, freshness and coverage. Validate before atomic replacement, copy accepted input and invalidate stale selections/acknowledgments.
4. Return bounded agent context through the actual consumer contract: top-level session/range/label, string-array type:id ids and typed entities. Resolve selections through the host's real return channel.
5. Make every control produce a visible outcome. Use loop.js intents, undo, explanations and keyboard paths; reserve holds for irreversible/external actions and confirm execution only from real consumer receipts.
6. Use synthetic public data by default. Obtain explicit owner approval before publishing any real operational measurements, even sanitized ones; keep raw captures private and run leak checks before and after publication. See references/trace-cards.md.
7. Mark authored examples as authored-example; validate bounded typed graphs and atomic edits without executing imported JSON. Label diagram arrows as intent rather than verified integration. See references/infrastructure-examples.md.
8. Gate the exact candidate with dead-control probes, emitted-ID journeys, boot/error checks, overflow and inspected light/dark desktop/phone screenshots. Run full browser fidelity on MBP; label light-gate skips and unrun gates. See references/browser-gates.md.
9. Separate one-off HTML boards, native catalog components and the kit site. Deliver the requested interactive artifact in the actual client; verify transport, renderer revision and Android behavior independently. See references/inline-boards.md and references/native-host-integration.md.
10. Preserve non-linear workflow graphs, typed handoffs, evidence/diff/approve-edit-why checkpoints and prompt/stack personalization. Keep review requests separate from approval or execution authority.
11. Publish only within the current request and execution ownership. Default to GitHub Pages with private source; mirror Vercel only when explicitly requested. Build from live gh-pages when HEAD differs, apply only owned hunks and gate that exact tree.
12. Read back every shipped file against the candidate, probe live boot again before reporting and open every supplied deep link. Deliver feature-state card captures, honest pass/fail counts and checked live links; normalize playlist links against the live catalog. See references/social-playlists.md and references/launch-posts.md.
