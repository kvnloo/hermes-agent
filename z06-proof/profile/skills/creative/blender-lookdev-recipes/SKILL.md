# Blender look-development recipes

Research the physical cause, prove it with a controlled coupon, and transfer only the verified mechanism into an authorized scene. These are mechanism-qualified recipes, not universally owner-approved looks. The existing executed coupons use Blender 5.2.2; requalify another API, scale, fixture or display transform. Linux is the qualified headless execution environment; no cross-platform runtime certification is claimed.

## When to Use

- Diagnose HDR glow, glass, wet/dew, bioluminescence, coat, painterly detail, moss/ivy, bloom or fixed-view projection.
- Do not use a shader to hide a form, silhouette, coverage, mapping or art-direction failure.

## Prerequisites

Read the target native crop, current fixture and scoped OWNER-PREFERENCES. Resolve exact executable/API, shared GPU ownership and authorized output paths. Distinguish neutral mechanism controls from the production lighting/view fixture; numeric values do not transfer automatically.

## How to Run

Use `read_file` for the relevant recipe, `web_extract` for current primary docs, `terminal` with explicit workdir for headless Blender (`--python-exit-code 1`), and `vision_analyze` for actual candidate/control crops. Discover environment paths rather than copying historical host commands. Retain unique filenames and saved-scene receipts.

## Procedure

1. Name one visible defect and classify FORM/MATERIAL/LIGHT/ALBEDO/MAPPING/DISPLAY. Preflight ray-hit receivers, effective material slots, live shader links, normals/UV/tangents, light links, exposure/view/glare; a shader may exist without affecting the surface.
2. Before full assets, provide native target crop, structural style reading, two distinct causal form hypotheses, negative example and small coupon. Owner approves the language before scattering or detail growth. Keep the agreed objective fixed.
3. Retrieve the relevant recipe and current API documentation. Record source/rights, predicted cue and falsifier. Do not “fix” an API error by deleting the intended effect.
4. Freeze scale, seed, camera, lighting, view and exposure within a one-variable candidate/control. Save code, packed blend, actual render/settings and linear HDR when the claim requires values above display white. Inspect the result; geometry counts are not appearance evidence.
5. Record API/render, mechanism, family/style, integrated and owner status separately. Publish the mechanism with applicability matrix and known negative appearance, not a universal parameter preset.
6. Apply to an authorized frozen-fixture copy, integrate exposure/light baseline first and use one glare owner. Reapply twice, save/reopen, measure protected deltas, inspect full frame, native interfaces and final density. If two trials fail the same named defect, block dispatch and ask for a different owner-approved hypothesis; do not call the project finished.
7. Compile successful work into an executable appearance packet: typed controls/ranges/units, response atlas, positive/negative examples, licenses, fixture hashes and unseen transfer. Revisit after a gap on new geometry/light. Studied, technical, mechanism, transfer and owner approval are separate states.

## Pitfalls

- Inspect installed compositor RNA: the qualified 5.2 path uses `scene.compositing_node_group` and Glare sockets. Old tutorial attributes are not current API proof.
- View Exposure and a pre-Glare Exposure node affect different stages. Preserve the approved view transform; a cookbook AgX fixture does not certify another transform.
- A wet coat needs a reflected source; a base normal must not automatically shred the coat normal. Thin Principled Coat is not a thick epoxy meniscus.
- Treat MNEE as limited refractive-caustic support; check caster/receiver/light flags. A bright disk is not glass depth.
- Large hair offsets can explode small grooms. Approve real leafy morphology before population; hair is not a cure for a wrong envelope.
- Use authored depth for relief, not assumed portrait luminance. Separate continuous form faceting from localized weathering; stamps can look pasted and triangle fans remain a rejection risk. Preserve artwork registration and inspect actual undercuts.
- Read packed pixels with `foreach_get` for bounded audits; preserve source graphs even at zero users. Realized-state checks and visible benefit are distinct.

## Verification

Require an inspected actual render/control, saved-scene readback, settings/source/image hashes, current owner scope, integration guards and honest limits. No node count, download, API smoke or mechanism PASS establishes style mastery. The [Quackles archive](references/case-studies/quackles-2026-10/original-skill.md) retains original evidence paths/constants and all older prose without making them new-project defaults.
