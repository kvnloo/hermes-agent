# Multi-scene reference-match orchestration

Parent-session procedure for bringing several themed Blender scenes (one shared asset, per-theme reference stills) to their references. The worker-side round loop lives in `blender-locked-scene-continuation`.

## 1. Recover state before asking
- Read the latest run's round table/notes (meta.md), the newest verdict's backlog, kept edits, plus any scene plan, critic and gap reports in the project's artifact store. Check session history (Hermes state.db read-only, Codex/Claude session logs) only to find where work stopped.
- Resume from the documented stall point. A stall rule that says "ask the owner" is answered when the owner says to continue.
- Quote per-item status (done / open / not rolled out) with evidence paths; sandbox-only wins that never reached shipped assets count as not shipped.
- When the user says a look was "already fixed", find that earlier round before redoing it: list the per-theme texture/analysis logs (`tex/<theme>/LOG.md` round headers, `scene-ref/*`) and match by mechanism, not by the user's remembered wording (their phrase often never appears in logs or chat history). Then check whether that round's mode/edits are in the current render path; earlier sandbox rounds are frequently absent from the preserved base scenes every later port builds on. Fastest search: `grep -rIn -iE` over the artifact store's `*.md` logs for the defect's mechanism words plus a colour word (e.g. `rim|edge|lip` with `black|white|navy`); round headers often quote the owner's complaint. Integrate it as a reusable step and blind-test it, with a REF | SHIPPED | CURRENT | +EARLIER-FIX crop sheet opened for the user.
- When the user wants that earlier look back ("just recover those"), freeze the exact built assets (textures, edits JSON, integration script, masks, original render) into a canonical store (e.g. `<artifacts>/canonical-textures/<theme>-<mode>/`) with SHA256SUMS, and point the integration at that copy. Do not rebuild or refit them: the rebuild path drifts. Acceptance = mean dE on the protected region versus the earlier render, plus the blind A/B.
- A second offset ring/crescent beside a physical eye ring is the reference photo's drawn element printed onto the shell through the projected artwork UV (the drawn element sits elsewhere than the mesh's), not mesh drift. Confirm with matched native crops across historical rounds, then stop projecting that element instead of editing geometry.

## 2. Lanes
- Exactly one worker owns the GPU lock and the scene being finished. Send it via delegate_task with the full run context: run dir, latest kept round, backlog order, gate command, judge command, hard locks (camera, canonical meshes/pose, approved blends, repo, shipped assets), one change class per round.
- Other scenes run in parallel as CPU-only critique agents: re-baseline REF | SHIPPED (full frame + crops), run the same structure gate with a per-scene UI mask, map every gap to an exact knob via a no-render `blender --background` probe, and write a ranked minimal change set plus an edits JSON proven by a CPU dry run (value readback, protected-state hashes unchanged). One output dir per scene in the artifact store.
- Put user-flagged defects at the top of the worker's backlog with concrete target coordinates (compare target vs latest crop yourself first).
- Require ledger, round table and hash manifest updates every round: long loops hit iteration caps, and a truncated worker must leave a consistent latest-kept state. Re-dispatch from latest kept, never the newest capture.
- Read-only scanning lanes (branch/history/issue/tooling audits) can run on a cheaper or user-requested model as parallel background Hermes one-shots when delegate_task children are pinned to another model: one prompt file per lane (shared preamble + lane scope + OUTPUT path), `hermes -p <profile> chat --oneshot -Q --provider <p> -m <model> [--reasoning max] -t terminal,file,web --query-file laneN.txt > laneN.log &` (e.g. openai-codex `gpt-6-luna` at max reasoning when the owner asks for luna-max scanners; smoke-test the provider/model with a one-line query first), run under one tracked background wrapper with completion notify, then synthesise the lane reports yourself. Cross-check each lane's status claims against live run ledgers before synthesis: scanners read status docs that lag the active loop, and lanes contradict each other on merge order.
- Long one-shot scans can end with `Gateway disconnected; turn outcome is unknown` and no output file. Do not resend the work: resume each by the session id printed in its log (`hermes ... chat --oneshot -Q --resume <session_id> -q "continue; write the output file now; list coverage gaps"`) so gathered context is kept. In the original brief, tell scanners to write a partial report early and refine it, so a dropped connection still leaves a file.
- A worker can end as `interrupted` (model connection drop) with no summary. Inspect its run dir and ledger first (which rounds rendered, which have result/verdict files), then re-dispatch from the latest kept round naming the exact unfinished step (e.g. "judge rN, both orders"); reuse its partial scripts if sound. Tell workers to run judges and other long steps in the foreground and wait: background processes started by a child die with it and their results never reach the parent.
- For unattended (overnight) runs, tell the worker to spend its whole budget and reserve only the last ~15 calls for the compare sheet, hashes and report; workers otherwise stop after a few rounds with allowed work left. When one returns early, re-dispatch at once with the named remaining blocker as item A. Tell lanes that must end in an integrated candidate to deliver it first and explore afterwards: a lane that explores first hits its iteration cap with coupons but no integration, and its queued renders die with it.
- On a shared, overloaded host, serialize every heavy Blender render or bake (CPU included) across all lanes behind one `flock` render lock, one Blender process per lane, border-crop coupons at low samples for exploration and full frames only for the pick. Never gate a lane on load average or free VRAM alone: other sessions keep a shared host above any threshold and the lane idles for hours; the lock queues instead. Queue small proof renders with an unbounded `flock` (no `-w`) in a tracked background process: a timed wait expires behind long renders and nothing runs. Leave other sessions' processes alone.
- After every child completion, list leftover processes for its lane dir (`ps -eo pid,ppid,etime,args | grep <lane>`) and stop render chains you own whose results are no longer needed: a finished child's queued renders keep holding the GPU lock and CPU for hours. Check what already rendered first, and note each kill in the run log: chains handed off by children later report exit 143 (SIGTERM), which should read as intentional, not as a render failure to re-queue.
- When the owner narrows scope ("just the stones, the hands print next, the robot later"), mirror it in three places: the worker's work order, the judge prompt (do not score or request out-of-scope changes), and the gate (owner-approved exclusion of the out-of-scope locked subject, validated as in section 4).
- A UV/mapping defect fix (anisotropic tiling, stretched texels) is a geometry correction, not a gated look change: authorize it while the structure gate still fails, judged only for regressions. Mottling, sheen, palette and lighting stay gated.
- Parallel COMPONENT lanes on one scene (materials, hero prop, emitters, vegetation): each lane works on a copy of one frozen fixture scene, iterates with border renders of its own region (all lanes share one GPU lock; full frame only at the end), and finishes by writing `<lane dir>/READY` (apply-script path + chosen variant). A separate integration lane polls the READY files, re-runs one fixed-order `integrate.py`, and alone owns the global settings (exposure, bloom/glare, clamp, DOF, colour management), rebalancing lane gains so lanes don't fight. When a lane comes back interrupted without READY, resume it from its files on disk on the current fixture rather than restarting.
- Meta lanes (a brief-aware tiled critic and a methods-research agent) run alongside and publish early, short outputs that running lanes are told to read at the start of each internal round: `meta/lane-gaps/<lane>.md` and a `RESEARCH.md` TL;DR within ~45 min, full report later.
- Before calling crops "native", check the capture's actual pixel size: a lane's `best-full.png` can be a 1024 preview, and upscaled crops hide exactly the fine texture under review.
- Scan breadth-first before (and between) deep element lanes: cut TARGET | CURRENT into quadrant pairs and list every concrete difference yourself (missing growth on blocks/steps/edges, regions that should be bokeh-blurred but are sharp, light-source shape, missing or placeholder objects such as flat untextured slabs, artifacts), then run a reusable whole-frame diff scan ranked by visible area x severity. Fix the cheap large ones first; weeks of single-element depth missed differences a ten-minute scan found. Put the scan's measured numbers for the lane's region (low-pass luminance median, hue, contrast, target vs CURRENT) into each element lane's work order as the acceptance direction: a lane given only a verbal hypothesis tests that hypothesis, not the gap, and can push the region further from the target.
- Drive placement from the target: camera-project masks derived from the reference (greenery, bokeh lights, wet highlights) onto the scene geometry and use them as scatter density / weight maps, publishing them early for every lane that places growth. Growth then lands exactly where the reference has it.
- Fit optics per region, not globally: measure blur, contrast and haze per region (subject, plinth, banner face, background foliage, hanging lights, architecture) and match each. A single global conclusion ("softness is all haze, keep f/64") contradicted visible bokeh; a broad radius enlarges already-soft light discs. Region-limited diffusion/defocus that leaves the subject untouched is what wins.
- Code-built scenes (one Python builder + per-area modules, .blend is an output): before fan-out, cut a clean base branch from the last committed head plus only the project-relevant uncommitted files of the old worktree (save the full `git diff` and status to the artifact store first), then smoke-render one camera from the base. Give each lane its own `git worktree` + branch and a list of owned modules; in the shared builder a lane may only add the import+call for its own module and its own cameras, and any other shared change goes to `<lane dir>/SHARED-CHANGE-REQUEST.md` for the integrator. Lanes editing the same builder otherwise produce unmergeable conflicts and silently overwrite each other's world/material settings.
- Ship lanes one render helper script (in the artifact store `bin/`) that wraps the unbounded flock, the clean environment and the copy-to-lane-dir step, so no child hand-types Blender invocations. Launch Blender from agent shells with `env -i HOME="$HOME" PATH=/usr/bin:/bin TMPDIR="$TMPDIR" <scene env vars> blender --background --python-exit-code 1 --python <builder>`: the agent's inherited PYTHONPATH shadows Blender's bundled stdlib and the script dies at startup (`No module named 'math'`) with exit 1.
- Open every quality reference with vision before putting it in a work order: a file named `*_hero.png` can be a roof-obstructed or debug frame, and lanes then either match the wrong thing or burn passes reporting the reference unusable.
- Integrating code-built lanes: merge each lane branch `--no-ff` into the base, then run a no-render build probe for cross-lane geometry clashes (world-bbox overlap of site props vs building volumes, objects inside walls) before rendering; lanes report clashes they are forbidden to fix, and another lane's module may already have removed the culprit. Land the requested shared fixes, then re-render the whole camera set as one tracked background job with completion notify: a serialized queue of many frames exceeds the foreground tool timeout.
- Delegation batches report only when every sibling finishes, and a finished sibling can no longer be steered. To act on an early finisher, read the tail of its live transcript and its lane dir directly instead of waiting for the batch.
- New additive work (site/context, a new building or room package) that would otherwise contend for the shared builder runs as LOCAL-frame modules in parallel with the integration lane: `build(parent_collection, mats) -> collection` at its own origin, declared bounds in the docstring/collection props, a standalone preview script under the same flock, no edits to shared files. Write the contract and an owner DECISIONS.md into the run dir before dispatching; the integrator alone places modules and resizes footprints when declared bounds collide with reused content.

## 2b. Port carry-over fixes to sibling scenes
- Verify shared geometry before porting: a no-render probe per scene file listing set objects with mesh-vertex hash, world location, dimensions and hide state, tabulated against one base scene. Identical rows mean a fix can be copied as is; missing/extra objects are per-scene exceptions.
- Split the finished scene's work into SHAPE/registration (block massing, decals and their registration, label layout, UV-density fixes, prop size/position, robot-layer decisions) and LOOK (lighting, stone tone, slab/glass materials, wall colour). Shape carries; look is redone per scene from that scene's reference.
- Package the carry-over as ONE reusable shared-layer script applied to every sibling, with a per-scene overlay for palette/ink. Hold back any geometry the main scene is still actively refitting, and apply it later through the same layer.
- Keep siblings in sync continuously: every time the lead scene gets an owner-approved or locked shared change, dispatch one sync agent per sibling in the same turn (CPU prep, GPU through the shared flock). The owner expects common changes to flow without asking; siblings that sit on an old port while the lead advances are a miss.
- Sync by transplanting the lead's FROZEN shared meshes (geometry + UVs + object transforms) and re-assigning each sibling's own materials to the slots; then adapt shared material structure (e.g. anti-tiling) to the sibling's own stone material. Replaying the lead's build scripts on a sibling drifts (sub-mm surface differences) and fails when the sibling's base is older. Before transplanting, check the sibling actually has the lead's base: a probe can call sets "identical" while siblings still carry older low-poly stones or miss whole blocks; restore missing prerequisites first and report them.
- Hold geometry the owner has not settled (e.g. a print placement still being fixed) out of the sync and hide its old carrier objects, so siblings show plain stone rather than a stale version.
- After porting, render each sibling hero, gate it with its own UI mask, and blind A/B it against the shipped hero before claiming progress. Show all scenes in one REF-row / SYNCED-row sheet; elements missing from every scene (e.g. a shared poster) are the top shared fix, not per-scene tuning.
- Prove each ported change is consumed and attributable: a corrected UV map is inert if the sibling's procedural shaders do not read it, and a rebuilt base can drift from the shipped hero (render a no-layer control so drift is not credited to the port). Decals registered to the reference overhang blocks that have not been refit yet, so port decal sizing together with the final block geometry. A canonical shared robot layer overwrites per-theme owner exceptions (e.g. an emissive livery); re-apply those on top.

## 3. Judge
- Default judge per round: a fresh one-shot Hermes session on the same model, launched from the worker's shell because children cannot call delegate_task:
  `hermes chat --oneshot -Q --provider anthropic -m <model> -t file,vision --query-file rounds/rNN/judge_prompt.md`
  The `vision` toolset is required (file tools cannot open PNGs); tell the judge to use region crops.
- Render and judge every candidate twice: LOOK (optics fitted to the reference) for appearance, CLEAR (no DOF/diffusion) for craft and max-zoom fidelity. Show both to judges and the owner; blur hides defects and a crisp render can mismatch the reference.
- Integrate component candidates only on an in-scene side-swapped A/B win against the current integration; an isolated-coupon win often splits once composed.
- When both judges prefer a candidate but a measured regression blocks it (e.g. glint count dropped), run a one-variable repair of exactly that regression on a copy and re-A/B. Allow at most a third trial on one line, then stop and write two directions for the owner.
- When a mechanism family keeps losing narrowly over several rounds, do a Dream-RSI step instead of another near-variant: search the trial archive for the family that produced owner-approved results in this scene (e.g. projecting the reference worked for the orb) and switch representation; list partial wins per trial and recombine them (one lane's coverage + another's volume + the owner-approved surface language). Reuse the owner-approved assets literally (same meshes and materials) when recombining; a lane that re-models an approved element in a new style loses even with better coverage.
- When projecting the reference as a low-frequency band onto geometry (frequency-split: projected tone, geometric mid band, procedural fine band), remove the reference's light sources and their glow from the projected source first: emitters bake in as smooth glowing patches that no fibre density hides. Projection fixes tone and layout, never morphology.
- When several consecutive one-variable rounds on one scene come back tie/parent from fresh side-swapped reviewers, the reviewers can no longer discriminate at that level: pause new render lanes for that scene, put the candidates and the measured region table in front of the owner, and resume from their labels. More renders against the same critics only burn host time.
- Do not stall on an expired external CLI login or ask the user to re-auth; switch to the Hermes one-shot, calibrate it on a historical kept round, and report score drift.
- Once the structure gate passes, keep a candidate only if the gate still passes and a fresh no-history judge prefers it (or ties) in a blind A/B against the parent run twice with sides swapped. Numeric gate non-regression after a pass throws away real wins on rounding/denominator noise; history-carrying judges drift upward, so report paired preference, not absolute scores. Periodically stack candidates rejected under a stricter rule onto the latest kept round and test them blind as one candidate.

## 4. Owner decisions
- Present open decisions that change what "match" means (print colour, metal finish, theme mood, byte-locked heroes, set geometry, non-physical tricks) as a short list with a recommended default.
- Check a blanket material decision against each reference before applying it everywhere: a shared "dark satin metal" finish turned a matte, paper-printed reference robot glossy. Compare matte/gloss in matched crops (specular highlights on joints and shells) and raise the conflict with a per-reference alternative instead of shipping the blanket rule.
- When answered, steer every running child immediately (gated -> ungated) and append the answer to the project's decisions log. Later revisions supersede by appending, not editing history.
- A learning/payoff loop cannot learn the owner's taste from critic verdicts alone. Capture owner verdicts as labels: a keyboard-first local rating app (TARGET | LOOK | CLEAR, stars, accept/reject/maybe, pairwise) that appends to the trial ledger, plus a one-time backfill from the owner's chat history (verbatim quote, message source pointer, mapped trial or element-level scope, mapping confidence; never invented statements). UI labels supersede backfilled ones; owner labels and standing preferences beat critics where they conflict.
- A gate blocked by locked geometry is an owner decision. Offer the concrete remedy: exclude the dilated silhouette of the separately identity-guarded locked asset from the structure statistic and re-run the known-answer must-fail/must-pass suite before use. Never relax it silently.

## 4b. Owner delegates judgment (unattended night)
- Write one decisions + queue file in the artifact store (decisions taken on the owner's behalf, what stays off-limits: pushes of private repos, deploys, locks, deletions; method; queue; a running log) and append to it on every landing.
- Take reversible agent picks only: back up the selection pointer (`CURRENT.before-<id>.json`), mark the entry "AGENT PICK, pending owner" with what changed and the evidence, and never touch the production/LATEST pointer. Regenerate the review hub through its own pipeline after every pointer change (history rediscovery before the index build; builders refuse a pointer that no longer matches the recorded history) and confirm the new round appears in the built page before reporting it. Adjudicate close calls yourself with a measured value on matched ROIs plus two fresh side-swapped blind judges; owner chat labels and standing preferences beat critics where they conflict. Promote when both judges prefer the candidate and their reservations move toward the reference, even if a lane's stricter 'both clearly better' gate held it; keep the current pick when the candidate carries a named artifact that contradicts a standing owner preference (e.g. long specular slivers when the owner asked for dot glints), and offer it on the morning page as a one-pointer alternative.
- Run a dedicated integrator lane that applies the in-scene A/B and one-variable-repair rules (section 3) and alone owns pointer updates; concurrent lanes coordinate through a pointer lock and the integration log and rebase onto the newest pick before their final A/B.
- Arm a fallback heartbeat (the `loop` skill's sentinel loop, ~45 min) so the session wakes and dispatches the next queue item even when no child reports for a long stretch.
- When the owner returns, hand over ONE morning review page built per section 6 (live from the pointer, freshness stamps, compare modes, LOOK/CLEAR): what changed in a few lines, the trajectory of the current pick, per-element candidates with verdicts, decisions taken on their behalf, and any owner decision boxed at the top with two concrete directions and their cost/risk. Load the same candidates into the rating app.

## 5. Soft or generated references
- Before using a reference numerically, measure effective resolution: mean abs loss of a Lanczos 2x down/up round trip, compared with the other references (use `uv run --with numpy --with pillow` if host python lacks numpy).
- If it is markedly softer, gate and judge at matched lower resolution (e.g. both at half size), take layout/light/colour/mood from it, take fine texture from sharper assets, and tell the judge its missing detail is not a target.
- Where its hero/robot geometry differs from the locked canonical asset, ignore and record it.

## 6. Show, don't describe
- For any visual discussion, build a static HTML review page in the artifact store and open it in the user's browser in the background: `zen-browser --new-tab file://<page>` (also for single compare sheets).
- Generate review pages with a script that reads the selection pointer (CURRENT.json) at build time, never from a hand-picked image list, and stamp every image with round, mtime and short hash; rerun it after every pointer change. The owner checks for stale images and should not have to ask.
- Order cards by priority (biggest change or open decision first). Each card compares CURRENT against any layer (reference, previous pick, start of session, CLEAR, test grades) with swipe, overlay, difference, flicker and side-by-side modes and synced pan/zoom; static REF | CURRENT crops are not enough to judge a large image against its reference. Starter: [compare page template](templates/compare-review-page.html). Verify in a headless browser that every image loads with no console errors before opening it.
- The owner wants one interactive portal, not a growing set of separate viewers: click-and-dictate feedback pinned to a region, agent replies in the thread, scoped standing rules, one-tap decision cards and replay of conversations plus renders on the timeline. Requirements and failure-mode fixes: [review portal](references/review-portal.md).
- If a user's annotated image arrives without their marks, say so plainly and ask for a flattened export (GIMP's copy omits layers) rather than guessing. When marks show edges/planes, restate your reading of each mark with coordinates and confirm before dispatching.
- Label 2D what-ifs/photomontages as mockups, not renders. State which numbers are critique-only (no render yet).

## 7. Report
- Lead with kept round, gate numbers vs thresholds, judge score, what the user-flagged items look like now; then blockers and the decisions needed. Call a blocked result blocked.
