# Linked promotion inventory reconciliation

## When to Use

Use for recursive canonical OSS issue inventories, current-head readiness checks and narrowly authorized downstream reconciliation.

- Establish worker ownership, parent-only publication surfaces, forbidden routes and parked prerequisites before collecting or writing. An old READY row never grants current publication authorization.
- Retain root/index-to-child edges, context-qualified shorthand shards, repository-rename aliases and excluded worker edges. Preserve historical work rows with no public issue/artifact separately; do not inflate them into ready operations. Bound recursive traversal at canonical downstream children and retain origin-context links as context rather than expanding the whole dependency graph.
- Save timestamped raw issue bodies, comments, PR head/base, reviews, inline threads, reviewer requests and exact-head checks. Paginate every connection and assert collected count equals totalCount; a first100 response is not complete evidence. Mark inaccessible records explicitly, preserving literal identifiers.
- Use read-only GraphQL when REST read quota is exhausted; log partial errors and retain usable data. Reduce read batch size for transient502. Never use protocol changes to retry a denied write.
- Recover original exact-commit source and receipt bytes; verify Git blob SHA1 and supplied SHA256 manifests. Label sanitized historical logs as such. Do not substitute summaries for unrecovered originals or transfer test counts between different fixes in the same repository.
- Check workflow-level conclusion and job count: action_required with zero jobs is not PASS, and empty status contexts are not success. Separate historical qualification from fresh source identity and current hosted CI.
- Measure portfolio integration independently with exact-main/exact-head `git merge-tree --write-tree --name-only`; retain raw output, merge bases and path lists. Separate documentation, tests, runtime and configuration/ownership conflicts rather than calling every non-runtime conflict docs-only.
- Quantify shared-document churn with a private Git index: restore only selected shared documents in each head to its merge-base blobs, create an unreferenced child commit and rerun merge-tree. Record synthetic trees/commits and compare conflict-bearing PRs as well as path occurrences. Treat this as a scoped counterfactual, never permission to omit required docs or a proof that one proposed workflow removes every conflict.
- Reconcile executable overlap by comparing actual mechanisms, ancestry and blob identities. A stacked child, copied source file, alternate product schema and independently complementary fix need different ownership decisions; filenames alone do not establish duplication.
- Assert historical/open/closing cohort identity and exact head equality, and distinguish full metadata screening from complete selected file inventories and narrower source review. Keep addressed downstream repairs separate from unchanged upstream defects and fresh supported-toolchain qualification.
- Keep old/head probes identical and label extraction/stubs versus real native execution. A newer toolchain parser corroboration does not become a pinned-toolchain build. Never rerun heavy/resource/hardware-held qualification simply to refresh a timestamp.
- Append only novel, useful receipts to permitted existing downstream threads: full destination/source read, live head/state guard, unchanged-destination check, then exact body and author readback. Preserve contributor credit without human mentions. Keep parent origin/dashboard writes separate.
- Emit per-item/per-repo JSON plus readable ledger, historical-row inventory, excluded edges, exact coverage counts and ranked operations with eligible_now explicit. Zero prepared origin payloads is a valid outcome when gates remain; distinguish this from claiming no future work can ever qualify.
