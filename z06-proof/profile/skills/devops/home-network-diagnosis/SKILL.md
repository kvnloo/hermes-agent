# home-network-diagnosis

Use when diagnosing home Wi-Fi, internet, router topology, firmware support or printer/shared-device discovery, or planning an authorized recoverable-router change.

## Rules

1. Recover prior omp sessions and receipts, then re-observe the current topology. Diagnose read-only until the owner approves a change. Explain affected clients, expected interruption and rollback before channels, security, routes, bridge mode, reboots or firmware writes. Keep research-only work free of device contact and reserve physical/account steps for the owner.
2. Extend `/mnt/zer0models/workspace/zer0/data/operations/home-network/REPORT.md` with sourced findings, explicit hypotheses, an ordered permanent-fix plan and verification windows. Continue independent permitted work while an owner gate is blocked, and obtain billing approval before analysis delegation.
3. Check `ip -br addr`, `ip route`, `nmcli device status` and `resolvectl status` before trusting scans. Prove the chosen LAN interface reaches the gateway; bind read-only probes with `curl --interface wlan0` or `ping -I wlan0` around a dead lower-metric NIC. Correlate host CRC/flap counters, router link events, station association, DNS and endpoint traffic before assigning cause.
4. Use BWS credentials inside secret-preserving processes and stdin, keeping values out of argv, output and captures. Read NETGEAR clients, port/WAN status, SSIDs/security, guest settings and firmware through the mapped pages in `references/netgear-rax200.md`. Read effective JS/hidden-field or nvram state. Extract Debug_log.zip under `umask 077` and delete it afterward because it contains passwords.
5. Treat RAX200 authenticated UDP Telnet enable as a state-changing diagnostic action, not a read-only GET. Use the LAN MAC and an in-memory genhash path that prints no password/hash. Identify it as unencrypted root Telnet. Coordinate closure with dependent owner workflows, stop owned clients/listener and verify TCP 23 closed plus web/WAN health. Treat surviving authenticated unlock as a remaining risk requiring approved credential rotation and persistence/exposure checks.
6. Separate Wi-Fi association failures, WAN flaps, RF overlap, double NAT and application failures. Use bounded `tv_watch.py --duration 600` observations with the correct MAC/IP/interface, and ask whether the TV entered standby before interpreting PS/ping changes. Treat deauth indications, retry counters and intermediate ICMP loss as observations rather than a proven initiator or cable fault.
7. Measure simultaneous wired/wireless baselines and change one approved factor at a time. Prefer Ethernet or a separate compatible TV SSID over weakening all clients. Persist winning settings through supported configuration, verify throughput/loss/stability and approved-reboot persistence, and monitor intermittent WAN events for 24-48 hours. Follow `references/xfinity-gateway.md` for Admin Tool and Bridge Mode, with owner-entered passwords and the outage explained.
8. For missing printers/cast devices, follow `references/printer-discovery.md`: verify host path, mDNS, router guest membership, service ports and phone print services. Preserve isolation until the owner chooses a fix. Explain that guest-uplink IoT double NAT blocks main-LAN discovery; reachable island printers require `iot-wired`, narrow forwards and client add-by-IP. Keep vendor firmware/toner claims contested where evidence conflicts.
9. Before firmware support claims, identify exact board/revision/chips, all-target OpenWrt profiles and current WIP/source evidence. Prefer leanrea-style cheap inventories and mark seen/inferred/unknown. Keep extracted firmware unprivileged, traversal-safe and free of host secrets; execute no extracted binaries. Use `references/openwrt-feature-mapping.md` for release/architecture/kernel-ABI package inventories and feature traffic-path requirements.
10. Use `references/spare-router-openwrt.md` only on a recoverable spare. Cross-check ToH, forum reports and patch revisions, give complete LED/beep/fallback steps, verify image checksums and recovery tools before writing. Identify USB serial/model with `lsblk -dno NAME,SIZE,TRAN,MODEL,SERIAL,RM`, list existing content and obtain erase approval before `scripts/write_usb_image.sh`. Obtain separate explicit authority for persistent eMMC writes.
11. Before recabling the CachyOS MBP, save route/DNS settings and obtain authority to make its wired profile never-default through its desktop session. Verify Wi-Fi internet/Tailscale before cable movement and avoid overlapping lab/home subnets. Stop after one sudo failure and inspect auth logs. Verify direct/link-local recovery and any alternate management path end to end before removing cables or replacing a trusted host key.
12. Apply every authorized OpenWrt configuration through a saved rollback profile using `scripts/openwrt_profile_switch.sh`, `/usr/sbin/onhub-profile apply <name> 300`, verification and `confirm`. Save factory first and use private `uci -c <dir> -P /tmp/uci-<name>` staging. Extend transactions to every affected file/service, arm recovery before network reload and rehearse failures on isolated hardware. Keep secrets on stdin and recovery access real rather than inferred from a displayed address.
13. Keep the production gateway untouched during parallel pilots. Use distinct SSIDs for routed subnets. Reject untrusted private destinations through pilot WAN and attach VLAN-unaware OEM APs only to Trusted access ports. Treat router/AP choice, recabling and final gateway cutover as owner decisions. Verify discovery/casting after multicast or Avahi changes, matching nodbus configuration to its build. Follow `references/onhub-radio-evidence.md` for calibration, radio/chain, regulatory, CT/mesh and DFS claims.
14. For an authorized ET8 emergency shutdown, use `~/onhub/et8/ssh`, verify productid RT-AXE95Q, disable all primary/guest radios and WPS, and read back saved plus runtime state in a separate SSH call. Keep disabled Wi-Fi off until explicit approval. Verify actual authentication on every BSS before connecting an AP to Trusted. Treat saved NVRAM, cached scans and local mock tests separately from reboot, fresh RF and physical traffic acceptance.
