# dash-living-night-proof

Use when changing or qualifying Dash phone UI presentation under the Living Night design contract.

## Rules

1. Read the assigned AGENTS.md, CONTRIBUTING.md, docs/design/zeros-night.md, garden reference PNGs and orb catalog. Preserve navigation and product information architecture during restyles; zeros-night supersedes old black/system-font guidance only. Inspect existing zerOS/AODL components and show candidate directions before porting.
2. Use docs/design/language.md vocabulary consistently. Keep bots limited to deployed messaging identities in collapsible host sections with dense 44-52 px rows. Show useful chat summaries, active repositories and subagent counts; source rich transcripts through Hermes tui_gateway JSON-RPC via z0bridge rather than text-only SessionDB history.
3. Base glyphs on AODL intent contracts, typed gaps, human gates and verifier/observation edges. Render undeclared fields as unspecified and use only AODL topology IDs. Build several interactive directions with fixture/live pickers when uncertain; verify comprehension from a 390 px screenshot. Put reusable cross-app viewers in a shared repo and use tldraw through Expo DOM for interactive canvases, accounting for its production license.
4. Use upstream thinking-orbs for genuine agent activity, silver/mono static catalog avatars at about 40 px and full color only for the Voice hero. Preserve the ElevenLabs notice. Keep idle voice still and drive listening/work indicators only from actual state. Match each harness to its own mark, with OMP's light ring.
5. Use shared src/motion.ts tokens with instant mount paint, no entrance fades or slides and no visible layout overshoot. Keep transitions within 200 ms, navigation settling within 180 ms of release and press feedback within 80 ms. Make motion interruptible; run orbs on a shared UI-thread clock and pause them offscreen.
6. Place actions in the thumb-zone bottom bar or sheet through useHandedness(). Keep top chrome for title/status. Apply useTileGestures for instant tap detail, double/triple quick actions and haptic hold-radial actions. Provide working direct touch controls with plain labels; implement or hide visible controls instead of placeholder alerts or mode-only changes.
7. Render agent work as wrapped live-tailing blocks with grouped tool calls, descriptive command/path/query titles, thinking summaries and shared Tree disclosures. Lead data views with timelines, lanes, charts and numeric strips. Use one neutral base with amber needs-you, red failing/stalled and blue live; offer Compact, Comfortable and Rich density.
8. Keep presentation separate from bridge, protocol and store producers. Default optional stale to false and let ended override live evidence. Require a matching online host and running session for a live dot. Load pinned Expo fonts/gradients behind the splash and preserve Bun locks; use sans tabular numerals on gold count pills and content-sized tabs.
9. Preserve original screenshots and hash UI source, lockfile, orb assets and harness into each fresh receipt. Run `cd app && bun run debug:shots --port <unused>` and scripts/assert-living-night.mjs; inspect every required PNG personally at 390x844, including before/after pairs. Repeat with `EXPO_PUBLIC_ZEROS_THEME=proof-mono` and grayscale avatar assets.
10. Exercise real clicks alongside geometry and explicit web aria-selected/aria-checked states. Hide closed overlay descendants from accessibility, remove obsolete drag interceptors and keep shared pager-progress unwritten on web. Bound native Text payloads in compact previews and retain disclosure state through close/reopen while output streams.
11. Preserve numeric pager/motion mutation canaries and behavior checks when updating renderer assertions; demonstrate that the old renderer fails the new layout assertion. Reproduce stale runner failures on the exact base and label geometry-only captures separately. Pass PLAYWRIGHT_BROWSERS_PATH explicitly when cache environments differ.
12. Admit heavy work only with at least 4 GB available and the owner's shared heavy.lock under nice 10. Queue a tracked job while another holder runs. Execute the applicable app/bridge/root test, typecheck, lint and mutation gates without disguising a baseline failure or export success as phone proof; retain the lockholder and served dependencies.
13. Preserve the owner's live phone Metro/bridge ports. Report unreachable live-doctor routes rather than starting replacements. For separately authorized phone integration, keep UI and bridge on the same combined tree, preserve private environment and pairing, keep DASH_GATE_LIVE=0, and distinguish Expo Go links from native app routes. Follow references/owner-phone-dogfood.md subject to explicit service/phone authority.
14. Keep publication scoped to the assigned branch and requested draft base, disable followed tags and read back draft/base/head SHA. Reserve merge and force-push for separate authority. Report rendered frames, source gates, live service checks and phone/microphone acceptance separately. Suggested companions are rendered-ui-qualification and reference-led-ui-recovery.
