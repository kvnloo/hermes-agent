# Optional provider pulse gates

- Baseline inspected collector, scorer, legacy-sync, and adjacent workflow tests before modifying their contracts; store exact commands, exit codes, logs, and source hashes outside the repository.
- Trace the scorer's actual acceptance predicate before separating provider health. If legacy `status` gates primary-provider overlays, retain that meaning and expose aggregate requested-provider health separately. Never let optional-provider failure erase independently qualified primary observations.
- Make collection opt-in at the executable CLI, not only at the workflow step. Prove the default makes zero optional-provider calls even when the I/O stub would succeed.
- Preserve primary-provider boundedness checks. Run below-cap, at-cap, malformed/unknown, failed, timed-out, valid-empty, owner-excluded, and no-hit controls through the real collector and scorer.
- For GitHub Actions booleans, use typed `inputs` rather than string-valued event inputs. Gate optional sync/dwell steps and credential injection with both dispatch-event and explicit opt-in conditions.
- Parse workflow YAML with an available real parser, normalizing the YAML 1.1 `on` boolean-key quirk. Ruby's standard Psych parser can avoid an installation on a runner that already includes Ruby; document this test dependency rather than assuming every host has it.
- Execute extracted workflow `run` blocks with the real shell and copied production entrypoints in scratch directories. Replace only provider I/O process-locally, retain actual CLI parsing/scoring/sync/dwell behavior, and supply a sanitized HOME and scratch TMPDIR. Do not call live providers.
- Model only the workflow condition grammar the test understands and reject unsupported syntax. Apply GitHub Actions' implicit success guard to ordinary step conditions; check always-run diagnostic/upload eligibility after a requested sync failure.
- Distinguish local upload eligibility from a hosted artifact upload. Without authorization, never execute uploads, secrets management, host rollout, commits, or GitHub writes to obtain stronger receipts.
- Use a vertical RED/GREEN cycle for each changed behavior. Additional unchanged-boundary controls may pass immediately; report them as controls, not fabricated RED evidence.
- Keep opt-in historical archive context in a separate nested output, never in primary health, live outcome counts or authorization fields. Differentially compare default, accepted-cache and rejected-cache executions against the exact baseline, including stdout/stderr, provider calls and the real scorer's acceptance gate.
- Bind frozen SQLite context to an expected byte hash and explicitly caller-pinned source revision; do not call the revision independently verified unless acquisition proves it. Reject active sidecars, unknown consumed schemas and ambiguous identity keys, recheck the hash after content reads, and discard partial output on failure.
- Consume whole pinned snapshots with deterministic keyset pages rather than creation-only watermarks, because old-event edits and deletions must replace prior context. Report per-type ingestion age separately from event creation, collection completion, completeness and live inbox availability; preserve unresolved source privacy risks.
- Execute each owning workflow test command literally before reporting totals. Unittest discovery can omit script-style assertion suites even when it exits successfully; compute counts from the actual command logs.
- Normalize legacy symlink-loop failures directly around strict path resolution, checking the wrapped `OSError(ELOOP)` rather than catching every `RuntimeError` across consumption. Exercise initial open, metadata rechecks and content open with real links; mutation-remove the catch and separately broaden the consumer catch to prove both isolation and programming-error propagation.
- When replaying immutable probes that hard-code an old checkout, explicitly preload the selected production modules, verify their canonical `__file__` paths and byte hashes, then execute the unchanged probe. Preserve the original probe digest and disclose this import routing; a green run against the old root is not candidate evidence.
- For no-source-edit acceptance, execute removed-catch and broad-catch mutants by compiling transformed source into a child process module with the original `__file__`, then run the unchanged regression suite. Record original and mutant hashes, require named behavioral failures, rerun in fresh unmodified processes, and verify every tracked file; keep executing cwd identity separate from the loaded source revision.
- Attribute warning changes with the same retained test selection on both revisions. A larger repaired suite can emit more inherited fixture warnings merely because added tests exercise the same leaking setup; distinguish equal original-test warnings from warning-free execution and production reader lifetime.
- Challenge optional local-input failures on the workflow's configured Python version as well as the host interpreter. On Python 3.11/3.12, `Path.resolve()` raises `RuntimeError` for symlink loops, whereas newer Python raises `OSError`; an OSError-only boundary can pass on the host yet abort the primary collector before any provider I/O on supported runtimes. Use real disposable symlinks and assert unavailable context, unchanged diagnostics policy, and the full primary-provider call sequence without editing source.
