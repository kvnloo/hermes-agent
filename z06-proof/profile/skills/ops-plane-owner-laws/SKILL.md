# ops-plane-owner-laws

Use when converting a recurring owner correction into a shared proven decision law and an enforced runtime gate.

## Rules

1. Locate the owning contract, peer assignment, reserved law names and current receipt before changing anything. Compare receipt hashes with source; reuse the canonical law and add only missing consumer adapters.
2. Settle a small mode/action table and unresolved authority choices. Keep accepted compatible contracts unchanged; use an isolated worktree for authorized implementation and preserve peer work.
3. Model exclusive states with typed decisions. Keep text classification outside the proven kernel and establish authorization, completion, workflow and wake facts at the host boundary.
4. Write nonvacuous branch and failure laws, generate matching proofs, assert unique mutation preimages and test type-preserving mutants. Maintain the Python twin, exhaustive parity and transcript-derived incident tapes.
5. Expose the decision, CLI gate and read-only resolver where needed. Enforce pure refusals; give safe reroutes explicit targets and refusal exit 3. Update exact-set tests, law counts and integration docs.
6. Run mutants and pytest off groot through the MBP procedure in references/mbp-proof-runs.md. Require all mutants rejected, reference restoration and unskipped parity; bind receipts to exact tested source.
7. Separate pure proof, adapter qualification, deployment and observed enforcement. Deploy stamped consumers before claiming a gate is live; unexpected external-consumer gate failures warn and fail open, while agreed refusals retain their meaning.
8. For continuation, audit both native stop decisions and next-turn admission. Reuse the existing scheduler, preserve explicit pause/stop and real approval/budget holds, and verify the original goal rather than an exhausted todo list. See references/continuation-contracts.md.
9. Start timed workflow observation only after native-boundary behavior passes. Record revision, profile, session, effective model and actual elapsed progress; label candidate qualification separately from owner-profile activation.
10. Treat sqlite-ghosts as read-only preflight, not repair. Preserve unknown holder evidence, credential privacy and lifecycle exclusion; obtain separate cleanup authority. See references/sqlite-store-lifecycle.md.
11. Check composed rules from arbitrary states and test indefinite interruption. Qualify reachable-only invariants, delivery acknowledgments, fairness and mutation equivalence; count only observed non-equivalent kills.
12. For authorized delivery, include exact-head proof/mutant/test receipts and explicit limits in the draft PR, then link it. Update managed skill copies, not user-authored copies; obtain restart approval and independently fetch facts that unlock autonomy.
