# Newton CPU raycast receipts

## When to Use

Use for receipt-only requalification of immutable Newton geometry candidates, including baseline controls and current-upstream compatibility overlays.

1. Read the exact candidate's AGENTS.md, CONTRIBUTING.md, CODING_GUIDELINES.rst, REVIEW_GUIDELINES.rst and `.agents/skills/code-review-newton/SKILL.md`. Preserve original contributor and evidence credit; a new replay is independent evidence, not recovered original logs.
2. Record upstream main, candidate, implementation parent, fork head and registration/HITL separately. Download immutable source archives into owned scratch rather than editing an existing checkout. Verify archived file bytes against GitHub recursive-tree blob IDs before calling execution exact-head.
3. Before dependency reuse, read installed package metadata without importing Warp and compare it with the intended receipt and source lock. A queued runner's hardcoded venv is not a pin: scratch venvs may have been pruned, and an installed checkout can carry an older Warp than the candidate lock. If installs are forbidden and bounded discovery finds no matching environment, record native NOT_RUN and advance an existing named gate; do not transfer historical GREEN or silently downgrade Warp. Provision only the receipt's pinned Warp and NumPy wheels in a task-owned `uv venv` when installation is authorized; clear inherited PYTHONPATH/PYTHONHOME. Record the actual Python patch release. For Warp 1.18, do not rely on `wp.config.enable_cuda=False`: it is not a supported containment flag and assigning it can silently leave CUDA enabled. Set `CUDA_VISIBLE_DEVICES=''` before importing Warp, use an owned `wp.config.kernel_cache_dir`, initialize, then fail closed unless `wp.get_devices()` contains only CPU; set the default device to CPU before test-module registration. Inspect raw device/kernel lines and preserve any mixed-device attempt separately rather than relabeling it CPU-only.
4. Use unittest through `uv run --no-project --python VENV/bin/python python RUNNER`. Put the selected source root on sys.path. For geometry normal regressions, run the original frozen tests through `kernel_test_geom` and the public `newton.intersect_ray` path, retaining both fast-math modes.
5. Count registered tests and subTest cases independently with a TextTestResult subclass. Sixteen failed subcases across two tests is not sixteen independent tests. Do not add focused, full-module and overlay counts as unique tests.
6. For RED, copy only the frozen candidate test file into an isolated baseline archive. For current-upstream drift, repeat RED on its complete source tree, then overlay candidate production/test files and run raycast plus adjacent `newton.tests.test_bvh` and `newton.tests.test_collision_primitives`. Label this last tree a composition, not a rebased/published commit.
7. Preserve exact commands, stdout/stderr, exits, source manifests and small source-only archives in durable receipts outside scratch. Verify archive CRC and unique member names. Exclude wheels, caches and unrelated private data.
8. When explicitly authorized to prepare a current-base commit, use separate candidate and baseline worktrees. Apply only the original implementation commit; preserve evidence-only follow-ups verbatim in the durable receipt rather than inserting historical execution claims into a minimal upstream patch. Preserve original Git author/date and identify the replay agent as committer without adding human signoffs or CLA attestations. Compare the complete original and rebased parent-relative diffs byte-for-byte, as well as blob IDs and modes, then run GREEN and native precommit at the final local commit with clean before/after snapshots.
9. Compare commit-relative and staged-overlay patches with explicit `--src-prefix=a/ --dst-prefix=b/` (and consistent full-index settings). Inherited `diff.mnemonicPrefix` can change only `a/b` to `c/i` and cause a false byte-identity failure; retain the failed preflight, verify the discrepancy, and never change global Git configuration to mask it. Count actual native precommit hook outcomes from the fresh log rather than copying historical totals. A passing uv-lock hook must leave the lockfile and complete candidate tree unchanged to preserve exact original implementation evidence.
10. Verify standalone bundle restoration, not only `git bundle verify`: a shallow-source bundle can report complete history yet fail a fresh clone with missing parents. Preserve that failed receipt, hydrate the owned restoration checkout with a targeted no-prune/no-tags `fetch --unshallow` from the authoritative repository when allowed, then recreate the bundle. Clone it into another fresh checkout, require nonshallow history, `git fsck --full`, exact head/tree and original-base ancestry; never invent or edit boundary ancestry to claim full preservation.
11. For a deliberately incremental bundle, first prove the stated prerequisite is an ancestor of the delivered head. A too-small depth fetch may sever that path and make `bundle verify` misleadingly report complete history. Fetch a bounded deeper slice from the authoritative remote, recreate the bundle, seed a fresh restore with the exact prerequisite on a named ref, and require bundle verification, connectivity fsck, exact clean head/tree, and native replay. Label a depth-one prerequisite and the bundle's non-standalone status explicitly; do not claim full-history restoration.
12. Refresh the live PR head again before reporting. If the author or parent has already landed the same follow-up, compare its bytes to the local proposal, mark the proposal superseded, and rerun the new exact head rather than offering a duplicate patch.
13. Do not require every CPU test ID to end in `_cpu`: collision-primitive tests can have unsuffixed IDs and use the selected default device. Gate actual Warp device visibility before registration and audit resolved launch devices/module-load logs; a naming-only guard can abort valid adjacent coverage.
14. Inspect exact-head Actions runs and their job counts in addition to `gh pr checks`. License, changelog, or general PR workflows can be `action_required` with zero jobs and absent from the visible rollup, even while EasyCLA and pre-commit statuses succeed. Report those admission holds separately from AWS GPU approval waits.
15. Keep CPU qualification, GPU acceptance, performance, hosted CI, ownership and publication permission separate. A commit with zero check/workflow runs has no hosted verdict. Search all current open PR file sets, expand truncated file lists, then inspect overlapping mechanisms rather than equating a shared test file with ownership.
