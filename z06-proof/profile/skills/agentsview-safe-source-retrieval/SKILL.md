# AgentsView non-migrating source retrieval

## When to Use

Use for source-backed evaluations that allow retrieval but prohibit archive migrations, reindexing, new memory databases, or implementation changes.

## Procedure

When an existing operator-managed daemon becomes available, test its supported read API without restarting it. Discover routes with `agentsview openapi` before constructing requests: the session routes are `/api/v1/sessions/{id}` and `/api/v1/sessions/{id}/messages`, not `/api/sessions/...`. Verify JSON content type and parseability as well as HTTP status, because an unmatched route can return the web application's HTML with status 200. An explicit remote `--server` CLI request may omit local authentication even when saved authentication exists; use the documented `--server-token-file` option with an existing appropriate token file, or read the configured `auth_token` into process memory and issue a bounded GET with a Bearer header. Never print or persist Authorization headers. HTTP 200 proves transport access, not source-slot binding or oracle qualification.

Audit a replacement reader's required schema shape, including required indexes, before calling it archive-compatible. An exact-source build may fix a column mismatch while still refusing a missing index. Never bypass these refusal checks. Inspect whether an apparently read-only export command attempts an automatic writable schema upgrade before using it against an authoritative archive.

1. Resolve the real canonical data directory and inspect the installed executable version/commit. Keep the actual HOME and existing archive paths; an isolated nonexistent path is not proof the archive is absent.
2. Audit the exact installed revision's database-open and command paths before starting anything. A checkout at a different commit is not authoritative for the installed binary.
3. Treat `PRAGMA user_version` as necessary but insufficient. Equal parser/data versions can coexist with incompatible table shapes. Inspect metadata through read-only/immutable SQLite only; never use SQL transcript extraction as a substitute for the supported retrieval capability.
4. Do not treat `serve --no-sync` as read-only. Verify whether the exact version unconditionally calls writable initialization, trigger installation, column migrations, or data backfills. If any are required or unsafe, stop before launch and name the concrete gap.
   - The plain CLI `search` with no running daemon can start its own server, which then begins a metadata backfill/sync and writes to the archive. When the task is read-only, say so in the subagent brief: no AgentsView CLI search unless an operator daemon is already healthy (probe it first). For history scans, use `ctx` or read-only SQLite/JSONL instead. If it happens anyway, report it as a possible write and check that no stray server is still running.
5. Audit apparently read-only commands too. Some `export sessions` paths attempt additive schema upgrades after a failed read-only open. Prefer a command proven to call a strict read-only open without an upgrade fallback for compatibility checks.
6. Keep `require_auth` enabled and use an existing token only in process memory. Do not print config secrets, put tokens in arguments, or write token copies to captures.
7. If a compatible owned service is allowed, bind only loopback, prefer OS port zero, record URL/PID/executable/start identity, never replace another daemon, and use a bounded lifetime with `finally` cleanup. Read back actual listener/auth behavior before claiming readiness.
8. Supported message responses may be `{messages,count,first_ordinal,last_ordinal}` objects. Normalize message content, exact session identity, native harness from session metadata, ordinal, timestamp, and authoritative original file path. Preserve any native-ID/lookup-ID mapping explicitly; do not invent origin or paths.
   - For recent owner-priority recovery, fetch session metadata and `/messages?roles=user&direction=desc&limit=500`; save each page, check `count == len(messages)`, and continue with `from=<minimum returned ordinal minus one>` until the requested time boundary or archive start. Use the minimum ordinal rather than assuming `first_ordinal` is numerically smallest in descending output. Role-filtered counts still include non-human wrappers, so filter provenance before interpreting priorities.
   - After locating an important owner request, fetch a bounded `around=<ordinal>&before=0&after=<window>` and the latest assistant window to recover claimed follow-up work. Keep those claims separate from live deployment evidence; the next useful step is often reconciling an existing fix rather than searching or implementing again.
   - Content search can return `matches` and `next_cursor`, with separate message, thinking, tool-input and tool-result locations. Use the audited `in=messages` filter when the contract binds exact message text; a tool-result snippet is not proof that its text appears in the message body. Re-fetch the exact ordinal and check the returned count and identity.
   - HTTP detail may omit the original path even when it exists locally. A bounded native-ID filename lookup is only discovery: establish an explicit lookup-ID/native-ID mapping, verify the original header identity, and match the complete decoded message text plus exact native timestamp to an original record before using that file as the baseline. Otherwise report a baseline blocker; never substitute a normalized capture silently.
   - Filter approval-review wrappers, compaction copies and quoted histories before selecting original assertions. Bound printed excerpts before output; keep full private captures in the authorized evidence directory.
   - For recurrence counts, use `session search <pattern> --regex --in messages --exclude-system --json --limit 500`, exhaust every `next_cursor`, and hydrate complete message bodies. Set `AGENTSVIEW_DATA_DIR` to the canonical real path on every CLI subprocess when the default directory is a refused symlink. Once an operator-authorized daemon is healthy, retrieve through it rather than reopening a startup/schema audit.
   - For a same-day scan of a large archive, inspect indexes and select candidate sessions by started/ended activity, then read messages through indexed session IDs; avoid an unindexed global timestamp join. Record that stale session activity metadata can still omit records and supplement current native stores.
   - Native T3 projections can distinguish message `createdBy=user` from agent-composed user-role sends. Use strong provider-thread `nativeThreadRef` bindings plus complete normalized text and nearest timestamps to establish cross-import lineage; keep same-text records with missing bindings explicitly ambiguous, not agent-authored or silently deduplicated. Preserve repeated native human messages separately even when their text is identical.
   - Count original human messages, not search matches or metadata `user_message_count`; user-role rows can contain tool wrappers, task notifications, compaction summaries and repeated originals. Deduplicate exact timestamp plus full text across session lineages, preserving all source ordinals. Separate explicit complaints, broader cleanup requests and distinct incidents; three fresh requests during one outage are three messages, not three outages. Mark keyword coverage as a lower bound.
   - Save each page/window before processing and keep source bodies separate from bulky tool attachments in review output. A transient local-daemon response failure during parallel hydration should trigger bounded retries with lower concurrency, not a daemon restart or duplicate full-history download.
9. Pin exact UTF8 message text with SHA256. Literal extractors need an unambiguous support quote and character offsets into that quote. Hash full-source baselines from authoritative original file bytes, not normalized capture files.
   - In a bounded follow-up, reuse immutable raw captures read-only instead of duplicating whole histories. Record separately which capture hashes, original header/text/timestamp links, file statistics, and full-file hashes were freshly checked versus reused; a line-link check is not a new whole-file uniqueness or hash audit.
   - Compare local capture filesystem aliases by resolved paths when matching receipt files, because an imported scratch helper can inherit a resolved symlink directory. Never apply that filesystem equivalence to native session IDs, source IDs, message text, or other literal source tokens.
   - Separate literal-oracle success from semantic relationship approval. Matching broad scope strings can conceal a component-versus-whole distinction, and a component label placed in validity is not automatically a revision. Hold a relationship when the frozen quotes omit the common component; full-message context may justify a separately reviewed quote expansion, not an invented field.
   - Reject corrections that change diagnostic invocation or execution context as same-validity contradictions even when the underlying code was unchanged. An informal license description and a qualified correction also need an explicitly common immutable revision and identically framed single-valued property before qualification.
10. Distinguish absence of evidence from unavailable retrieval. Never label a failed transport/schema open as an abstention case, invent missing slot values, or claim conflict from unrelated assertions.
11. Record DB/config size and mtime before/after, and disclose any SQLite sidecars. A nominally read-only WAL-mode open can create an empty WAL and SHM. Do not delete coordination files without proving ownership and lack of live users; do not claim a whole-directory no-write result from main DB mtime alone.
12. Exercise the actual frozen preflight contract. A blocked draft must stay unmistakably non-runnable, with no fabricated facts or fake baselines. Keep all raw source evidence/captures private and outside the repository; report the exact blocker and safe next requirement.
