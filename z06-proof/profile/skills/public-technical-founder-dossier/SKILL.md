# Public technical-founder dossiers

Use public material only. Keep personal health, travel, contacts, private operational sources, and unrelated people out of outreach-oriented research even when timelines contain them. Read-only research does not authorize social writes, repository changes, or software upgrades.

## Collection

1. Load agent-reach and grounded-citations. Health-check login-backed platforms and use the selected backend. Use a task-specific citation ledger.
2. Save fetched batches in profile scratch. Deduplicate by stable post ID and count authored posts separately from retweets, quoted third parties, and conversation replies.
3. A requested `-n` is a maximum, not a delivered count. Some twitter-cli installations impose an internal 200-entry cap even with `-n 400`. Inspect actual JSON and installed public pagination implementation before claiming coverage. A task-local in-memory maximum override may preserve the existing read-only transport and pacing without editing installed code or persistent settings. Report what returned.
4. If X search fails twice, use working timeline and direct-post retrieval. Do not imply complete reply coverage from UserTweets. Do not upgrade an installed client during a read-only task merely to repair search.
5. Retrieve important conversations to retain replies/corrections. Preserve exact text and UTC dates. Derive canonical links only from retrieved identities/IDs, fetch them, and keep body evidence from the working transport.
6. Enumerate relevant GitHub accounts/organizations, then read canonical READMEs, releases, commits, comments, and implementation. Push dates can reflect migration rather than new research. Match GitHub login, not a human author name: different people can both be named `victor`.

## Interpretation

- Separate historical roadmap, current README, latest published release, and unreleased main changes.
- Funding announcements are plans until completion is supported. A gist update does not refresh old financial figures.
- Distinguish theory consistency, executing kernel, source translation, compiler, runtime, adapter parity, and operational enforcement.
- Read benchmark scripts and recompute raw result totals. Arms may differ in tools and iteration protocol despite simplified headlines.
- Inspect a real page before describing aesthetics. Legacy domains may redirect while extractors return old content.
- Retweeted application claims are announcements, not reproduced outcomes. Inference parity or shape proofs are not training gains or complete numerical correctness.
- Label predictions and recommendations INFERENCE. Preserve nuance: someone can enjoy exuberant demos while demanding exact mechanisms and honest limits.

## Verification

Deliver numbered sections, current open problems, concrete do/don't guidance, exact requested posts, short quote table, and a mechanically rendered source list. Programmatically verify quotes are contiguous substrings, snippets meet word limits, dates match, counts reconcile, sections exist, and strict citations pass. Keep a compact public-safe verification JSON beside the dossier. Raw mixed/personal timelines remain in scratch, not the public artifact.
