# Tern merge-wave integration

- Work in an owned scratch clone and explicit fork remote; preserve coder history using merge commits, never force-push.
- Fetch moving main before each integration and retarget stacked children only after verifying the parent merged.
- Wait for the pushed head's workflow to appear: immediate `gh pr checks --watch` can report the previous head's success. Compare workflow headSha explicitly.
- Union rendering ports end-to-end: frame context Pick types, entry cache revisions, shell/card signatures, work-log forwarding and test callers must retain browser focus, LSP host evidence, media delivery, charts and artifact links together.
- When per-open overlay namespaces land, migrate newly merged sheets' JSX keys, focus and scroll roots together. Update SDK test ID discovery, not only expected focus strings.
- Observe Surface.send operations when recovery reconciliation replaces Surface.render; negotiate actual test credits and include incremental child adds.
- Correlate gateway RPC response IDs past unsolicited session events. Initialize real-agent tests with an inert local test provider rather than operator credentials.
- Bind staging witnesses and live leases to modification identity as well as device/inode and digest: filesystems may reuse an unlinked inode for same-byte replacements.
- Share capability-negotiated canonical media staging across upload entry points. Test owned uploaded images rather than inserting unauthenticated objects through restore.
- Keep ratchet ceilings fixed; extract cohesive app helpers instead of raising limits or adding suppressions.
- Report auxiliary scanner failures separately from required checks; never call all CI green when another check remains red.
