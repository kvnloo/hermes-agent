## Execution and release discipline

- Treat “keep building” and hackathon entry requests as implementation mandates: inspect current owners and source, select one uncontested product or release defect, edit it, and exercise the smallest relevant test before handing back. A checklist, eligibility question or validation-only pass is not the requested deliverable; resolve publication questions in parallel with authorized downstream development. After an execution complaint, skip apology-only turns and perform the next authorized action in that same turn; an admission that no work was done does not advance the task.
- Keep blocked lanes scoped to their actual dependency. Continue parent-executable source investigation and authorized edits when worker admission is unavailable; do not let phone connectivity or fleet storage become a whole-project pause. Never bypass execution admission to manufacture a green result.
- Check current admission once before dispatching verification, use bounded waits, and select an alternative only from evidence that it is eligible. Match the runner's input contract before dispatch: snapshot lanes can test uncommitted source, while exact-SHA hosted lanes require a publicly reachable commit. Resolve any missing commit/push authority before selecting the latter. Do not serially probe every unavailable worker merely to end with the same blocker; retain the unverified patch and exact test command, route one precise unblock request to the existing owner, and continue independent authorized work without describing the patch as tested.
- Separate catalog eligibility, plugin loading, source tests, bundle provenance and real-client acceptance. Run `hermes plugins validate PATH --json` for initial discovery, review warnings, and run final `--install-deps` validation in an approved isolated environment at the selected release SHA. Neither a passing loader check nor a feature-branch receipt qualifies the release candidate.
- Check the current catalog's lineage rules before preparing a fork listing; retain original authorship and resolve collaborative entry versus independent eligibility without renaming to evade policy. Submission uncertainty must not block useful downstream fixes.
- When reviewing immutable build receipts, inspect both tracked changes and untracked inputs in every source checkout: `git diff --quiet HEAD --` alone cannot establish source-to-SHA identity. Keep generated outputs outside the checkout and inspect nested source-checkout handling separately. Require regression coverage for injected untracked source, ignored installed dependencies and nested checkouts before calling a proposed guard verified.
