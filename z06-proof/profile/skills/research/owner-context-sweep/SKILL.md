# owner-context-sweep

Use when planning, roadmapping, auditing owner requests or work status, or checking whether related work already exists.

## Rules

1. Recover owner context across relevant repos, harnesses, profiles and hosts before proposing new machinery or claiming absence. Cite existing carriers and state which surfaces and freshness limits support not-found claims.
2. Choose retrieval by question: recent top-level sessions for global status, repo/live threads for a named project, complete owner turns for original requirements, and source-plus-receipts for completion. Reuse sibling work read-only and preserve its owner.
3. For exhaustive message audits, fix timezone, UTC bounds and capture cutoff; enumerate source coverage including sessions starting before the window. Preserve full private messages and source identities before prioritizing.
4. Classify machine messages, worker briefs and compaction copies separately; strip injected envelopes without losing following owner text. Deduplicate only proven copies, account for every human message and expand multi-ask turns into source-linked ledger rows.
5. Reconcile corpus counts, exclusions, duplicates and dispositions mechanically before claiming completeness. Verify delegated audit artifacts and bundle work into exactly the requested lanes with existing owners, dependencies, next actions and acceptance evidence.
6. Check actual implementation, integration and deployed revision separately from assistant reports, merged branches and ship logs. Keep phone installation or publication as separate authorized operations rather than automatic audit side effects.
7. Search local owner-message stores and factory queues before app history. Use presence-gated focus-safe capture, exact relevant titles and bounded single-chat extraction; keep unrelated personal chats private. Treat direct owner messages as authority, not ChatGPT advice. See references/chatgpt-app-history.md.
8. Read related issues and source contracts across the ownership map: AODL intent, z0intelligence cognition/dispatch, z0evals evaluation, Kerdoios placement, Tokenomics measurement, z0 registry and oss-factory queues. Treat incomplete imports as incomplete coverage.
9. Build dependency audits from paginated full threads with reconciled comment counts, durable corpora and bounded question-based specialist partitions; synthesize evidence yourself. See references/thread-corpus-dependency-audit.md.
10. Rank unanswered owner asks and owner decisions before capacity risks, ship-ready and stale work; attach fresh numbers, exact heads and one next action. See references/priority-audit.md.
11. Keep one canonical private plan and machine-readable revision-bound gate state. Test accepted, missing-gate, missing-evidence and stale-revision cases; call a checker enforcement only when the actual delivery path invokes it. Advance independent authorized work despite operation-specific holds.
12. Prefer the smallest plan using built-ins and harness pass-through commands; quote the owner's framing accurately. Ground portfolio and meeting claims in verified uptake with authored merges, salvage, proposals and experiments separate. See references/owner-work-inventory.md and references/collaboration-meeting-prep.md.
