# Paper-to-process gap audit

1. Pin the paper version and upstream workflow revision before synthesis. Distinguish similarly named research methods from practical skills; do not merge their claims.
2. Read the full primary manuscript including appendices and code/prompt listings. Fall back from truncated HTML to PDF text. Record page/section coverage; label survey skims separately.
3. Compare embedded downloadable listings byte-for-byte as well as main text between revisions. A changed formal objective may coexist with an unchanged implementation prompt; report that discrepancy rather than calling every appendix mechanism new.
4. Audit the installed workflow AND actual run ledgers. Separate rules already written, practices exercised, and mechanisms not evidenced. Cite canonical paths and sections; do not infer global absence from a scoped audit.
5. Distinguish scene rebuild replay from controller-policy replay. Require prefix-only observations, explicit ancestry/dependencies, compatible evaluation cohorts and out-of-support handling. Never simulate outcomes for unseen edits or component combinations.
6. Rank gaps with concrete files, available data, acceptance tests, qualitative cost and owner-permission boundaries. Keep technical validity, perceptual quality and human approval distinct.
7. Preserve source snapshots and a hash manifest with the report. Verify the pinned upstream reference-file inventory, citations, snapshot hashes and local evidence paths. Recommendations are not implementations or measured speedups.
